# 实践案例目录规范

本规范用于统一 `samples/` 下实践案例的代码布局，同时保留现有教材、构建脚本和板端部署所依赖的稳定路径。

## 标识与显示名称

`caseN` 是机器可识别的稳定标识，不能随意改名；`src/experiment/caseN.md` 和 `samples/caseN/` 继续作为正式书稿与样例的固定入口。面向读者的标题、README、导航和索引使用“案例 N · 中文功能名（English slug）”格式。完整映射见 [`case-index.json`](case-index.json)。

语义后缀用于检索和理解，不作为当前文件系统路径的一部分。这样既能让读者根据功能找到案例，也不会破坏 Pandoc 转换、VuePress 路由、GitHub 链接和已有板端命令。

## 目标目录骨架

```text
caseN/
├── README.md                 # 唯一运行入口和案例说明
├── app.py                    # 可选的兼容启动入口
├── <semantic_package>/       # 业务运行代码；包名按案例语义命名
├── scripts/                  # 准备、转换、部署和诊断 CLI
├── tests/                    # pytest、合同测试和板端测试
├── docs/                     # 编号工程文档、验收记录和迁移说明
├── frontend/                 # React/Vite 前端（有前端时）
├── templates/ 或 assets/     # 服务端模板或静态资源
├── models/                   # 模型元数据；二进制默认忽略
├── data/                     # 数据集、缓存和运行时数据；默认忽略
├── reports/                  # 实验报告和板端证据；默认忽略
└── third_party/              # 必要的第三方源码（可选）
```

已存在的 `web/`、`webui/`、`doc/` 或多个语义包不会在一次重命名中强行合并；迁移时先补充兼容入口和链接，再逐案调整，避免运行路径和证据文件失效。

## 迁移约束

1. 每次只迁移一个案例，先更新运行入口、导入路径和 README，再更新书稿与导航。
2. 模型、OM、数据集、真实图像、数据库和板端报告不随目录整理复制到版本库。
3. 目录迁移不等于功能验收；模型合同、隐私边界、性能指标和板端结果仍须单独验证。
4. 兼容入口只保证已有命令的过渡期可用，新文档统一指向语义包、`scripts/` 和 `tests/`。
