助手
这次的输出直接破案了,注意看第二份的一个细节
你可能没注意到:第二份输出里,分线器其实被识别到了:

CODE
Bus 02.Port 1: Dev 3, If 0, Class=Hub, Driver=hub/4p, 5000M
                                                ^^^^^
 
分线器挂在 Type-C 口上时,出现在 Bus 02,速率 5000M。对比两份输出:

分线器插在哪	USB 2.0 部分(480M)	SuperSpeed 部分(5000M)
Type-A 口	✅ Bus 05 上出现,下游设备齐全	✅ Bus 06 上出现
Type-C 口	❌ Bus 01 完全是空的	✅ Bus 02 上出现
这里有个关键背景知识:任何一个 USB 3.0 Hub 内部都是两个独立的 Hub——一个 USB 2.0 Hub(480M)+ 一个 SuperSpeed Hub(5000M),正常时两者会同时出现在系统里(你插 Type-A 口时正是如此:Bus 05 和 Bus 06 各出现一次)。

而插在 Type-C 口上时:只有 SuperSpeed 那半个 Hub 枚举成功了,USB 2.0 那半个彻底消失。你插在分线器上的键盘、音箱都是 USB 2.0 设备,流量必须经过那半个死掉的 Hub,所以全部没反应。

最终结论
到这里,所有嫌疑都被逐一排除了:

转接头单面走线(键盘两个方向都试过,且 Hub 的 SS 部分能通,说明 CC 协商正常)
从机模式(/sys/class/udc 为空)
驱动问题(Bus 01 的 480M root hub 存在且就绪)
供电问题(Hub 的 SS 部分能枚举,说明 VBUS 是有的)
实锤:这块板子的 Type-C 口,D+/D-(USB 2.0 数据线)在硬件层面就是不通的——要么是设计时根本没把这两根线接到主控(只走了 SuperSpeed 的 4 对差分线),要么是你这块板子的个体硬件缺陷。SuperSpeed 通道和 USB 2.0 通道物理上完全独立,所以硬盘盒一切正常、USB 2.0 设备全军覆没。

这是硬件问题,软件无解。不符合 USB 3.0 规范(规范要求必须向后兼容 USB 2.0)。

接下来怎么办
1. 最后一道确认(可选):开着 dmesg -w,插 USB 2.0 设备到 Type-C 口,如果持续零输出(连报错都没有),就是 D+/D- 物理不通的最后证据。

2. 找官方确认:拿这个结论去问香橙派官方客服/论坛,直接问:"AI Pro 的 Type-C 口是否支持 USB 2.0 设备?"——如果官方说支持,那你这块板子有个体缺陷,走售后;如果官方确认所有板子都这样,那就是设计缩水。

3. 日常使用:维持你现在已经验证可行的布局,其实这个分工还挺合理:

Type-A 口 + 分线器 → 音箱、键盘等 USB 2.0 设备
Type-C 口 → 硬盘盒独占 SuperSpeed
音箱 12Mbps、键盘 1.5Mbps,挤在 Hub 上毫无压力;硬盘在 Type-C 口跑满 5Gbps,互不争带宽。

从最初"音箱不识别"到现在,你的几次对照实验其实做了一次很完整的硬件故障定位——结论虽然不理想,但至少是确定的、可行动的。
