## 已核实问题

### P1-1 后处理使用跨类别 NMS，可能错误抑制不同手势

**证据**

- samples/case8/hagrid_yolo/postprocess.py 第 31--33 行分别读取 box、score 和 class_id。
- 第 54--59 行把所有框放入一个 nms_boxes 列表，并对全部 scores 只调用一次 cv2.dnn.NMSBoxes；没有按 class_id 分组，也没有加入类别偏移。
- 第 64--71 行再把保留索引映射回 class_id，因此不同类别发生高 IoU 时已经无法恢复被抑制的框。
- 正文 src/experiment/case8.md 第 269--274 行把这一步描述为 YOLOv10 导出兼容措施，却没有说明它会改变多类别检测行为。

**影响**

当画面中出现相互重叠的两只手或不同手势时，一个类别的高分框可能删除另一个类别的框，造成漏检、类别偏置或与模型原始 NMS-free 输出不一致。这个问题直接影响案例的核心检测结果，不是单纯性能优化。

**修复建议**

1. 首选按类别分别执行 NMS，或使用带类别偏移的 class-aware NMS；对 YOLOv10 已验证的 NMS-free 输出则应提供显式开关，而不是无条件二次抑制。
2. 在后处理函数中保留输入类别、阈值、导出版本和输出格式的合同，禁止用“兼容”掩盖算法语义变化。
3. 增加至少包含重叠不同类别框、重叠同类别框、多手和空输出的单元测试。

**验证要求**

用固定的合成检测矩阵验证：不同类别重叠框应同时保留，同类别重叠框按 IoU 阈值抑制；再用一组真实匿名帧比较 NMS-free 与 class-aware 结果的框数、类别和坐标。

### P1-2 板端性能数字没有可追溯的仓库内原始报告

**证据**

- 正文第 149--169 行给出四个 OM 模型的精确平均推理延迟，第 426--434 行给出 YOLOv10n benchmark 输出，第 660--667 行给出 1280×720 WebRTC 约 27 fps、推理约 24 ms 等数值。
- 当前 Git 文件清单只包含 samples/case8/models/README.md、导出脚本和代码；生成的 ONNX、OM、权重及 reports 不在版本化资产中，models 目录还被 samples/case8/.gitignore 忽略。
- 正文虽注明主机名 313 和若干采集参数，但没有随仓库提供原始计时分布、CANN 版本、OM 摘要、预热/循环次数和完整 WebRTC 指标报告。

**影响**

读者无法区分当前版本的实测结果、历史开发机输出和目标参考值，也无法检查模型文件、输入合同和硬件层级是否与数字相同。精确到小数点后的结果若没有原始报告，不符合教材的可追溯性要求。

**修复建议**

1. 为每个模型提交小型、去除本地数据的报告索引：模型 ID、OM/标签摘要、硬件层级、CANN 版本、输入形状、预热、循环、重复、百分位数定义和原始报告位置。
2. 无法公开资产时，把正文表格改成示例格式或明确标记为“某次板端记录”，不要写成当前仓库可复现结果。
3. 将纯 OM 推理、摄像头流水线和 WebRTC 端到端指标分成独立证据，不相互替代。

**验证要求**

在同一 Ascend 310B4/8T 设备上重新执行四模型 benchmark 和至少一段固定时长的 WebRTC 运行，保存原始 JSON/日志，并核对正文每个数字来自同一报告。

### P2-1 README 将目标检测模型称为分类模型

**证据**

- samples/case8/README.md 第 37--44 行把 YOLOv10n_gestures、YOLOv10x_gestures 和 YOLOv10n_hands 标成“手势分类”。
- 正文第 5--15、78--81 行明确说明输入是完整图像、输出是一个或多个检测框；代码 postprocess.py 第 26--33 行也按框坐标、分数和 class_id 解码。

**影响**

初学者会把数据集任务、模型输出和评估方法理解为单标签分类，进而错误设计输入裁剪、损失解释和指标。README 与教程作为同一案例的入口，术语不应互相冲突。

**修复建议**

统一使用“多类别目标检测”或“手势目标检测”；只有在讨论单个检测框的类别判定时才使用“分类”。

**验证要求**

检查 README、脚本帮助、模型元数据、教程标题和图题，确保任务类型、输出张量和指标（框级 precision/recall，而非单图分类准确率）一致。

### P2-2 缺少对后处理和 WebRTC 合同的自动回归测试

**证据**

samples/case8/ 当前代码树没有与 hagrid_yolo/postprocess.py、preprocess.py、webrtc_app 或 WebRTC API 对应的 pytest/unittest 文件。教程第 580--644 行列出人工验收步骤，但没有给出可在无硬件环境运行的固定夹具。

**影响**

后处理坐标映射、letterbox、类别抑制和流状态机的回归只能靠板端手工观察；一旦修改模型输出格式或编码后端，教材中的验收清单无法自动发现行为变化。

**修复建议**

增加纯 Python/NumPy/OpenCV 单元测试和模拟 WebRTC offer/health/models 合同测试；硬件测试仍单独在板端运行。

**验证要求**

普通 pytest 应在没有 CANN、摄像头和 OM 的 clean clone 中通过；板端只补充 ACL、摄像头、VENC/DVPP 和真实 WebRTC smoke。
