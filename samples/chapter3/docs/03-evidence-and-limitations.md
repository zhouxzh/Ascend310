# 证据与限制

本章包含可运行训练源码、算子测试源码、历史日志和图片产物。它们分别属于代码事实、硬件数值检查和历史展示，不能互相替代。

## 证据分级

| 证据 | 层级 | 可以确认的内容 | 限制 |
|---|---|---|---|
| 训练与测试源码 | 静态代码事实 | 入口、设备选择、模型结构、损失、优化器、容差和产物路径 | 不证明代码能在当前板端运行 |
| [pytest_realtime_log.txt](../test/pytest_realtime_log.txt) | 历史运行时日志 | 2026-01-02 记录的 104 个开始项、91 个通过项和 13 个失败项 | 无最终摘要、失败详情、环境快照或重跑记录 |
| [LeNet 踩坑记录](../LeNet/errror.md) | 历史失败栈 | 一次 FP32 MaxPool 算子不支持错误及其当时输出 | 只对应记录中的软件硬件组合 |
| 训练曲线 PNG | 历史展示产物 | 文件存在，文件时间约为 2026-01-16 | 没有绑定命令、代码提交、随机种子、设备版本或原始指标 |
| `fusion_result.json` | 运行副产物 | 文件存在 | 多处内容为 `null`，不能证明融合成功 |
| `kernel_meta/`、`.pytest_cache/` | 缓存/临时产物 | 历史执行曾发生 | 不构成验收证据，不应手工编辑 |

## 当前结论

- 本章训练入口和测试入口可由“documented”源码确认。
- 一次历史通用算子测试中，91/104 个已开始用例被日志记为通过，13 个记为失败；失败没有根因，当前状态是 `blocked`。
- 仓库中的训练曲线只能作为历史展示。没有与新源码绑定的 `observed-pass` 板端训练记录。
- 当前源码在本次任务中没有重跑，故 NPU 训练、数值一致性、准确率和性能均为 `untested`；CPU 曲线也不能替代 310B 结论。

## 可复现性缺口

训练脚本的可复现性不一致：

- 线性回归和加州房价脚本设置了 Python/NumPy/PyTorch 随机种子，但没有设置 NPU 随机种子，也没有保存最终参数。
- LeNet、AlexNet、VGG 和 ResNet 没有设置随机种子。
- CIFAR-10 的 NPU/CUDA 配置不完全一致；AlexNet 的 epoch 数和批大小存在差异。
- 脚本没有记录 pip/conda 包版本、CANN 版本、驱动、固件、SoC 或 8T/20T 规格。
- 图片文件名没有携带运行编号，部分入口还会写入相同路径。

因此在新的板端复现时，应把命令、完整输出、`pip freeze`、CANN 版本文件、设备快照、开始/结束时间和产物 SHA-256 保存在独立运行记录中。

## 数据集边界

| 数据 | 获取方式 | 网络/缓存边界 |
|---|---|---|
| 合成电流/电压 | 脚本内生成 | 无外部下载 |
| California Housing | `sklearn.datasets.fetch_california_housing()` | 首次运行可能需要网络和 scikit-learn 缓存 |
| MNIST | `torchvision.datasets.MNIST(download=True)` | 缓存到 `LeNet/data/`；网络失败会阻塞 |
| CIFAR-10 | `torchvision.datasets.CIFAR10(download=True)` | 缓存到各网络目录的 `data/`；网络失败会阻塞 |

本章没有第三方模型权重或 NPU 编译模型。训练脚本只生成曲线，不导出 ONNX/OM，也不保存 checkpoint。

此前提到的 ResNet18-TinyImageNet OM 实际属于 chapter8/chapter9，不属于 chapter3。该模型在 Hugging Face revision `dfcf5885dcf7beab3a5d6e2143c73d7973bead36` 下的 OM SHA-256 为 `0b9e112751181aab82b43963f1b975adf4abbcdeec7c919ee93e496c0df8d46d`，已与下载文件核对一致。

## 结果解释边界

- 训练曲线说明某次运行的损失或准确率轨迹，不说明当前源码在另一块板卡上的结果。
- FP16 与 FP32 运行之间可能存在算子实现、容差、批大小或训练预算差异，不能把输出差异全部归因于精度。
- 加州房价脚本的标准化发生在训练/验证切分之前，指标包含数据泄漏，不能当作严格泛化指标。
- 算子测试是逐层/小形状数值检查，不是完整模型精度、吞吐、稳定性或内存泄漏测试。
- 历史日志中的通过项没有环境快照，不能和安全基线、其他 CANN 版本或 20T 结果合并。

## 重复运行前清理

运行脚本和测试会更新/覆盖 `pytest_realtime_log.txt`、PNG、`kernel_meta/`、`.pytest_cache/` 和数据缓存。需要保留证据时，应在运行前另建独立结果目录，运行后记录哈希；不要为了让工作树保持干净而删除未知来源的数据或日志。

`kernel_meta/` 和缓存目录不应作为源码提交；数据、模型和运行报告按仓库资产边界处理。
