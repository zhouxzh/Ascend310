# 触摸屏 UI 与操作手册

*QDtech MPI1001 10 寸触摸屏的照片优先界面、控件和 kiosk 操作。*

---

## 🖥️ 首页布局

目标显示为 HDMI 1920x1080。首页不再是后台表单，而是照片优先的沉浸式相册：

- 当前推荐照片占据主区域并按 `cover` 裁剪；
- 右上角显示 NPU 状态、时间和 Open-Meteo 天气；
- 文件名可在设置页通过“显示文件名水印”开关控制；
- 文件名位于照片控制工具栏内，和上一张/下一张按钮同一组；
- 图片请求会按触摸屏实际可用宽高协商 `landscape` 或 `portrait`；服务器先应用 EXIF 方向，再按显示 profile 修正。默认“保持照片方向”避免把竖拍人物横置，需要铺满相反方向时可在设置中选择“旋转匹配屏幕”；该选项只变更输出图片内容，不代表设备安装角度；
- 触摸屏 8 秒无操作后，工具栏和文件名一起淡出；触摸照片后恢复。

## 🧰 紧凑工具栏

工具栏包含五个动作：

| 动作 | 行为 |
| --- | --- |
| 上一张 | 从持久化显示历史回退 |
| 下一张 | 消费由 Chinese-CLIP/FAISS 生成的 NPU 语义候选；候选耗尽时补做一次 NPU 排序，不请求天气 |
| 暂停/继续 | 控制后台自动轮播 |
| 浏览图库 | 打开固定比例图片网格 |
| 智能搜索 | 打开中文/英文语义搜索 |

大屏工具栏按内容自适应宽度；窄屏使用全宽并把文件名放到第二行。按钮高度不低于 56px，文件名超长时省略，不遮挡照片或触摸按钮。

## 🧭 功能面板

底部导航固定提供：

1. 图库：点击图片设为主屏照片；
2. 搜索：自动路由中文到 Chinese-CLIP、英文到 MobileCLIP，也可手动选择模型；
3. 上传：选择照片并查看单线程 NPU 索引任务；
4. 设备：创建 PhotoPainter、设置 cron、裁剪和叠加策略；注册方式固定为设备主动拉取。卡片生成唯一的设备取图 URL，设备下次访问该 URL 时取得新选择；点击“推进下一张”只更新 310B 的持久化选择，不会向 ESP32 发起网络连接；
5. 设置：触摸屏选图间隔（默认 60 秒）、电脑网页刷新间隔（默认 30 秒）、电子纸轮播间隔（10 或 30 分钟）、重复抑制、天气位置、JPEG 参数、文件名水印开关和照片方向模式。

方向设置说明：`auto` 会识别手机照片的 EXIF Orientation 1-8，并保持照片本身的横竖方向；`match_display` 只在源图和屏幕方向相反时选择 `landscape` 或 `portrait` 目标并旋转输出内容。设备 profile 不提供 360°、180°或 90°/270°安装旋转选项。Waveshare PhotoPainter 官方 Wiki 的 Mode 1 输入可为 800x480 或 480x800，因此内容可选两种方向；Case7 把 Seeed reTerminal E1002 固定为 `landscape`，请求 `portrait` 必须拒绝。后者是本项目的设备策略，不能反推上游固件支持范围。

面板以全屏底部抽屉显示，不在照片下方堆叠后台卡片。关闭面板后恢复照片首页和图库导航状态。

设备页没有传输方式二选一：管理的 ESP32 始终使用 URL Rotation，由已确认固件的终端发起
`GET`。设备处于深度睡眠时，310B 无法通过网络将它唤醒；它必须在自己的轮播时隙醒来并
访问保存的取图 URL。新的“验证并注册”入口会在注册阶段通过设备 HTTP API 写入并读回
URL Rotation；如果设备固件不提供该 API，注册会失败，需先在 ESP32 本机网页完成配置并确认
固件支持该协议后再重试。

### 设备页的两类设备

设备页把本机显示与远端电子相册拆成独立卡片，避免将 HDMI 屏当成需要配网的 ESP32：

| 卡片 | 身份与用途 | 可设置项 | 不具备的能力 |
| --- | --- | --- | --- |
| 本机触摸屏相册 | `local-touchscreen`，开发板 HDMI/QDtech MPI1001 输出 | 名称、自动轮播启停、换图间隔、显示方向、重复抑制、文件名水印、立即切换 | IP、HTTP 轮询、ESP32 设备 profile |
| 注册 ESP32 电子相册 | 新建 Waveshare ESP32-S3-PhotoPainter 或 Seeed Studio reTerminal E1002 远端终端 | 名称、固定 profile、内容方向；注册后设置 cron、裁剪、日期/天气叠加、播放列表和启停 | 不能修改本机 HDMI 的显示策略；不能选择服务器主动发送或注册第三种 ESP32 相册型号 |

#### 如何识别已注册设备

打开 **设备** 面板后，先看顶部 **设备总览**。这里的“已注册”数量来自
`GET /api/admin/devices`，不包含本机 `local-touchscreen`；“型号已确认”表示 profile
已经明确，“待确认”表示历史记录仍在数据库中但尚未绑定到 Waveshare 或 E1002，不能用于
取图、换图或 profile 专属策略。列表随后按“待确认型号、Waveshare PhotoPainter、Seeed E1002”等分组，
每张卡片顶部显示名称、设备 ID 和启用状态，事实摘要显示固定的设备主动拉取方式、设备取图 URL、
当前照片、最近请求、请求结果和策略 revision。

每台已确认设备的 **设备取图 URL** 可以复制到固件配置中。ESP32 注册只有一个传输路径：

1. 从 ESP32 串口日志或其本机网页获取当前 IPv4；
2. 在 Case7 注册页面填写该地址并执行“验证并注册”。服务会在设备可达且 API/身份核验
   成功时写入 URL Rotation，并返回卡片中的取图 URL；
3. 若固件没有可写入的 URL Rotation API，才在设备自己的网页中粘贴取图 URL、保存并开启
   自动轮播，然后回到 Case7 重新登记/核验；
4. 在 Case7 点击 **推进下一张** 时，只更新该设备的持久化选择；ESP32 下一次访问 URL 时才
   会获取新照片。

注册不扫描局域网、不猜测 ESP32 IP 或固件端点。它只访问用户明确填写的设备地址，并在
设备 API 支持时写入 URL Rotation；若固件网页没有 URL Rotation 或图片 URL 配置，必须先
刷入或修改明确支持该协议的固件，不能通过本页面强行
开启。设备页面不显示服务器主动发送的协议、根 URL、超时、重试或“立即推送当前照片”控件；
历史兼容接口仅见 [03 API 与 ESP32 协议](./03-album-server-api-and-esp32-protocol.md) 的维护章节。

设备卡片底部的操作分为两种：**禁用设备**是可恢复的软停用，记录仍留在列表中，
但设备不能取图；**删除注册**是永久移除设备注册记录及其轮播状态，
需要先点一次进入确认状态、再点一次确认。删除不会删除原始照片、照片元数据或其他设备的
索引。删除接口要求 `DELETE /api/admin/devices/{id}?confirm=true`；缺少确认参数会返回
`400`，本机 `local-touchscreen` 永远不能删除，只能修改或禁用。

当前板端历史数据可能包含多个同名记录。不要按名称判断设备，使用卡片上的 profile、分辨率、
设备 ID 和最近请求时间确认目标；无法确认来源的记录可以先禁用，确认无误后再删除注册，
避免向错误终端发送照片。

本机卡片通过 `GET/PATCH /api/admin/touchscreen` 与
`POST /api/admin/touchscreen/advance` 操作；更新时页面带上配置 revision。点击“暂停轮播”只停止
本机自动换图，恢复后继续使用保存的当前照片和显示历史。ESP32 注册则使用
`POST /api/admin/devices/register`：页面要求填写串口确认的设备 IPv4，服务会实际访问设备、
核验 PhotoFrame 固件/型号并读回 URL Rotation 配置；只有全部验证通过才返回 HTTP `202`
（`registration_status=awaiting_pull`）并保留注册。该响应表示控制面配置完成，不表示设备已经
拉图或刷新屏幕。
失败时返回“未注册”，不会留下不可达设备。旧 `POST /api/admin/devices` 对 PhotoFrame 请求固定返回
`400/not_registered`，不会创建待连接记录；数据库中已有的 `pending_connection` 仅作历史状态展示，
不能当作成功注册。服务不会扫描局域网、猜测设备 IP 或测试未确认的
固件端点。配置验证成功也不等于屏幕已刷新，必须等待设备真实拉图证据。

## 📥 首次导入照片

刚安装系统、清空索引或更换开发板后，图库可能为 0 张，首页会显示“相册还没有可显示的照片”。这是数据目录为空的提示，不代表触摸屏或 NPU 服务故障。首次导入按以下顺序操作：

1. 点击底部 **上传** 入口，选择一张或多张 `JPG/JPEG/PNG/BMP/WebP` 图片，或使用 **选择文件夹** 递归读取整个照片目录。
2. 点击 **上传并建立 NPU 索引**。服务优先读取 EXIF 拍摄时间，缺失时使用服务器上传时间；上传面板不要求手工标签。
3. 在上传面板观察“文件传输”和“NPU 索引”进度条，等待任务从 `queued` 经哈希、导入、校验、各模型编码和收尾变为 `completed`；进度的文件/embedding 计数来自实际处理结果。最终检查任务摘要中的 `indexed`、`duplicates`、`skipped` 和 `photo_ids`。索引期间不要反复提交同一文件。
4. 返回 **图库** 查看已导入照片，点击任意照片可设为当前主屏照片；首页的 **下一张** 可触发下一次选择。

普通网页/API 上传不设置单张文件大小或单次张数上限；仍保留单张解码像素不超过 50 MP 的内存保护，并要求扩展名和图片内容通过校验。选择文件夹后前端会按 100 张一批顺序提交，用户无需手动拆分；实际总量仍受浏览器、磁盘和单线程 NPU 索引速度限制。服务器使用内容哈希去重，重复上传不会产生第二份照片。默认上传任务会依次使用已准入的 MobileCLIP、Chinese-CLIP 和 ResNet50 建立向量；模型未准入、文件损坏或超限时状态为 `failed`，错误文字会显示在面板中。生产服务不使用 CPU 推理兜底。

也可以从另一台局域网电脑执行：

```bash
curl -F "files=@/path/to/photo.jpg" \
  http://192.168.1.135:7860/api/photos/upload
curl http://192.168.1.135:7860/api/jobs/<job_id>
```

从第一条响应复制 `job_id`，重复查询第二条命令直到 `status` 为 `completed`；随后刷新图库。普通上传会写入系统用户的 `~/Pictures/ai-album/imports/`，临时文件写入 `~/Pictures/ai-album/.upload-tmp/`；不要将个人照片直接放入仓库的 `photos/` 或 `shared/photos/`。也不要期待服务器预先生成缩略图缓存。完整请求字段见 [03-album-server-api-and-esp32-protocol.md](03-album-server-api-and-esp32-protocol.md)。

### 显示更新周期

本机 HDMI 触摸屏由服务器每 60 秒执行一次新的智能选图；电脑浏览器默认每 30 秒请求一次显示元数据。浏览器会比较 ETag，照片和渲染参数未改变时只更新状态，不重复下载 JPEG。电子纸输出拥有独立时钟，默认 30 分钟刷新，也可在设置页选择 10 分钟；暂停相册会同时暂停自动选图和电子纸刷新。手动点击上一张、下一张不请求天气：调度器在空闲时用已准入 Chinese-CLIP 文本编码器和 FAISS 为本机准备一份内存候选队列，点击只提交其中下一项；队列因天气、配置、图库变化而失效或耗尽时，下一次操作会补做一次 NPU 语义排序。因而手动导航仍由 NPU 的语义分数决定，同时避免每次点击都重复加载模型或访问天气服务。

### 切图延迟与资源边界

一次手动切图包含两个不同阶段：`POST /api/display/control` 先提交 NPU 语义候选对应的照片 ID，随后浏览器按实际视口请求按需 JPEG。2026-08-30 在 `192.168.1.135` 的 8T 板上，控制请求约为 15--17 ms，1024x676 JPEG 渲染约为 0.28--0.32 s，1920x1080 JPEG 渲染约为 0.65--0.71 s；旧版本 1024x676 约为 0.45--0.48 s。首次启动、天气/配置变化或队列耗尽时，控制请求还会包含一次串行 NPU 文本推理，延迟应单独记录；队列温热时不会重复推理。高分辨率原图的 EXIF 处理、缩放和 JPEG 编码仍是图像显示阶段的主要延迟来源。

首页启动不再预加载图库。只有打开“图库”面板时才读取照片列表，网格图片使用浏览器 `loading=lazy`、异步解码和低优先级请求，避免数十张 2--4 MB 原图与主屏渲染争用网络、磁盘和解码资源。服务器仍不生成或保存缩略图、JPEG 或其他图片缓存；`Image.draft` 仅作为当前请求的 JPEG 解码提示，不能替代硬件验收。

## 📱 视口适配

| 视口 | 规则 |
| --- | --- |
| 1920x1080 | 照片优先、带文字按钮的紧凑工具栏 |
| 1280x800 | 工具栏按内容收缩，模型/天气信息保持可读 |
| 1024x600 | 按钮缩短，文件名限制宽度 |
| 400x900 | 工具栏全宽，按钮保留图标，文件名独占第二行 |

页面禁止横向滚动；网格图片使用固定宽高比，避免图片加载或文件名变化造成布局跳动。

## 🚀 启动 kiosk

板端执行：

```bash
DISPLAY=:0 \
XAUTHORITY=/home/HwHiAiUser/.Xauthority \
bash scripts/launch_touchscreen_kiosk.sh
```

脚本只启动本项目的 Firefox URL，不结束其他浏览器进程。调试时可访问
`http://192.168.1.135:7860/?mode=touchscreen`，手机浏览器直接访问根 URL 即可。

## 🛠️ 常见问题

- 图片为空：新系统通常是尚未导入照片；先打开上传面板并等待任务 `completed`，再检查 `/api/display/current` 和图库数量。
- 搜索显示返回数量但照片卡片空白：相机照片可能是 MPO 容器；图库和搜索现在使用 `/api/photos/{id}/preview` 的短时内存 JPEG 预览，先强制刷新页面并确认响应为 `image/jpeg`。`/file` 仍是原图下载接口，不应直接作为 `<img>` 地址。
- 上传失败：查看任务中的 `error`；`400` 多为格式或空请求，前置代理的 `413` 属于代理请求体策略，模型未准入时不会回退 CPU。
- 上一张/下一张无变化：检查服务是否仍在运行、按钮是否处于“切换中”，再查询 `/api/display/status` 中的 `semantic_preselection.last_inference`、`queue_size` 和 `current.selection_source`。
- 页面旧样式：使用带 `ui=` 版本参数的 kiosk URL，或重新启动脚本。
- 天气不变：这是预期行为；下一张复用后台天气，天气只在定时周期或显式刷新时请求。`selection_source=npu_semantic_prefetch` 表示照片来自已完成的 NPU 语义预选，`npu_semantic_sync` 表示本次点击补做了 NPU 排序。
