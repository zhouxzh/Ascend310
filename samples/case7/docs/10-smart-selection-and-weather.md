# 智能选图与天气

*日期、天气、兼容元数据和 CLIP 语义共同驱动本机与远程显示选择。*

---

## 🎯 选择评分

候选集合只包含可用且未删除照片。默认评分为：

```text
总分 = 0.60 * 语义相似度
     + 0.25 * 日期/时段匹配
     + 0.15 * 天气/兼容元数据匹配
```

中文上下文使用 Chinese-CLIP；照片日期优先 EXIF，缺失时使用上传时间。天气分数可将最后有效天气标签与历史数据库的兼容元数据比较。常规上传不要求或接收手工标签，当前工程也没有部署自动图像标注模型，因此新照片在没有这类历史元数据时，该部分得分为零；最近显示的 12 张照片进入重复抑制窗口，无候选时回退到最新拍摄或上传照片。

## ⏰ 轮播与 revision

PhotoPainter/电子纸默认 cron 为 `*/30 * *`，按服务器时区解释；可按需改为 `*/10 * *`。固定测试播放列表仍使用 `selection_mode=playlist` 和 `*/5 * *`，按照片 ID 顺序循环。选择结果写入 `display_state` 和 `display_history`，包含当前照片、时隙、策略 revision 和 selection revision。触摸屏选图默认每 60 秒执行，电脑网页每 30 秒轮询元数据，和电子纸 cron 相互独立。

同一时隙内的网络重试返回同一选择；服务重启后读取持久化状态，不重新随机选图。上传、天气变化、配置变化和轮播时隙到达时递增 selection revision。

## 🌦️ 天气刷新边界

天气客户端默认使用 Open-Meteo。后台轮询根据 `weather.refresh_seconds` 刷新并保留最后有效状态；请求失败时继续使用日期、兼容元数据和已有天气状态。

`next`、`previous`、图库点选和相似图搜索不主动请求天气。手动 `next` 消费由 Chinese-CLIP 文本编码和 FAISS 预先生成的语义候选队列；队列失效或耗尽时，下一次操作会使用缓存天气同步补做一次 NPU 排序。显式 `POST /api/display/refresh` 或后台刷新周期才会访问天气服务，因此连续点击不会重复请求天气，也不会在每次点击都重新加载模型。后台定时轮播仍按本节评分规则执行。

手动切图的控制请求与图片渲染是两个阶段。控制 API 的响应确认 NPU 语义候选对应的选择状态，浏览器随后请求按视口编码的 JPEG；温热队列只做内存中的 ID 提交，冷队列会在同一串行锁内执行一次 NPU 文本编码和 FAISS 排序。高分辨率原图的 EXIF 旋转、缩放和编码会占用主要时间。图库面板延迟加载并对网格图片启用浏览器懒加载，避免整库原图下载与主屏 JPEG 渲染竞争。服务端不写入缩略图或派生图片缓存，解码尺寸提示只作用于当前请求。

## 🖼️ 显示 profile

本机触摸屏、LCD、PhotoPainter 和 E6 共享选择器，但渲染 profile 不同：

| profile | 选择器输出 | 渲染输出 |
| --- | --- | --- |
| touchscreen | 当前照片元数据 | 浏览器按需 JPEG |
| lcd | 当前 revision/ETag | 能力尺寸 JPEG |
| photoframe | 设备策略选择 | bounded JPEG，交给固件六色转换 |
| epaper | 当前照片和 revision | 800x480 六色 192000-byte dry-run 帧 |

不同设备维护独立的当前照片和历史，避免一个设备的轮播改变另一个设备的结果。
