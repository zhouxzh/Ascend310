# Ascend 310B Debug Plugin Audit

Date: 2026-10-26
Scope: `lib/`, browser panel, HTTP routes, discovery/inventory, serial/apt/download/task policy, 14 packaged skills, data indexes, and tests.

This audit is read-only. It does not change plugin implementation and does not run board commands.

## Verdict

**Needs changes before calling the plugin stable.** The host tools and packaging tests pass, but the browser panel has several confirmed stale-state races, and the task/download policy has a privileged reboot bypass plus an over-broad write destination.

## Findings

### P1 - Privileged reboot bypass

Files: `lib/shell.js:413-454`, `docs/command-execution-matrix.md:72-76`, `test/shell.mjs:178-198`.

Pure validation reproductions:

```text
validateTaskCommand('sudo reboot', {allowPrivileged:true}) -> ok: true
validateTaskCommand('sudo /sbin/reboot', {allowPrivileged:true}) -> ok: true
validateTaskCommand('sudo -- reboot', {allowPrivileged:true}) -> ok: true
```

The reboot guard does not account for a `sudo` prefix, while the same `allowPrivileged` flag admits sudo. This contradicts the documentation that reboot/shutdown/poweroff are always refused. Existing tests cover reboot and sudo independently, not the combined forms.

### P1 - Model download can write anywhere in the user's home

Files: `lib/index.js:2021-2048`, `lib/index.js:619-642`.

The public description says the destination must be inside the board workspace or `/tmp`, but `resolveTaskCwd` permits every path below `/home/HwHiAiUser`, and `remotePath` accepts absolute paths. The download task unconditionally passes `allowDestructive:true` and ends with `mv -f`. A caller can therefore overwrite `.bashrc`, `.env`, or other home files. Restrict downloads to a configured model workspace and `/tmp`, and reject sensitive directories.

### P1 - Browser target rail hides configured targets

File: `lib/client.js:717-744`.

When inventory has any board, the rail builds rows only from inventory boards. Configured targets that are offline or not yet discovered disappear. Reproduction: `targets=[8T,20T]`, `boards=[8T]`; only 8T is rendered. A selected hidden target can still be active in state but cannot be selected in the UI.

### P1 - Browser target switching displays mixed-board data

Files: `lib/client.js:878-909`, `lib/client.js:956-963`.

`selectBoard` updates the selected target immediately while the old report remains `ready` until the new request returns. The header can show board B while facts, memory, CANN and peripherals still belong to board A. Add a displayed target/request generation and render an explicit stale/switching banner or clear facts until the new response commits.

### P1 - Cross-action async races and unmount updates

Files: `lib/client.js:911-1054`.

`loadSequence` and `probeSequence` are independent. A report GET can overwrite a newer probe; discovery and serial completion capture an old `selected` value and can switch the UI back to the wrong target. The component also has no unmount cleanup for initial load, discovery, or serial requests. Use one generation coordinator for all actions and abort every controller on unmount.

### P1 - Unified environment false pass

File: `lib/compat.js:551-575`.

The verdict uses `ascendEnvPolicyIsolated === true || ascendEnvIsolated === true`. A bare interpreter with user-site enabled can therefore pass if its direct `site.ENABLE_USER_SITE` happens to be false, even when the actual launch policy was not set. The policy field must be mandatory; the bare field should remain diagnostic only.

### P1 - Package gate checks discoverability, not importability

Files: `lib/probe.js:136-144`, `lib/compat.js:494-525`, `lib/compat.js:567-588`.

Most required packages are tested only with `importlib.util.find_spec`. Native packages such as `cv2`, FAISS, ONNX Runtime, PyAV, PySide6 and sounddevice can have a spec while failing to load shared libraries. This failure was observed in a real `ascend` environment. Add true import smoke checks with origin/error capture. `torch_npu` and `mindspore_lite` are also absent from the required-package set despite being discussed by skills.

### P1 - Fixed-revision publication policy is not enforced

Files: `lib/index.js:661-675`, `lib/index.js:2006-2031`, `skills/ascend310b-case-testing/SKILL.md:86`.

The downloader defaults revision to `main` and accepts branch names. The case-testing skill requires an immutable revision. The tool should reject moving branches by default and require a commit SHA or an explicit immutable tag policy.

### P2 - Download integrity is reported as verified after failures

File: `lib/index.js:2053-2060`.

`integrity` becomes `verified` whenever the task executed and a SHA was supplied, regardless of `task.exitCode`. A failed download or failed checksum can therefore be presented as verified. Set verified only when `exitCode === 0` and the atomic command completed.

### P2 - Probe ACL field has misleading environment context

Files: `lib/probe.js:50-55`, `lib/probe.js:115-149`.

The top-level `aclImportSourced` check activates `base`, not `ascend`. The later `ascendEnvAclImport` check is the correct unified-environment gate, but the top-level field and README wording can be read as case-environment evidence. Rename or explicitly label the top-level value as base/system diagnostic.

### P2 - CWD failure can fall through to task execution

Files: `lib/shell.js:617-620`, `lib/index.js:759-773`.

The composed shell can look like `cd '/missing' && set +u; export ...; command`. The failed `cd` only gates the adjacent command before the semicolon; subsequent setup/task commands may run in the SSH default directory. Use a shell block with `cd ... || exit` or validate the directory remotely before execution.

### P2 - Fresh report drops diagnostic fields

File: `lib/index.js:2499-2510`.

When preserving the cache after `fresh=1`, the route copies facts and pairing but omits `rawExcerpt`, `transport`, and `inventoryChange`. The raw-output tab and offline context can disappear after “重读快照”. Merge all display fields or use one canonical report serializer.

### P2 - HTTP report exposes internal target fields

Files: `lib/index.js:2451-2459`, `lib/index.js:2544-2552`.

Routes put the internal target object directly into browser JSON instead of using the redacted `publicTargets` serializer. This can expose `identityFile`, `workdir`, or other local configuration paths. Return an explicit public target shape only.

### P2 - Knowledge route overstates root cause

File: `lib/knowledge.js:348-358`.

“HTTP health passes but inference fails” is categorized as “service has no CANN environment”. Model load, input contract, device state, operator, memory and application errors are equally plausible. This must be a hypothesis with branches to load/contract/runtime checks.

### P2 - Version evidence is incomplete

Files: `lib/probe.js:484-503`, `skills/ascend310b-debug/SKILL.md:52-58`, `lib/knowledge.js:393-400`.

Skills and knowledge require Toolkit/compiler/ops/NNAL evidence, but the parser exposes mainly core CANN and driver fields. Either collect structured compiler/ops/NNAL fields or mark those fields explicitly untested; do not let the pairing report imply a complete version matrix.

### P2 - Frontend accessibility and error-state quality

Files: `lib/client.js:520-545`, `lib/client.js:1212-1219`, `lib/client.js:1340-1364`, `lib/client.js:1475-1481`.

Arrow/Home/End changes the selected tab but does not move focus. Search, symptom and dependency controls lack labels/aria-labels. Failed-load errors lack consistent `role=alert`/live-region behavior. The panel also conflates initial report loading with probe cancellation.

### P2 - Test and composed-bundle coverage is weak

Files: `test/client-mount.mjs:37-44`, `test/client-render.mjs:129-139`, `cordis.patch.yml:5-7`.

React hooks are no-ops, rendering is mostly text flattening, and tests do not trigger fetches, clicks, target changes, aborts, discovery, serial discovery, binding, stale responses or keyboard focus. The patch test checks host registration but not a composed browser bundle/profile installation. A green `npm test` is not evidence that the UI state machine works.

### P2 - Dependency panel contains stale case metadata

File: `data/case-dependencies.json:73-82`.

Case6 still advertises `python3-dev` and `python3-pip` as required apt packages although the current case6 setup uses the unified `ascend` environment and no system pip. The panel can recommend obsolete installation steps.

## Skills review

All 14 packaged skills exist and are byte-identical to their matching `.dsh/skills` copies. Names reviewed:

- `ascend310b-api-best-practices`
- `ascend310b-camera-debug`
- `ascend310b-cann-development`
- `ascend310b-case-testing`
- `ascend310b-code-review`
- `ascend310b-crash-debug`
- `ascend310b-debug`
- `ascend310b-env-check`
- `ascend310b-microphone-debug`
- `ascend310b-npu-arch`
- `ascend310b-precision-debug`
- `ascend310b-runtime-debug`
- `ascend310b-speaker-debug`
- `ascend310b-sync-audit`

Coverage is conceptually coherent, but most peripheral/API/precision skills are prose runbooks without executable command-contract fixtures. The largest policy mismatch is the environment skill claiming package coverage while the implementation only performs `find_spec`; the case-testing skill requires fixed revisions while the downloader defaults to `main`; and the CANN skill requires version evidence the probe does not collect.

## Verification

The following test modules passed after the fixes: parse, compat, scope, planner, shell, install, targets, discovery, serial, client-mount, client-render, portability, skills, capture and smoke. `node --check lib/client.js` and `git diff --check` also passed. No board commands or board state changes were made during the repair.

## Repair status

The following audit findings were fixed in the current worktree:

- sudo-prefixed reboot/shutdown/poweroff/halt/kexec rejection;
- task cwd shell-block handling so a failed `cd` cannot fall through;
- download destination restriction and exit-code-aware integrity reporting;
- mandatory launch-policy user-site isolation and true package import evidence;
- case6 stale dependency metadata and broad service-root-cause wording;
- target/inventory merge, unified frontend request generation, abort cleanup,
  stale snapshot retention, binding reset, keyboard focus and ARIA fixes.

The report's remaining advisory items are intentional follow-up work: complete
browser-level interaction tests rather than React stubs, collect structured
compiler/ops/NNAL evidence, and enforce immutable revisions in the model
publisher workflow. The original findings above are retained as audit history;
the current source and test suite are the post-fix state.
