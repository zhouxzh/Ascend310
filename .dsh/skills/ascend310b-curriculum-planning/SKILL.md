# 教材课程计划

## 范围

用于教材层计划，而不是直接改正文：

- 理论章节与案例之间的先修关系；
- 每章/案例的学习目标、可观察产出和评估证据；
- `samples/` 入口与教学内容映射；
- `src/presentation/` 课件的课堂节奏；
- 8T/20T 实验、摄像头、CANN 和模型依赖的覆盖检查。

本 skill 参考教育 Agent Skills 的学习目标、能力拆解和评估有效性思想，但以本仓库冻结命名、样例入口和板端证据为准。

## 计划矩阵

每行至少填写：

```text
对象: 第N章 / 案例N / 附录 / 课件
学习结果: 学生能做什么（observable verb）
先修: 需要的前置概念或实验
理论: 对应 src/book 或 src/experiment 页面
代码: 对应 samples/ 入口
评估: 代码、日志、数值、任务指标或演示证据
硬件: 8T/20T、摄像头、NPU、CANN 条件
缺口: 尚无证据的内容
```

学习结果使用“解释、实现、诊断、验证、比较、设计”等可观察动词，不用“了解、熟悉、掌握”这种无法评估的词。

## 工作流

1. 运行 `ascend310b_writing_progress` 和 `ascend310b_writing_audit`，了解当前篇幅、冻结名和断链。
2. 阅读 `src/book/README.md`、`src/experiment/README.md`、`src/presentation/README.md` 和 `samples/case-index.json`。
3. 建立“章节—案例—代码—课件—证据”矩阵。
4. 检查先修顺序：理论概念是否在案例前出现，案例代码是否对应真实 `samples/` 入口。
5. 检查评估：每个案例至少有一个真实可运行证据；没有板端证据的结论标为 `untested`。
6. 检查 8T/20T、摄像头、模型和 CANN 依赖；不要把某板结果当作全平台结果。
7. 只修改计划/docs 或用户要求的源页面；冻结标题和 sidebar 只在明确改名时同步。
8. 完成后复跑 audit/progress，推送前运行 `ascend310b_writing_push_check`。

## 评估原则

- 学习目标、课堂任务和最终证据必须对齐。
- 案例的演示截图不能替代 API、数值和性能证据。
- 同一评估只测一个主要能力，不要把模型精度、性能和 UI 混成一个“通过”。
- 如果没有可复现输入和命令，该目标保持 `blocked` 或 `untested`。
- 课程计划可以建议新增实验，但不能伪造实验已经执行。

## 停止条件

- 学习目标不可观察或没有评估方式。
- 先修关系形成循环。
- 章节/案例/样例入口不一致。
- 案例结论没有当前 310B 证据。
- 需要修改冻结名但没有用户明确要求。
