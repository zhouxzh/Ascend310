# 技术报告图表设计

本 skill 只负责“把已确定的技术关系画成可编辑、可渲染、可验证的图”。技术内容、专利边界、论文图注或教材教学顺序由对应领域 skill 决定。

- 专利交底：`patent-disclosure` 决定附图类型、标号、线型、公开边界和图注；
- 教材 Graphviz：`ascend310b-writing-dot` 提供画布、字体、模板和文件引用规则；
- TikZ 神经网络：`ascend310b-writing-neural-diagram` 提供路径/模块框碰撞审计；
- 论文：`paper-latex-cn` 或目标期刊 LaTeX skill 决定最终排版和编号。

## 图形选型

| 关系 | 首选工具 | 说明 |
| --- | --- | --- |
| 系统边界、模块依赖 | Graphviz `dot` | 方向明确，自动布局稳定 |
| 方法步骤、判断与失败分支 | Graphviz / Mermaid flowchart | 判断节点必须有“是/否”出口 |
| 状态迁移 | Graphviz / Mermaid state | 标明触发条件、状态和恢复 |
| 时序与消息 | Mermaid sequence / 手工矢量图 | 标明参与者、消息方向和条件 |
| 神经网络与编码器结构 | TikZ | 使用 sidecar 做几何审计 |
| 硬件连接 | 简化原理框图 | 信号方向、接口、供电和保护可见 |
| 参数、符号或模块关系 | 技术表格 | 纯叙述关系不塞进表格 |

## 构图规则

1. 先写图的节点清单：实体、输入、输出、信号、控制、状态和外部边界。
2. 每个箭头必须有一端明确表示数据、控制、时序、供电或物理连接；不画无语义装饰箭头。
3. 判断节点必须有明确出口；正常、异常、恢复路径连续。
4. 单图聚焦一个主要关系。超过 6–8 个主节点时拆成总览图和细节图。
5. 图内不复述文档标题；图注由宿主文档维护。
6. 术语与正文一致；缩写首次出现要给全称。
7. 黑白材料使用线型、填充和文字区分层级，不靠无法复印的浅色。
8. 不得用彩色营销图替代技术关系图。

## 可编辑源与渲染

每种图都必须保留源文件、渲染命令和导出文件。详细命令见 [toolchain.md](references/toolchain.md)。

最低交付：

```text
diagram.dot / diagram.mmd / diagram.tex / diagram.drawio
diagram.svg
diagram.png（仅固定像素载体需要）
diagram.layout.json（TikZ 神经网络需要）
```

不得只交截图。发现图错误时修改源文件并重新生成，不手改 PNG。

## 验收

- 源文件存在且可重新渲染；
- 渲染命令和工具版本可追溯；
- 图中节点、边、状态和技术方案一致；
- 箭头不穿节点、不压标签、不产生无语义交叉；
- 判断分支和失败路径完整；
- 图号、图注、正文引用和标号一致；
- 黑白或目标材料要求的配色正确；
- 最终网页、PDF、Word 或幻灯片尺寸下文字可读；
- 专利图再加载 `patent-disclosure` 的附图专项规则；
- 几何审计 PASS 不等于最终视觉验收，仍须检查实际渲染。
