# 教材学术写作

## 范围

用于《昇腾 310B 边端 AI 实战》的学术性文字：

- 理论章节的概念框架、问题定义和相关工作；
- 案例的方法、实验设计、结果解释和限制；
- 图表、引用、数据来源和可复现实验说明；
- 将论文中的方法映射到教材，但不虚构论文结论。

不替代代码实现、板端验证、案例运行手册或真实实验报告。

本 skill 参考 PaperOrchestra、latex-arxiv-SKILL、PaperFit 等论文工作流的“主张—证据—可复现”门控，但教材内容必须围绕本仓库的 310B 事实和教学路径重新组织。

## 学术写作门

每个重要段落至少能回答：

```text
claim: 作者主张什么？
evidence: 哪次实验、哪份原始日志、哪篇文献支持？
scope: 8T/20T、CANN/驱动、模型、输入和日期是什么？
limit: 哪些情况没有验证？
```

没有证据的句子只能写成：
- 明确标注的假设；
- 待验证问题；
- 外部文献的 reported result；
- 不能写成 `observed-pass`。

## 结构建议

### 理论章节

1. 问题与边界；
2. 背景与相关工作；
3. 概念模型或方法；
4. 在 310B 上的映射；
5. 可验证例子；
6. 限制与练习。

### 案例方法/实验

1. 假设；
2. 数据、模型与硬件；
3. 预处理和输入输出合同；
4. 基线；
5. 指标与测量协议；
6. 结果；
7. 失败样本；
8. 限制和复现条件。

## 引用和证据

- 引用必须能追到论文、官方文档或本仓库原始报告。
- 不编造 DOI、作者、年份、页码或数据。
- 外部论文结果与本板实测分开写。
- 8T 与 20T 的结果不合并，不把一个档位的结果泛化到另一个档位。
- 图表编号、正文引用和图源要一致。
- 生成式工具只用于改写表达；事实、引用和实验数据必须由作者核对。

## 教材润色模式

用户说“润色”“正式出版”“人类可读”“去 AI 味”“压缩”“像教材一样写”时，进入本模式。参考 `nature-polishing` 的读者工作流，但输出必须是中文教材正文，不是英文论文润色报告。

### 先诊断，再改句

不要先做同义词替换。按这个顺序判断：

```text
读者对象 -> 段落任务 -> claim / evidence / scope / limit
-> 段落是否必要 -> 术语是否一致 -> 句子改写
```

每个重要段落至少要能回答：

- 读者为什么需要这一段；
- 这一段的主主张是什么；
- 证据来自代码、日志、命令、板端报告还是引用；
- 适用于 8T、20T、哪个 CANN/模型/输入；
- 哪些情况没有验证。

如果段落的结构问题不能在不知道新事实的情况下修复，明确列为“待作者确认”，不要用漂亮句子掩盖。

### 必须保护的内容

润色可以改表达，不得静默改动：

- 代码、命令、API 名、配置键、路径、端口、错误码；
- 数值、单位、token 预算、性能指标、日期和版本；
- 8T/20T、SoC、CANN、驱动、模型 revision 的适用范围；
- `observed-pass`、`observed-fail`、`untested`、`blocked` 的证据等级；
- 引用、链接、图片 alt 和代码块语言标记；
- 用户已经确认的结论边界。

### 句子和段落规则

- 每段先给结论或任务，再给机制、条件、证据和限制。
- 用“因为、因此、但是、例如”表达真实逻辑，不用“值得注意的是、综上所述、可以看到”填充。
- 删除营销腔、空泛总结、对话残留、重复排比和“本页/本节聚焦……”式模板句。
- 删除作者可见但学生不需要的生产备注：`.dot` 路径、字体名、pt/dpi、审计规则名、工具名、`human-review`。
- 技术术语保持 canonical form，不为“文采”换同义词；缩写首次出现时解释。
- 句子以短句和中等长度句为主；一个句子只承担一个主要判断。
- 不编造动机、用户体验、生产效果、性能提升或“显著”结论。
- 不把“页面返回 200”“命令退出 0”改写成“模型质量通过”。
- 中文标点、空格、数字单位和代码格式按本仓库 Markdown 规则处理。

### 输出格式

用户要求润色时，默认给出：

1. 可直接替换的润色正文，用普通 Markdown，不放在代码围栏里；
2. `Revision notes:`，3–5 条，说明主要结构、段落和表达改动；
3. `保留项：` 列出不能从现有证据确认的内容；
4. 如果改变段落顺序或论证结构，明确说明。

如果用户要求逐段对比，再给：

```text
Original
Polished
Why changed
```

只给建议、不给可替换正文，不算完成润色。

## 工作流

1. 运行 `ascend310b_writing_audit`。
2. 确定对象和段落任务；建立术语表和 claim/evidence 表。
3. 先修结构、段落必要性和事实边界，再做句子润色。
4. 生成可替换正文和 Revision notes。
5. 运行 audit；`ascend310b_writing_style` 只能作为风格诊断，不能代替人工改写。
6. 有 LaTeX/PDF 需求时使用 `ascend310b-writing-latex`。
7. 推送前运行 `ascend310b_writing_push_check`。

## 停止条件

- 关键主张没有证据或 citation。
- 把外部论文的 reported result 写成当前板端 observed-pass。
- 混淆 8T/20T、CANN 版本或模型版本。
- 生成图表/PDF 后才想补事实。
- 无法复现的实验没有写入限制。
- 把 `.dot` 路径、字体名、pt/dpi 或作者自检备注写进学生可见正文。
- 只运行 `ascend310b_writing_style` 或只给修改建议，却声称已经完成润色。
