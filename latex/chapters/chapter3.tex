PyTorch
是以动态计算图著称的深度学习框架，核心由灵活的张量运算与自动微分系统构成。eager
execution 让调试、可视化和原型迭代更直观，而 TorchScript
则提供图模式部署以兼顾性能与可移植性。配合丰富的
TorchVision、TorchAudio、TorchText
等生态包，开发者可以在视觉、语音、自然语言处理等任务上快速搭建端到端方案。

Ascend Extension for PyTorch 是华为昇腾为 PyTorch
用户提供的深度适配插件，使 PyTorch 能无缝调用昇腾 AI
处理器算力，沿用原生接口并针对算子、通信与调度做深度优化。项目源码可在官方仓库获取，更多动态可关注昇腾社区。

虽然当前已有 CANN、MindSpore 等优秀深度学习框架，但在 PyTorch
广泛应用的背景下，先基于 PyTorch 学习并借助昇腾插件迁移至昇腾
310B，既能降低学习门槛，又可减少适配成本、缩短开发周期。

\section{架构速览}\label{ux67b6ux6784ux901fux89c8}

整体架构可概括为``PyTorch前端 + torch\_npu中间层 +
昇腾算子后端''。图1展示了其分层设计：PyTorch前端将动态图、自动微分、优化器等能力暴露给开发者；\passthrough{\lstinline!torch\_npu!}
负责对接CANN算子库、通信库以及运行时；底层由昇腾AI处理器提供硬件加速。理解这一层次关系有助于在故障排查时迅速定位问题。

\section{核心能力纵览}\label{ux6838ux5fc3ux80fdux529bux7eb5ux89c8}

插件在多个维度增强了PyTorch在昇腾平台的体验：

\begin{itemize}
\tightlist
\item
  \textbf{算子与生态适配}：基于开源PyTorch实现对昇腾AI处理器的深度定制，持续补齐主流算子与第三方库，保证常见模型脚本可直接迁移。
\item

\item

\section{脚本迁移示例：MNIST
CNN}\label{ux811aux672cux8fc1ux79fbux793aux4f8bmnist-cnn}

下面的示例演示如何把一个GPU版MNIST卷积网络脚本迁移到昇腾NPU。示例采用自动迁移与混合精度策略，适合快速体验。

\subsection{基准脚本}\label{ux57faux51c6ux811aux672c}

首先准备原始GPU脚本 \passthrough{\lstinline!train.py!}：

\begin{lstlisting}[language=Python]
import time
import torch
import torch.nn as nn
from torch.utils.data import DataLoader
import torchvision

device = torch.device('cuda:0')

class CNN(nn.Module):
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(
            nn.Conv2d(1, 16, 3, 1, 1),
            nn.MaxPool2d(2),
            nn.Conv2d(16, 32, 3, 1, 1),
            nn.MaxPool2d(2),
            nn.Flatten(),
            nn.Linear(32 * 7 * 7, 16),
            nn.ReLU(),
            nn.Linear(16, 10)
        )

    def forward(self, x):
        return self.net(x)

train_data = torchvision.datasets.MNIST(
    root='mnist',
    download=True,
    train=True,
    transform=torchvision.transforms.ToTensor()
)

batch_size = 64
model = CNN().to(device)
train_dataloader = DataLoader(train_data, batch_size=batch_size)
loss_func = nn.CrossEntropyLoss().to(device)
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)
epochs = 10

for epoch in range(epochs):
    for imgs, labels in train_dataloader:
        imgs = imgs.to(device)
        labels = labels.to(device)
        outputs = model(imgs)
        loss = loss_func(outputs, labels)
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()

torch.save({
    'epoch': epochs,
    'arch': CNN,
    'state_dict': model.state_dict(),
    'optimizer': optimizer.state_dict(),
}, 'checkpoint.pth.tar')
\end{lstlisting}

\subsection{启用昇腾算力}\label{ux542fux7528ux6607ux817eux7b97ux529b}

将运行设备切换到NPU，并引入 \passthrough{\lstinline!torch\_npu!}
自动迁移工具。若使用Atlas训练系列（如Atlas
800T），建议开启混合精度；Atlas A2/A3系列可按需求决定。

\begin{lstlisting}[language=Python]
import torch_npu
from torch_npu.npu import amp
from torch_npu.contrib import transfer_to_npu

device = torch.device('npu:0')
transfer_to_npu(model)
\end{lstlisting}

若未启用自动迁移，可参考《PyTorch
训练模型迁移调优指南》的``手工迁移''章节逐一调整算子。

\subsection{配置AMP与GradScaler}\label{ux914dux7f6eampux4e0egradscaler}

在模型与优化器定义完成后，实例化 \passthrough{\lstinline!GradScaler!}
用于自动Loss Scale管理：

\begin{lstlisting}[language=Python]
loss_func = nn.CrossEntropyLoss().to(device)
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)
scaler = amp.GradScaler()
\end{lstlisting}

\subsection{NPU训练主循环}\label{npuux8badux7ec3ux4e3bux5faaux73af}

将原循环替换为包含 \passthrough{\lstinline!amp.autocast()!} 与
\passthrough{\lstinline!GradScaler!}
的版本，实现混合精度训练以及自动unscale。

\begin{lstlisting}[language=Python]
for epoch in range(epochs):
    for imgs, labels in train_dataloader:
        imgs = imgs.to(device)
        labels = labels.to(device)
        with amp.autocast():
            outputs = model(imgs)
            loss = loss_func(outputs, labels)
        optimizer.zero_grad()
        scaler.scale(loss).backward()
        scaler.step(optimizer)
        scaler.update()
\end{lstlisting}

\subsection{启动训练与产出}\label{ux542fux52a8ux8badux7ec3ux4e0eux4ea7ux51fa}

执行 \passthrough{\lstinline!python3 train.py!}
即可启动在昇腾NPU上的训练。生成的
\passthrough{\lstinline!checkpoint.pth.tar!}
权重文件意味着迁移流程完成。Atlas训练系列需要混合精度支持才能充分发挥算力；若在Atlas
A2/A3平台，可根据模型稳定性决定是否启用AMP。

\section{迁移流程概览}\label{ux8fc1ux79fbux6d41ux7a0bux6982ux89c8}

整体流程分三条主线：脚本迁移、环境与启动配置、关键特性适配。实际操作可按``脚本→环境→特性''的顺序逐步验证；若过程中遇到问题，再依序排查即可。以下分别介绍三种迁移方式。

\subsection{自动迁移（推荐）}\label{ux81eaux52a8ux8fc1ux79fbux63a8ux8350}

自动迁移只需在脚本中导入
\passthrough{\lstinline!transfer\_to\_npu!}，运行时会自动把 CUDA
接口替换为 NPU 接口，非常适合快速验证。注意
\passthrough{\lstinline!channel\_last!} 目前尚未适配，可改用
\passthrough{\lstinline!contiguous!}；若脚本在
\passthrough{\lstinline!init\_process\_group!} 后通过字符串判断
\passthrough{\lstinline!nccl!}，需要改写为
\passthrough{\lstinline!hccl!}；\passthrough{\lstinline!torch.jit.script!}
与自动迁移的动态特性冲突，此类脚本建议改用工具迁移。示例：

\begin{lstlisting}[language=Python]
import torch
import torch_npu  # PyTorch<=2.4 时需要显式导入
from torch_npu.contrib import transfer_to_npu
\end{lstlisting}

引入后按常规方式启动训练；能正常打印迭代日志意味着训练链路已迁移成功，能保存权重则表明推理/导出路径也可复用。若仍有
CUDA 接口报错，可结合 PyTorch Analyse 的报告定位未适配的 API。

\subsection{工具迁移}\label{ux5de5ux5177ux8fc1ux79fb}

当代码规模较大或需要生成迁移报告时，可使用
\passthrough{\lstinline!Ascend-cann-toolkit!} 提供的
\passthrough{\lstinline!pytorch\_gpu2npu.sh!}。先根据《CANN
软件安装指南》部署 toolkit，再安装
\passthrough{\lstinline!pandas>=1.2.4!}、\passthrough{\lstinline!libcst!}、\passthrough{\lstinline!prettytable!}、\passthrough{\lstinline!jedi!}
等依赖，进入
\passthrough{\lstinline!ascend-toolkit/latest/tools/ms\_fmk\_transplt/!}
目录执行：

\begin{lstlisting}[language=bash]
./pytorch_gpu2npu.sh -i /home/train -o /home/out -v 2.1.0 [-s] [distributed -m /home/train/train.py -t model]
\end{lstlisting}

\passthrough{\lstinline!-i/-o/-v!} 分别指定输入目录、输出目录与 PyTorch
版本；\passthrough{\lstinline!-s!} 允许通过环境变量
\passthrough{\lstinline!DEVICE\_ID!}
指定设备；\passthrough{\lstinline!distributed!}
可在迁移阶段生成多卡脚本，并要求提供入口脚本
\passthrough{\lstinline!-m!} 与模型变量
\passthrough{\lstinline!-t!}（默认
\passthrough{\lstinline!model!}）。工具会输出转换后的脚本树、日志、算子清单以及
\passthrough{\lstinline!run\_distributed\_npu.sh!}，只需将其中的
\passthrough{\lstinline!please input your shell script here!}
替换成实际训练命令，即可启动多卡作业。

\subsection{手工迁移}\label{ux624bux5de5ux8fc1ux79fb}

对于结构高度定制的脚本，可以选择手工迁移。典型步骤是引入
\passthrough{\lstinline!torch\_npu!}、将设备切换为 NPU、逐步替换 CUDA
API，并在多卡场景下切换通信后端至 HCCL：

\begin{lstlisting}[language=Python]
# 迁移前
device = torch.device('cuda:{}'.format(local_rank))
model.to(device)

# 迁移后
device = torch.device('npu:{}'.format(local_rank))
model.to(device)
\end{lstlisting}

常见替换还包括
\passthrough{\lstinline!torch.cuda.set\_device!}→\passthrough{\lstinline!torch\_npu.npu.set\_device!}、\passthrough{\lstinline!model.cuda()!}→\passthrough{\lstinline!model.npu()!}、\passthrough{\lstinline!tensor.cuda(non\_blocking=True)!}→\passthrough{\lstinline!tensor.npu(non\_blocking=True)!}
等。其余接口可对照《API 参考》或``常见 PyTorch
迁移替换接口''章节逐一处理。

\section{脚本迁移示例：MNIST
CNN}\label{ux811aux672cux8fc1ux79fbux793aux4f8bmnist-cnn-1}

以下示例展示如何把一个 GPU 版 MNIST CNN 脚本迁移到昇腾
NPU，并启用混合精度训练。

\subsection{基准脚本}\label{ux57faux51c6ux811aux672c-1}

\begin{lstlisting}[language=Python]
import time
import torch
import torch.nn as nn
from torch.utils.data import DataLoader
import torchvision

device = torch.device('cuda:0')

class CNN(nn.Module):
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(
            nn.Conv2d(1, 16, 3, 1, 1),
            nn.MaxPool2d(2),
            nn.Conv2d(16, 32, 3, 1, 1),
            nn.MaxPool2d(2),
            nn.Flatten(),
            nn.Linear(32 * 7 * 7, 16),
            nn.ReLU(),
            nn.Linear(16, 10)
        )

    def forward(self, x):
        return self.net(x)

train_data = torchvision.datasets.MNIST(
    root='mnist',
    download=True,
    train=True,
    transform=torchvision.transforms.ToTensor()
)

batch_size = 64
model = CNN().to(device)
train_dataloader = DataLoader(train_data, batch_size=batch_size)
loss_func = nn.CrossEntropyLoss().to(device)
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)
epochs = 10

for epoch in range(epochs):
    for imgs, labels in train_dataloader:
        imgs = imgs.to(device)
        labels = labels.to(device)
        outputs = model(imgs)
        loss = loss_func(outputs, labels)
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()

torch.save({
    'epoch': epochs,
    'arch': CNN,
    'state_dict': model.state_dict(),
    'optimizer': optimizer.state_dict(),
}, 'checkpoint.pth.tar')
\end{lstlisting}

\subsection{启用昇腾算力}\label{ux542fux7528ux6607ux817eux7b97ux529b-1}

在 NPU 脚本中，将设备切换为
\passthrough{\lstinline!torch.device('npu:0')!}，并导入
\passthrough{\lstinline!torch\_npu!}、\passthrough{\lstinline!amp!} 以及
\passthrough{\lstinline!transfer\_to\_npu!}：

\begin{lstlisting}[language=Python]
import torch_npu
from torch_npu.npu import amp
from torch_npu.contrib import transfer_to_npu

device = torch.device('npu:0')
transfer_to_npu(model)
loss_func = nn.CrossEntropyLoss().to(device)
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)
scaler = amp.GradScaler()
\end{lstlisting}

\subsection{混合精度训练循环}\label{ux6df7ux5408ux7cbeux5ea6ux8badux7ec3ux5faaux73af}

\begin{lstlisting}[language=Python]
for epoch in range(epochs):
    for imgs, labels in train_dataloader:
        imgs = imgs.to(device)
        labels = labels.to(device)
        with amp.autocast():
            outputs = model(imgs)
            loss = loss_func(outputs, labels)
        optimizer.zero_grad()
        scaler.scale(loss).backward()
        scaler.step(optimizer)
        scaler.update()
\end{lstlisting}

执行 \passthrough{\lstinline!python3 train.py!} 即可在昇腾 NPU
上完成训练，生成的 \passthrough{\lstinline!checkpoint.pth.tar!}
说明迁移流程已闭环。Atlas 训练系列建议启用混合精度以充分发挥算力；Atlas
A2/A3 则可根据模型稳定性酌情选择。

若出现 coredump，可按以下步骤处理：设置
\passthrough{\lstinline!ulimit -c unlimited!} 以启用 core 文件，使用
\passthrough{\lstinline!sysctl -w kernel.core\_pattern=core-\%e.\%p.\%h.\%t!}
指定命名规则；当进程崩溃后，运行
\passthrough{\lstinline!gdb python3 core.xxx!}，通过
\passthrough{\lstinline!bt!}、\passthrough{\lstinline!info break!}
等命令查看堆栈和断点信息。

\subsection{Hook 定位}\label{hook-ux5b9aux4f4d}

对需要跟踪的模块注册正反向 hook，可迅速锁定出错算子：

\begin{lstlisting}[language=Python]
def hook_func(name, module):
    def hook_function(module, inputs, outputs):
        print(name)
    return hook_function

for name, module in model.named_modules():
    if module is not None:
        module.register_forward_hook(hook_func('[forward]:' + name, module))
        module.register_backward_hook(hook_func('[backward]:' + name, module))
\end{lstlisting}

\section{模型保存}\label{ux6a21ux578bux4fddux5b58}

\passthrough{\lstinline!torch.save(model.state\_dict(), path)!} 可生成
\passthrough{\lstinline!.pth/.pt!}
文件，专注于权重参数，适合在线推理或导出
ONNX；\passthrough{\lstinline!.pth.tar!} 以字典形式同时保存
epoch、损失、模型和优化器状态，便于断点续训。保存前建议创建明确的路径：

\begin{lstlisting}[language=Python]
save_pt_path = "state_dict_model.pt"
torch.save(model.state_dict(), save_pt_path)

checkpoint_path = "checkpoint.pth.tar"
torch.save({
    'epoch': epoch,
    'loss': loss,
    'state_dict': model.state_dict(),
    'optimizer': optimizer.state_dict(),
}, checkpoint_path)
\end{lstlisting}

恢复时记得重新构建模型与优化器，再调用
\passthrough{\lstinline!load\_state\_dict!}，并在推理前执行
\passthrough{\lstinline!model.eval()!} 关闭 Dropout、BatchNorm
的训练分支。

\section{导出 ONNX}\label{ux5bfcux51fa-onnx}

PyTorch 官方 \passthrough{\lstinline!torch.onnx.export!} 接口可将
\passthrough{\lstinline!.pth/.pt!} 或 \passthrough{\lstinline!.pth.tar!}
权重转换为 ONNX，然后使用 ATC 编译为 \passthrough{\lstinline!.om!}
文件以适配昇腾 AI 处理器。导出前请确保已调用
\passthrough{\lstinline!model.eval()!}、构造与训练一致的输入输出形状，并根据需要设置
\passthrough{\lstinline!opset\_version!} 和动态轴：

\begin{lstlisting}[language=Python]
import torch
import torch.onnx

model = ToyModel()
model.load_state_dict(torch.load('state_dict_model.pt', map_location='cuda'), strict=False)
model.eval()
dummy_input = torch.randn(20, 10)

torch.onnx.export(
    model,
    dummy_input,
    "model.onnx",
    input_names=["input"],
    output_names=["output"],
    opset_version=11,
    dynamic_axes={"input": {0: "batch_size"}, "output": {0: "batch_size"}}
)
\end{lstlisting}

若使用 \passthrough{\lstinline!.pth.tar!}，可通过整理
\passthrough{\lstinline!state\_dict!}
的前缀来对齐节点名称，再执行同样的导出流程。编译阶段建议保持与训练一致的
\passthrough{\lstinline!--op\_select\_implmode!} 以避免精度差异。

\section{自定义算子导出提示}\label{ux81eaux5b9aux4e49ux7b97ux5b50ux5bfcux51faux63d0ux793a}

使用 \passthrough{\lstinline!torch\_npu!} 自定义算子时，需要在导出脚本中
\passthrough{\lstinline!import torch\_npu.onnx!} 并确保调用形式为
\passthrough{\lstinline!torch\_npu.xxx!}（而非
\passthrough{\lstinline!torch.xxx!}）。Inplace 或 out
形式的算子需要改为常规版本，例如
\passthrough{\lstinline!torch\_npu.npu\_silu\_(input)!} 可替换为
\passthrough{\lstinline!input = torch\_npu.npu\_silu(input)!}。若模型继承
\passthrough{\lstinline!torch.autograd.Function!}
并带有自定义正反向，需要重新实现或提供
\passthrough{\lstinline!symbolic!}
函数；\passthrough{\lstinline!npu\_conv2d/npu\_conv3d!} 在部分版本会触发
\passthrough{\lstinline!allow\_tf32!}
相关报错，可参考《常见问题》章节的解决方案。

\section{精度调试流程}\label{ux7cbeux5ea6ux8c03ux8bd5ux6d41ux7a0b}

大模型迁移往往受到硬件差异、超参设置和数据质量的共同影响。昇腾 NPU
与主流 AI 处理器在浮点舍入模式（新增 A 模式、O
模式）和计算顺序上存在差异，但实验显示只要训练过程稳定，这些差异对最终收敛影响有限。例如，在
LLaMA2-1B 上人为注入 ±1\% 的无偏误差，1000 步后的 Loss 仍可控；在
LLaMA2-7B 的对比实验中，主流处理器与 NPU 在 8000 步内的 Loss 差异保持在
0.6\% 以内，参数余弦相似度高达 0.965。实际案例也表明：调低学习率、关闭
Dropout 或修复分布式库的同步 Bug，往往即可让 Loss 曲线重新对齐，甚至在
Qwen-1.8B 等模型上获得更好的表现。调试过程可按照``保证训练稳定→比较 Loss
趋势→检查超参→定位算子差异''的顺序推进。
