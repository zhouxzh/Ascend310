PyACL（Python Ascend Computing Language）是 AscendCL（Ascend Computing
Language）的 Python 绑定版本，它提供了一套用于管理昇腾AI处理器的 Python
API 库。相较于 C++ 版本的 ACL，PyACL
大幅降低了开发门槛，允许开发者使用简洁的 Python
代码实现模型推理、媒体数据处理、算子调用等高性能计算任务。本章将依据官方开发范式，系统讲解
PyACL 应用开发的全流程。

\section{快速入门}\label{ux5febux901fux5165ux95e8}

\subsection{概述}\label{ux6982ux8ff0}

PyACL 封装了底层 C++ 接口，主要包含以下模块： * \textbf{acl}:
核心模块，提供初始化、Device 管理、内存管理、模型推理等功能。 *
\textbf{acl.media}: 媒体数据处理（DVPP），包括 JPEG
编解码、视频编解码、VPC（图像处理）。 * \textbf{acl.op}:
单算子调用接口。

\subsection{Hello World: 查询 Device
count}\label{hello-world-ux67e5ux8be2-device-count}

一个最简单的 PyACL 程序，用于查询当前环境可用的 NPU 设备数量。

\begin{lstlisting}[language=Python]
import acl

def check_device_count():
    # 1. ACL 初始化
    ret = acl.init()
    if ret != 0:
        print(f"acl init failed, ret={ret}")
        return

    # 2. 获取 Device 数量
    count, ret = acl.rt.get_device_count()
    if ret != 0:
        print(f"get device count failed, ret={ret}")
    else:
        print(f"Found {count} Ascend devices.")

    # 3. ACL 去初始化
    ret = acl.finalize()
    if ret != 0:
        print(f"acl finalize failed, ret={ret}")

if __name__ == "__main__":
    check_device_count()
\end{lstlisting}

\section{PyACL
初始化与运行时管理}\label{pyacl-ux521dux59cbux5316ux4e0eux8fd0ux884cux65f6ux7ba1ux7406}

\subsection{初始化 (acl.init)}\label{ux521dux59cbux5316-acl.init}

在使用任何 ACL 功能前，必须调用
\passthrough{\lstinline!acl.init(config\_path)!}。即使没有配置文件，也需传入空字符串或指向空
JSON 的路径。

\subsection{运行时三板斧：Device - Context -
Stream}\label{ux8fd0ux884cux65f6ux4e09ux677fux65a7device---context---stream}

这是 PyACL 开发中最重要的基本概念： 1. \textbf{Device}：物理设备（NPU
芯片）。使用前需显式
\passthrough{\lstinline!acl.rt.set\_device(device\_id)!}。 2.
\textbf{Context}：上下文，类似进程空间，管理该 Context
下的所有资源（Stream, Memory,
Model）。\passthrough{\lstinline!set\_device!} 会自动创建默认
Context，也可以显式创建。 3. \textbf{Stream}：执行流，类似 GPU 的
Stream。在同一个 Stream 中的任务是顺序执行的，不同 Stream 间可并行。

\begin{lstlisting}[language=Python]
# 标准资源申请流程
device_id = 0
ret = acl.rt.set_device(device_id) # 隐式创建默认 Context
context, ret = acl.rt.get_context() # 获取当前 Context 句柄
stream, ret = acl.rt.create_stream() # 创建 Stream

# ... 执行业务 ...

# 标准资源释放流程 (必须逆序释放)
acl.rt.destroy_stream(stream)
acl.rt.reset_device(device_id)
# 注意：reset_device 会自动 destroy 默认 context
\end{lstlisting}

\subsection{内存管理 (Host vs
Device)}\label{ux5185ux5b58ux7ba1ux7406-host-vs-device}

昇腾包括 Host（CPU側）和 Device（NPU側）两部分。 *
\passthrough{\lstinline!acl.rt.malloc!}: 申请 Device
侧内存（大部分模型推理输入输出都在这里）。 *
\passthrough{\lstinline!acl.rt.malloc\_host!}: 申请 Host
侧内存（通常是Pinned Memory，便于快速传输）。 *
\passthrough{\lstinline!acl.rt.memcpy!}:
内存拷贝，需指定拷贝方向（Host-\textgreater Host,
Host-\textgreater Device, Device-\textgreater Host,
Device-\textgreater Device）。

\section{模型推理}\label{ux6a21ux578bux63a8ux7406}

模型推理是 PyACL 应用的核心，遵循 \textbf{OM 模型加载 -\textgreater{}
准备 Dataset -\textgreater{} 执行推理 -\textgreater{} 卸载模型} 的流程。

\subsection{加载模型}\label{ux52a0ux8f7dux6a21ux578b}

\begin{lstlisting}[language=Python]
# 加载离线模型 (.om)
model_path = "./model/resnet50.om"
model_id, ret = acl.mdl.load_from_file(model_path) # 返回 model_id 用于后续操作
\end{lstlisting}

\subsection{准备 Dataset
(核心难点)}\label{ux51c6ux5907-dataset-ux6838ux5fc3ux96beux70b9}

ACL 设计了一套通用的数据结构来描述模型的输入输出： *
\textbf{aclmdlDesc}:
模型描述，可查询输入输出的个数、Shape、Format、大小。 *
\textbf{aclmdlDataset}: 存放多个输入/输出 Tensor 的集合。 *
\textbf{aclDataBuffer}: 存放单个 Tensor 的数据的 Buffer 地址和大小。

\begin{lstlisting}[language=Python]
# 1. 根据 model_id 获取模型描述
model_desc = acl.mdl.create_desc()
ret = acl.mdl.get_desc(model_desc, model_id)

# 2. 准备输入数据集 (假设模型只有1个输入)
input_dataset = acl.mdl.create_dataset()
# 申请 Device 内存存放输入数据
input_size = acl.mdl.get_input_size_by_index(model_desc, 0)
input_dev_ptr, ret = acl.rt.malloc(input_size, 2) # 2=ACL_MEM_MALLOC_NORMAL_ONLY

# 将申请的内存封装为 DataBuffer 并加入 Dataset
input_data_buffer = acl.create_data_buffer(input_dev_ptr, input_size)
acl.mdl.add_dataset_buffer(input_dataset, input_data_buffer)

# 3. 准备输出数据集 (与输入类似，申请内存接收结果)
output_dataset = acl.mdl.create_dataset()
output_size = acl.mdl.get_output_size_by_index(model_desc, 0)
output_dev_ptr, ret = acl.rt.malloc(output_size, 2)
output_data_buffer = acl.create_data_buffer(output_dev_ptr, output_size)
acl.mdl.add_dataset_buffer(output_dataset, output_data_buffer)
\end{lstlisting}

\subsection{执行推理}\label{ux6267ux884cux63a8ux7406}

\begin{lstlisting}[language=Python]
# 执行同步推理
ret = acl.mdl.execute(model_id, input_dataset, output_dataset)
\end{lstlisting}

推理完成后，结果数据位于 \passthrough{\lstinline!output\_dev\_ptr!}
指向的 Device 内存中，需通过 \passthrough{\lstinline!acl.rt.memcpy!}
拷贝回 Host 进行后处理。

\section{DVPP
图像/视频处理}\label{dvpp-ux56feux50cfux89c6ux9891ux5904ux7406}

DVPP（Digital Vision
Pre-Processing）是昇腾处理器的硬件加速引擎，用于处理 JPEG
解码、缩放、抠图等，速度远超 CPU。

\subsection{JPEGD (JPEG Decode)}\label{jpegd-jpeg-decode}

将 \passthrough{\lstinline!.jpg!} 数据解码为 YUV 格式。

\begin{lstlisting}[language=Python]
# 1. 创建图片描述信息
channel_desc = acl.media.dvpp_create_channel_desc()
acl.media.dvpp_create_channel(channel_desc)

# 2. 准备输入内存 (Host -> Device)
# 假设 np_jpg_data 是读取的二进制 jpg 数据
input_dev, _ = acl.media.dvpp_malloc(len(np_jpg_data))
acl.rt.memcpy(input_dev, len(np_jpg_data), np_jpg_data_ptr, len(np_jpg_data), 1) # 1=Host2Device

# 3. 预测解码后大小并申请输出内存
output_desc = acl.media.dvpp_create_jped_config()
output_size, _ = acl.media.dvpp_jpeg_predict_dec_size(np_jpg_data_ptr, len(np_jpg_data), output_desc)
output_dev, _ = acl.media.dvpp_malloc(output_size)

# 4. 执行异步解码
acl.media.dvpp_jpeg_decode_async(channel_desc, input_dev, len(np_jpg_data), output_dev, output_size, output_desc, stream)
acl.rt.synchronize_stream(stream) # 等待完成
\end{lstlisting}

\subsection{VPC (Vision Preprocessing
Core)}\label{vpc-vision-preprocessing-core}

处理 Resize、Crop、Padding 等。输入必须是 Device 侧的 YUV 数据。
关键步骤：创建 \passthrough{\lstinline!acldvppPicDesc!}
描述输入和输出图片的格式、宽高、Stride，然后调用
\passthrough{\lstinline!acl.media.dvpp\_vpc\_resize\_async!}。

\section{单算子调用}\label{ux5355ux7b97ux5b50ux8c03ux7528}

如果不加载整个模型，仅需调用某个特定算子（如 Softmax, MatMul）： 1.
\textbf{acl.op.set\_attr}: 设置算子属性。 2.
\textbf{acl.op.execute\_v2}: 执行算子。
需注意，算子名称和输入输出格式必须与 CANN 算子库定义一致。

\begin{itemize}
\tightlist
\item
  \textbf{Profiling}: 通过 \passthrough{\lstinline!acl.prof!}

\section{应用调试与常见
FAQ}\label{ux5e94ux7528ux8c03ux8bd5ux4e0eux5e38ux89c1-faq}

\subsection{调试技巧}\label{ux8c03ux8bd5ux6280ux5de7}

\begin{itemize}
\tightlist
\item
  \textbf{返回值检查}：所有 ACL 接口均返回 \passthrough{\lstinline!ret!}
  状态码，\passthrough{\lstinline!0!} 表示成功。非 0
  需查阅《错误码参考》。
\item
  \textbf{日志获取}：设置环境变量
  \passthrough{\lstinline!export ASCEND\_GLOBAL\_LOG\_LEVEL=1!} (Info
  级别) 查看详细日志，日志默认位置在
  \passthrough{\lstinline!\~/ascend/log/!}。
\end{itemize}

\subsection{FAQ}\label{faq}

\begin{itemize}
\tightlist
\item
  \textbf{Q: 为什么 \passthrough{\lstinline!acl.mdl.execute!} 报错
  ``Memory Check Failed''?}

  \begin{itemize}
  \tightlist
  \item
    A: 检查
    \passthrough{\lstinline!acl.mdl.get\_input\_size\_by\_index!}
    获取的大小是否与你 \passthrough{\lstinline!acl.rt.malloc!}
    的大小严格一致。
  \end{itemize}
\item
  \textbf{Q: DVPP 解码后的图片看起来是花的？}

  \begin{itemize}
  \tightlist
  \item
    A: DVPP 输出通常有宽/高对齐要求（如 128x16
    对齐）。读取数据时需要根据 \passthrough{\lstinline!stride!} 跳过
    Padding 数据，而不能简单按 \passthrough{\lstinline!width * height!}
    读取。
  \end{itemize}
\end{itemize}

\section{使用约束}\label{ux4f7fux7528ux7ea6ux675f}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \textbf{Context 线程安全}：一个 Context
  可以在多个线程中使用，但需用户保证并发安全。推荐一线程一 Context。
\item
  \textbf{Stream 约束}：Stream
  上的任务按顺序执行，但异步接口下发后需显式
  \passthrough{\lstinline!synchronize!} 才能确保数据就绪。
\item
  \textbf{内存对齐}：DVPP 对内存地址和图片尺寸有严格对齐要求。
\end{enumerate}
