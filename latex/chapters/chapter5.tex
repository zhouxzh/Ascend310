\section{张量、数据类型与设备上下文}\label{src-book-chapter5-h9}

MindSpore 的核心数据结构是 \passthrough{\lstinline!Tensor!}。它和 NumPy
数组的差别不在于``能不能存数据''，而在于\textbf{数据放在哪里、图如何追踪它}。设备上下文由
\passthrough{\lstinline!set\_context!}
设定，\textbf{必须在创建张量之前调用}：

\begin{lstlisting}[language=Python]
import mindspore as ms
from mindspore import Tensor, ops

ms.set_context(mode=ms.PYNATIVE_MODE, device_target="Ascend", device_id=0)

a = Tensor([[1.0, 2.0], [3.0, 4.0]], ms.float16)
print(ops.matmul(a, a).asnumpy())
\end{lstlisting}

这段代码能通过，不是因为``矩阵乘在 310B 上一定能跑''，而是因为 dtype 是
\passthrough{\lstinline!fp16!}。把 dtype 换成
\passthrough{\lstinline!ms.float32!}，同一行在本板上会被拒绝：

\passthrough{\lstinline!value.shape!}
而不读数值时，\passthrough{\lstinline!fp32!} 的
\passthrough{\lstinline!nn.Dense!} 前向与
\passthrough{\lstinline!ops.matmul!} 各有 \passthrough{\lstinline!2/2!}
次``通过''；加上 \passthrough{\lstinline!.asnumpy()!}
把结果搬回主机后，同样两条路径各 \passthrough{\lstinline!2/2!}
次失败并给出
\passthrough{\lstinline!EZ1001!}。打印形状不需要设备物化计算结果，而
\passthrough{\lstinline!.asnumpy()!}
必须完成这次同步。因此``某个算子在板上能跑''必须以\textbf{取回的实际数值}为依据。

其余要点：

\begin{itemize}
\tightlist
\item
  \passthrough{\lstinline!Tensor!} 的 dtype
  显式给出，比依赖字面量推断更可靠；本板上
  \passthrough{\lstinline!fp32!} 与 \passthrough{\lstinline!fp16!}
  的差别不是精度取舍，而是能否执行；
\item
  \passthrough{\lstinline!.asnumpy()!}
  会触发设备到主机的同步拷贝，\textbf{不要放在性能敏感的循环里}，但它是唯一能证明算子真正执行的方式；
\item
  逐元素算子（如 \passthrough{\lstinline!add!}）与矩阵算子的 dtype
  支持范围不同，不要用一个算子的通过结果推断另一个算子。
\end{itemize}

\passthrough{\lstinline!Parameter!}
是会被优化器更新的张量，\passthrough{\lstinline!Tensor!}
默认不是。这个区分在第 5.8
节训练循环中会直接影响``为什么梯度算了但权重没变''。

\section{用 Cell 与 ops 构建网络}\label{src-book-chapter5-h10}

\subsection{最小可运行的网络定义}\label{src-book-chapter5-h11}

\passthrough{\lstinline!nn.Cell!} 相当于 PyTorch 的
\passthrough{\lstinline!nn.Module!}：用
\passthrough{\lstinline!\_\_init\_\_!} 声明子模块，用
\passthrough{\lstinline!construct!} 定义前向计算。下面这个网络在本板上是
\passthrough{\lstinline!observed-pass!}：

\begin{lstlisting}[language=Python]
import numpy as np
import mindspore as ms
from mindspore import Tensor, nn, ops


class Fp16Linear(nn.Cell):
    """本板可用的最小线性层：显式 fp16 参数，矩阵乘走 ops.matmul。"""

    def __init__(self, in_dim: int, out_dim: int, seed: int = 0):
        super().__init__()
        rng = np.random.default_rng(seed)
        weight = rng.normal(scale=0.1, size=(in_dim, out_dim)).astype(np.float16)
        self.weight = ms.Parameter(Tensor(weight, ms.float16), name="weight")
        self.bias = ms.Parameter(Tensor(np.zeros((out_dim,), np.float16), ms.float16), name="bias")

    def construct(self, x):
        return ops.matmul(x, self.weight) + self.bias


net = nn.SequentialCell([Fp16Linear(4, 8, seed=1), nn.ReLU(), Fp16Linear(8, 1, seed=2)])
output = net(Tensor(np.ones((1, 4), np.float16), ms.float16))
print(output.shape, output.asnumpy())
\end{lstlisting}

\subsection{什么时候用 ops，什么时候用
Cell}\label{src-book-chapter5-h12}

\passthrough{\lstinline!ops!}
是不可训练的函数式算子，\passthrough{\lstinline!Cell!}
是可持有参数、可组合的模块。经验规则：

\begin{itemize}
\tightlist
\item
  无参数、纯计算（激活、矩阵乘、归一化函数）用
  \passthrough{\lstinline!ops!}；
\item
  有参数、需要被优化器发现（\passthrough{\lstinline!Dense!}、\passthrough{\lstinline!Conv2d!}、自定义带权重层）用
  \passthrough{\lstinline!Cell!} 子类。
\end{itemize}

自定义算子属于第 7 章的内容。本章只强调边界：\textbf{图模式下 Python
的控制流和副作用不会按普通脚本执行}，所以不要把``打印调试信息''当成确认算子执行顺序的手段。

\section{数据集与预处理}\label{src-book-chapter5-h13}

\subsection{GeneratorDataset 的组织方式}\label{src-book-chapter5-h14}

MindSpore 的数据管道由 \passthrough{\lstinline!Dataset!}
对象组合而成。一个可复现的最小例子是：先用 Python
生成器描述单样本，再映射出规范化后的样本，最后批处理。

\begin{lstlisting}[language=Python]
import numpy as np
from mindspore.dataset import GeneratorDataset


def gen():
    rng = np.random.default_rng(0)
    for _ in range(64):
        vector = rng.normal(size=(4,)).astype(np.float32)
        yield vector, np.asarray([vector.sum()], dtype=np.float32)


def normalize(vector):
    return ((vector - np.float32(0.5)) / np.float32(2.0)).astype(np.float32)


dataset = (
    GeneratorDataset(gen(), column_names=["x", "y"], num_parallel_workers=1)
    .map(
        operations=normalize,
        input_columns=["x"],
        output_columns=["x"],
        num_parallel_workers=1,
        python_multiprocessing=False,
    )
    .batch(8, drop_remainder=True)
)
\end{lstlisting}

\passthrough{\lstinline!samples/chapter5/03\_dataset\_pipeline.py!}
用这段结构实测：\passthrough{\lstinline!64!}
个样本、\passthrough{\lstinline!batch\_size=8!} 得到
\passthrough{\lstinline!8!} 个批次，批形状
\passthrough{\lstinline![8, 4]!}，同一随机种子重建后首批数据完全一致（\passthrough{\lstinline!observed-pass!}）。

要点：

\begin{itemize}
\tightlist
\item
  随机源显式固定（\passthrough{\lstinline!default\_rng(0)!}），否则两次实验的
  loss 曲线不可比较；
\item
  \passthrough{\lstinline!map!} 里返回的必须是\textbf{显式 dtype 的
  numpy 数组或
  \passthrough{\lstinline!Tensor!}}，标量要包成单元素数组。返回未定型的标量会得到
  \passthrough{\lstinline!Failed to create tensor from numpy array, data type is unknown!}，这个错误来自数据管道而不是设备侧；
\item
  \passthrough{\lstinline!map!}
  中的函数在数据管道进程/线程中执行，\textbf{不要在里面访问设备上下文}；
\item
  \passthrough{\lstinline!batch!}
  之后张量形状固定，这对静态图编译很重要。
\end{itemize}

\subsection{数据管道与设备内存的关系}\label{src-book-chapter5-h15}

数据预处理放在主机侧还是设备侧，会改变吞吐而不改变正确性。判断顺序是：

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  先确认数据读取不是瓶颈（否则优化算子没有意义）；
\item
  再确认预处理是否占满 CPU；
\item
  最后才考虑把 resize、归一化下沉到 AIPP/DVPP------这条路径在第 6 章和第
  8 章展开。
\end{enumerate}

在没有测量前不要假设``预处理一定慢''。第 8
章的全部优化方法都建立在先测量之上。

\subsection{把函数编译成图}\label{src-book-chapter5-h18}

\passthrough{\lstinline!ms.jit!} 可以把单个函数编译成可复用的图：

\begin{lstlisting}[language=Python]

@ms.jit
def scaled_add(a, b, scale: float = 2.0):
    return (a + b) * scale
\end{lstlisting}

图模式下有三个必须遵守的约束：

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \textbf{不要依赖 Python 副作用}（修改全局列表、打印计数）来观察执行；
\item
  \textbf{避免随输入变化的结构}（在 \passthrough{\lstinline!if!}
  中依据张量值改变网络结构）；
\item
  \textbf{shape 尽量稳定}，动态 shape 会给图编译带来额外成本。
\end{enumerate}

违反这些约束的表现通常不是清晰的报错，而是``结果和 PyNative
不一致''。因此 PyNative 与 Graph 的结果对比应当作为固定验证项。

\passthrough{\lstinline!outputs/04\_graph\_mode\_pynative.json!} 与
\passthrough{\lstinline!outputs/04\_graph\_mode\_graph.json!}。

\passthrough{\lstinline!Mindspore can not compile temporary source code in terminal!}，所以凡涉及
\passthrough{\lstinline!@ms.jit!} 的验证都要先落成文件再运行。

\section{自动微分、优化器与训练循环}\label{src-book-chapter5-h19}

\subsection{损失函数与梯度函数}\label{src-book-chapter5-h20}

MindSpore 的函数式微分接口是
\passthrough{\lstinline!value\_and\_grad!}：给定前向函数，返回（损失值，梯度）。

\begin{lstlisting}[language=Python]
import mindspore as ms
from mindspore import ops


def make_grad_fn(net):
    def forward_fn(data, target):
        return ops.mse_loss(net(data), target)

    # grad_position=None：不对输入求梯度
    # weights=net.trainable_params()：明确指定要被更新的参数
    return ms.value_and_grad(forward_fn, None, net.trainable_params())


loss, grads = make_grad_fn(net)(x, y)
optimizer(grads)
\end{lstlisting}

上面这种 \passthrough{\lstinline!grad\_position=None!} +
\passthrough{\lstinline!weights=net.trainable\_params()!}
的写法是样例实际验证过的形式：前者表示不返回对输入的梯度，后者明确告诉框架要更新哪些参数。参数列表写错不会立刻报错，只会表现为``梯度算了但权重没变''，所以训练之后一定要检查
loss 是否真的下降。

\subsection{一个完整的训练骨架}\label{src-book-chapter5-h21}

\begin{lstlisting}[language=Python]
import mindspore as ms
from mindspore import nn, ops, value_and_grad


def build():
    model = MLP(in_dim=4, hidden=16, out_dim=1)
    optimizer = nn.Adam(model.trainable_params(), learning_rate=1e-2)
    return model, optimizer


def forward_fn(model, x, y):
    return ops.mse_loss(model(x), y)


def run(dataset, epochs: int = 5):
    model, optimizer = build()
    grad_fn = value_and_grad(forward_fn)
    model.set_train(True)
    for epoch in range(epochs):
        total, steps = 0.0, 0
        for x, y in dataset.create_dict_iterator():
            loss, grads = grad_fn(model, x, y)
            optimizer(grads)
            total += float(loss.asnumpy())
            steps += 1
        print(f"epoch {epoch}: loss={total / max(steps, 1):.6f}")
    return model
\end{lstlisting}

需要记住的三点：

\begin{itemize}
\tightlist
\item
  \passthrough{\lstinline!model.set\_train(True)!} 与
  \passthrough{\lstinline!model.set\_train(False)!} 会切换
  dropout、batch norm 等层的行为，\textbf{推理前必须显式关闭}；
\item
  \passthrough{\lstinline!model.trainable\_params()!}
  决定优化器能看到哪些参数，漏掉的层不会更新；
\item
  每次取 loss 都用 \passthrough{\lstinline!.asnumpy()!}
  会引入设备同步，训练循环里建议按 step 累积后统一取出。
\end{itemize}

\passthrough{\lstinline!samples/chapter5/05\_autograd\_train.py!} 用
\passthrough{\lstinline!Fp16Linear!} + \passthrough{\lstinline!nn.Adam!}
跑固定种子的合成线性回归，不需要下载任何权重：

\begin{lstlisting}[language=bash]

本板三轮实测的 loss 都从 \passthrough{\lstinline!4.644531!} 降到约

步耗时分别为

fp16}，不要先写完标准 fp32 训练脚本再指望它跑通。

\begin{enumerate}

\item

\section{MindNLP 与大模型加载}\label{src-book-chapter5-h28}

\subsection{MindNLP 的定位}\label{src-book-chapter5-h29}

MindNLP 在 MindSpore 之上提供 Transformer
类模型实现、分词器和权重加载器。工程上有两个直接后果：

\begin{itemize}
\tightlist
\item
  \textbf{模型能否加载取决于 MindNLP 版本的 loader
  覆盖范围}。某个新模型架构没有对应 loader
  时，这不是硬件问题，而是软件覆盖问题；
\item
  权重来源（Hugging Face Safetensors、Modelers
  等）会带来不同的可复现性要求，例如 revision 能否固定、哈希能否锁定。
\end{itemize}

\section{小结}\label{src-book-chapter5-h35}

本章的核心结论可以压缩成八句话：

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  MindSpore 处在 CANN 之上、用户代码之下，它把算子图交给 CANN
  图引擎与运行时执行；
\item
  全量 MindSpore 与 MindSpore Lite 是两个独立运行时，版本与 ABI
  不可混用；
\item
  网络用 \passthrough{\lstinline!nn.Cell!} 与
  \passthrough{\lstinline!construct!} 定义，训练用
  \passthrough{\lstinline!value\_and\_grad!}
  与优化器组织；本板可用路径是\textbf{显式 fp16
  参数与输入}，\passthrough{\lstinline!nn.Dense!} 的 fp32
  前向与梯度路径被 \passthrough{\lstinline!EZ1001!} 拒绝；
\item
  \passthrough{\lstinline!.asnumpy()!} 既是同步点，也是执行证据：只报
  shape 会在本板上产生假阳性；
\item
  CKPT 用于继续训练，MindIR
  用于交付，两者都要留存哈希与对齐结果（本板实测 CKPT
  \passthrough{\lstinline!60!} 字节、对齐误差
  \passthrough{\lstinline!0.0!}，MindIR \passthrough{\lstinline!2796!}
  字节）；
\item
  Lite \passthrough{\lstinline!2.2.11!} 只支持 MindIR version
  \passthrough{\lstinline!1!}，而 MindSpore
  \passthrough{\lstinline!2.4.10!} 导出 version
  \passthrough{\lstinline!2!}，端侧推理当前阻断在格式版本层，\textbf{这不是对
  310B 硬件的否定}；
\item
  MindNLP 决定大模型能否加载，其 loader
  覆盖范围随版本变化，缺失属于软件边界；
\item
  所有板端结论必须带硬件档位、版本组合与证据等级，\passthrough{\lstinline!blocked!}
  不等于 \passthrough{\lstinline!unsupported!}。
\end{enumerate}

\section{实践任务}\label{src-book-chapter5-h36}

  版本，整理成一页环境记录。
\item

  \passthrough{\lstinline!01\_tensor\_ops.py!}，然后把矩阵乘的 dtype 从
  \passthrough{\lstinline!fp16!} 改成

  shape''和``\passthrough{\lstinline!.asnumpy()!}
  取数值''两种方式判断，记录两次结论的差异。
\item

  里的 \passthrough{\lstinline!Fp16Linear!} 搭一个二分类模型，在
  PyNative 与 Graph 模式下各训练一次，比较 loss 曲线是否一致。
\item
  \textbf{数据处理}：在
  \passthrough{\lstinline!03\_dataset\_pipeline.py!} 的
  \passthrough{\lstinline!map!} 里故意返回一个未定型的 numpy
  标量，确认错误发生在数据管道阶段而不是图执行阶段，然后改回显式 dtype。
\item
  \textbf{训练与导出}：运行
  \passthrough{\lstinline!05\_autograd\_train.py!} 与
  \passthrough{\lstinline!06\_checkpoint\_mindir.py!}，记录 loss
  起止值、耗时、文件字节数与 SHA-256，并做一次重新加载后的数值对齐。

  \textbf{边界记录}：运行
  \passthrough{\lstinline!07\_lite\_inference.py!}，把 CPU 与 Ascend

完成这些任务后，读者应能独立判断一次 MindSpore
失败发生在软件的哪一层，并按第 5.12 节的格式留下可复现的证据。
