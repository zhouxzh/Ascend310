\section{项目简介}\label{ux9879ux76eeux7b80ux4ecb}

本案例在昇腾 310B 上实现实时手势识别。系统从 USB 摄像头读取视频，使用
HaGRID YOLOv10 模型在 NPU 上完成目标检测，把检测框和标签绘制到原始画面，
再使用 H.264/WebRTC 将结果发送到浏览器。

案例代码位于 \passthrough{\lstinline!samples/case8!}。其中
\passthrough{\lstinline!hagrid\_yolo!} 保存模型预处理、推理后端
和后处理，\passthrough{\lstinline!webrtc\_app!} 保存摄像头、DVPP 和 CANN
VENC 适配，\passthrough{\lstinline!scripts!} 保存 模型转换、OM 推理和
WebRTC 服务入口，\passthrough{\lstinline!web!} 保存浏览器页面。

\section{摄像头权限}\label{ux6444ux50cfux5934ux6743ux9650}

官方昇腾 310B 系统通常将摄像头设备设置为
\passthrough{\lstinline!root:video!}、\passthrough{\lstinline!0660!}。如果使用
\passthrough{\lstinline!HwHiAiUser!} 启动 case8，该用户必须属于
\passthrough{\lstinline!video!} 组，否则 WebRTC 会报告
\passthrough{\lstinline!Cannot open video source: /dev/video0!}，即使设备列表中能看到
\passthrough{\lstinline!/dev/video0!}。

使用 root 或具有用户管理权限的账户执行：

\begin{lstlisting}[language=bash]
sudo usermod -aG video HwHiAiUser
\end{lstlisting}

执行后退出当前 SSH 会话并重新登录。官方 Atlas 开发板的实际验证还要求随后
拔下并重新插入 USB 摄像头，使 UVC
设备重新初始化；否则即使用户组已经更新，
旧设备会话也可能导致首帧等待超时。重新插拔后再检查：

\begin{lstlisting}[language=bash]
id HwHiAiUser
ls -l /dev/video0 /dev/video1
\end{lstlisting}

\passthrough{\lstinline!id!} 输出中应包含
\passthrough{\lstinline!video!}。\passthrough{\lstinline!/dev/video0!}
通常是真实的视频采集节点， \passthrough{\lstinline!/dev/video1!} 可能是
UVC metadata 节点，case8 应使用
\passthrough{\lstinline!/dev/video0!}。不要 使用
\passthrough{\lstinline!chmod 666!} 代替用户组配置。

\section{系统流程}\label{ux7cfbux7edfux6d41ux7a0b}

\begin{lstlisting}
flowchart LR
    accTitle: 实时手势识别流程
    accDescr: 摄像头图像经过预处理和 OM 推理，检测结果绘制回原图后编码为 H.264，通过 WebRTC 发送到浏览器。
    cam[USB 摄像头] --> pre[预处理]
    pre --> om[ACL 加载 OM]
    om --> post[后处理与绘制]
    post --> enc[CANN VENC 或显式选择的 CPU 编码]
    enc --> rtc[WebRTC]
    rtc --> browser[浏览器]
\end{lstlisting}

原始画面可以是 1280x720 等采集尺寸，但模型输入固定为静态
\passthrough{\lstinline!1x3x640x640!}。程序使用 letterbox
保持宽高比，再转成 RGB、NCHW 和
归一化张量。推理输出经过置信度过滤、坐标恢复和 NMS 后绘制回原图。

\section{模型与数据集}\label{ux6a21ux578bux4e0eux6570ux636eux96c6}

本案例使用 HaGRID 提供的 YOLOv10 手势检测权重，不在开发板上训练模型。
导出脚本同时生成 ONNX、标签文件和元数据；ATC 在目标 Ascend 310B 上生成
OM。模型输入尺寸、输入名称和类别顺序以元数据及 OM 描述为准，不能在网页
中动态修改模型输入尺寸。

模型导出示例：

\begin{lstlisting}[language=bash]
cd samples/case8
python weights/export_yolo_to_onnx.py \
  --weights weights/YOLOv10n_gestures.pt \
  --output-dir models --imgsz 640 --batch 1 --opset 13 --device cpu
\end{lstlisting}

开发板转换示例：

\begin{lstlisting}[language=bash]
cd /home/HwHiAiUser/Documents/case8
source /usr/local/Ascend/ascend-toolkit/set_env.sh
SOC_VERSION=Ascend310B4 bash scripts/atc_convert.sh
\end{lstlisting}

\section{OM 推理}\label{om-ux63a8ux7406}

模型转换成功后，先执行不接摄像头的 benchmark：

\begin{lstlisting}[language=bash]
python scripts/infer_om_camera.py \
  --benchmark-runs 20 --warmup-runs 5 --print-model-info
\end{lstlisting}

再执行摄像头推理：

\begin{lstlisting}[language=bash]
python scripts/infer_om_camera.py \
  --source /dev/video0 --camera-width 1280 --camera-height 720 \
  --camera-fps 30 --max-frames 60 --no-window
\end{lstlisting}

benchmark 只验证 ACL 能够加载和执行 OM；摄像头测试还会验证采集、预处理、
后处理和资源释放。两者都通过后再进入 WebRTC 测试。

\section{WebRTC 推流}\label{webrtc-ux63a8ux6d41}

启动服务：

\begin{lstlisting}[language=bash]
python scripts/webrtc_om_app.py
\end{lstlisting}

浏览器访问开发板打印的局域网地址，默认是
\passthrough{\lstinline!http://192.168.1.100:8080!}。 服务通过
\passthrough{\lstinline!/models!} 列出 OM，通过
\passthrough{\lstinline!/offer!} 完成 SDP 协商，通过
\passthrough{\lstinline!/stats!} 提供 采集、推理和编码状态。

网页的编码器选项有两个：

\begin{itemize}
\tightlist
\item
  \passthrough{\lstinline!CANN VENC!}：推理仍在 NPU，H.264 使用 Ascend
  VENC；通道创建或编码失败 时明确报错并停止，不自动切换 CPU。
\item
  \passthrough{\lstinline!CPU libx264!}：仅在用户明确选择时使用 CPU
  编码，OM 推理仍在 NPU。
\end{itemize}

因此 CPU 编码可以作为明确的对照路径，但不能作为 CANN VENC 失败后的隐藏
回退。

\section{验收顺序}\label{ux9a8cux6536ux987aux5e8f}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  检查 CANN 环境和 \passthrough{\lstinline!import acl!}。
\item
  运行 OM benchmark。
\item
  运行有限帧摄像头推理。
\item
  检查摄像头实际 MJPG/FourCC 和帧率。
\item
  启动 WebRTC，选择 CANN VENC，确认浏览器持续收到 H.264。
\item
  若 VENC 失败，保存错误码和设备日志，不用 CPU 结果替代硬件验收。
\end{enumerate}

香橙派 8T 的系统版本差异会影响 VENC。当前已验证的旧系统、新系统和
\passthrough{\lstinline!iommu\_map failed -34!} 证据集中记录在
\passthrough{\lstinline!samples/case8/docs/05-known-issues-and-version-compatibility.md!}。
