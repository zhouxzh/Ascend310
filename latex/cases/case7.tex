\section{1. 项目简介}\label{ux9879ux76eeux7b80ux4ecb}

本项目基于昇腾 310B 平台，构建一个智能照片管理和检索系统。系统使用
\textbf{ResNet50} 卷积神经网络提取每张照片的 2048 维视觉特征向量，通过
\textbf{FAISS} 向量检索引擎实现毫秒级的相似图片搜索，利用
\textbf{OpenCV} 进行人 脸计数实现按人物筛选。

与案例1（人脸识别）的实时摄像头推理不同，本项目是书中第一个演示\textbf{批量
离线索引 + 在线检索}模式的案例，帮助读者理解 NPU 如何在''先算后查''的
场景中发挥作用。

\subsection{三个核心功能}\label{ux4e09ux4e2aux6838ux5fc3ux529fux80fd}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \textbf{照片浏览}：按''全部 / 有人脸 / 无人脸''筛选照片库
\item
  \textbf{相似搜索}：上传一张照片，找出视觉上最相似的 12 张
\item
  \textbf{批量索引}：一键扫描照片文件夹，提取特征向量，构建 FAISS 索引
\end{enumerate}

\subsection{2.3.
图像特征提取原理}\label{ux56feux50cfux7279ux5f81ux63d0ux53d6ux539fux7406}

\subsubsection{什么是图像特征向量}\label{ux4ec0ux4e48ux662fux56feux50cfux7279ux5f81ux5411ux91cf}

要让计算机判断两张照片是否''相似''，不能直接比较像素------同一物体在不同光
照、角度、背景下，像素值完全不同。正确的做法是：用一个训练好的深度神经
网络将每张图像映射为一个固定长度的\textbf{特征向量（Embedding）}，使得语义
相似的图像在向量空间中距离很近。

\begin{lstlisting}
照片 A (海滩日落)  →  ResNet50  →  [0.12, -0.34, 0.78, ..., 0.05]  (2048-dim)
照片 B (海边黄昏)  →  ResNet50  →  [0.11, -0.32, 0.80, ..., 0.04]  (2048-dim)
                                               ↓
                                    余弦相似度 ≈ 0.95  (高度相似!)

照片 C (会议室)    →  ResNet50  →  [-0.45, 0.67, -0.12, ..., 0.33]  (2048-dim)
                                               ↓
                              与 A 的余弦相似度 ≈ 0.12  (不相似)
\end{lstlisting}

\subsubsection{为什么选择
ResNet50}\label{ux4e3aux4ec0ux4e48ux9009ux62e9-resnet50}

昇腾 310B NPU 最适合运行固定输入输出形状的卷积神经网络。ResNet50 是计
算机视觉领域最经典的特征提取骨干网络之一：

{ % do not increment counter
\begin{longtable}[]{@{}lllll@{}}
\toprule\noalign{}
模型 & 特征维度 & 模型大小 (OM) & NPU 推理 & 备注 \\
\midrule\noalign{}
\endhead
\bottomrule\noalign{}
\endlastfoot
\textbf{ResNet50} & 2048-dim & \textasciitilde95 MB & \textasciitilde8ms
& 推荐，torchvision 内置 \\
MobileNetV3-Small & 576-dim & \textasciitilde10 MB & \textasciitilde5ms
& 案例8已使用，维度较低 \\
EfficientNet-B0 & 1280-dim & \textasciitilde20 MB & \textasciitilde10ms
& 也可用 \\
CLIP ViT-B/32 & 512-dim & \textasciitilde350 MB & △ & Transformer，OM
转换复杂 \\
\end{longtable}
}

选择 ResNet50 的理由：

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \textbf{零外部下载}：\passthrough{\lstinline!torchvision.models.resnet50(weights=...)!}
  自动从 PyTorch CDN 获取权重，无需维护第三方模型下载链接
\item
  \textbf{经典可迁移}：ResNet
  是计算机视觉的''标准答案''，``去掉分类头得到特
  征向量''的模式适用于几乎所有 CNN 骨干网络
\item
  \textbf{维度适中}：2048
  维特征向量在表达能力（越高越好）和存储开销（越低
  越好）之间取得平衡------10,000 张照片的索引仅占 \textasciitilde80 MB
\item
  \textbf{与案例8差异化}：案例8使用 MobileNetV3-Small
  做手势分类，本案使用 ResNet50
  做特征提取------不同的模型、不同的任务类型
\end{enumerate}

\subsubsection{去掉分类头：分类模型 →
特征提取器}\label{ux53bbux6389ux5206ux7c7bux5934ux5206ux7c7bux6a21ux578b-ux7279ux5f81ux63d0ux53d6ux5668}

torchvision 的 \passthrough{\lstinline!resnet50!} 默认输出 1000
类的分类概率。我们只需要图像的
``语义表示''，不需要分类结果。做法是将最后一层
\passthrough{\lstinline!fc!}（全连接层）替换为
\passthrough{\lstinline!nn.Identity()!}（恒等映射）：

\begin{lstlisting}[language=Python]
import torchvision.models as models

model = models.resnet50(weights=models.ResNet50_Weights.IMAGENET1K_V1)
model.fc = torch.nn.Identity()  # 去掉分类头 → 输出 2048-dim 特征向量
model.eval()
\end{lstlisting}

这样模型输入 \passthrough{\lstinline!(1, 3, 224, 224)!} 的图像张量，输出
\passthrough{\lstinline!(1, 2048)!} 的特征 向量，而不是
\passthrough{\lstinline!(1, 1000)!} 的类别概率。

\subsubsection{L2
归一化：让内积等于余弦相似度}\label{l2-ux5f52ux4e00ux5316ux8ba9ux5185ux79efux7b49ux4e8eux4f59ux5f26ux76f8ux4f3cux5ea6}

FAISS 的
\passthrough{\lstinline!IndexFlatIP!}（内积索引）计算的是向量点积。为了让点积等价于余
弦相似度，需要先将所有特征向量做 L2 归一化（模长为 1）：

\begin{lstlisting}[language=Python]
norm = np.linalg.norm(vec)
if norm > 0:
    vec = vec / norm  # 归一化后 |vec| = 1，点积 = 余弦相似度
\end{lstlisting}

\subsubsection{PhotoIndex 类设计}\label{photoindex-ux7c7bux8bbeux8ba1}

\href{samples/case7/photo_index.py}{photo\_index.py} 中的
\passthrough{\lstinline!PhotoIndex!} 类管理 整个照片索引的生命周期：

\begin{itemize}

\end{itemize}

\subsubsection{为什么用
IndexFlatIP（暴搜）}\label{ux4e3aux4ec0ux4e48ux7528-indexflatipux66b4ux641c}

\passthrough{\lstinline!faiss.IndexFlatIP!} 是 FAISS
提供的最简单的索引------不做任何近似或压缩，
直接计算查询向量与库中所有向量的内积。对于个人照片库（通常几百到几千张），
暴搜完全够用：

\begin{itemize}
\tightlist
\item
  在 10,000 张照片的库中搜索一次约需 1-2ms（2048 维 × 10,000 次点积）
\item
  不需要训练（IVF 需要）、不损失精度（PQ 会降低召回率）
\item
  索引文件大小 = 照片数 × 2048 × 4 字节，10,000 张约 80 MB
\end{itemize}

当照片库增长到数万张以上时，可以将 \passthrough{\lstinline!IndexFlatIP!}
替换为 \passthrough{\lstinline!IndexIVFFlat!} 或
\passthrough{\lstinline!IndexHNSWFlat!}，在精度和速度之间做权衡。

\subsubsection{NPU
批量推理的实际情况}\label{npu-ux6279ux91cfux63a8ux7406ux7684ux5b9eux9645ux60c5ux51b5}

OM 模型的输入形状固定为
\passthrough{\lstinline!(1, 3, 224, 224)!}（batch size = 1），所以 NPU
模式下的''批量索引''实际上是逐张调用
\passthrough{\lstinline!execute()!}。对于几百张照片的索引，
总耗时完全可以接受（每张 \textasciitilde8ms，100 张不到 1 秒）。

CPU 回退模式反而可以利用 PyTorch 的动态批处理能力------将多张照片堆叠为
\passthrough{\lstinline!(N, 3, 224, 224)!}
的张量，一次前向传播处理整个批次。这是 OM 模型的一
个已知限制，书中已在多处提及（参见案例8、案例9中的相关讨论）。

\subsubsection{人脸检测：为什么只用 Haar
Cascade}\label{ux4ebaux8138ux68c0ux6d4bux4e3aux4ec0ux4e48ux53eaux7528-haar-cascade}

本案例使用 OpenCV 内置的 Haar Cascade
分类器做人脸\textbf{计数}，而不是使用 案例1中的 SCRFD NPU
模型做人脸\textbf{识别}：

\midrule\noalign{}
\endhead
\bottomrule\noalign{}
\endlastfoot

\subsubsection{双后端切换}\label{ux53ccux540eux7aefux5207ux6362}

\passthrough{\lstinline!FeatureExtractor!} 在初始化时自动检测 NPU
可用性：

\begin{lstlisting}[language=Python]
class FeatureExtractor:
    def _init_backend(self):
        if os.path.exists(OM_MODEL_PATH):
            try:
                self._acl_resource = AscendResource(NPU_DEVICE_ID)
                self._om_model = AscendModel(...)
                self.use_npu = True     # NPU 模式
                return
            except Exception:
                pass
        self._init_cpu_backend()        # CPU 回退
\end{lstlisting}

这意味着： - 在昇腾 310B 上 → 自动使用 OM 模型，NPU 特征提取 -
在没有昇腾硬件的机器上 → 自动使用 PyTorch ResNet50，CPU 推理 -
同一份代码，无需修改任何配置

\subsubsection{懒加载}\label{ux61d2ux52a0ux8f7d}

_extractor = None
_photo_index = None
