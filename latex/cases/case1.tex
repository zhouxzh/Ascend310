\section{教程定位}\label{ux6559ux7a0bux5b9aux4f4d}

考勤系统是边缘人工智能中一个典型的端到端问题：摄像头产生连续图像，模型
在设备侧完成检测和特征提取，主机程序负责比对与记录，浏览器则提供管理和
观察入口。它同时涉及模型合同、主机---设备数据传输、线程生命周期、网络接口
和个人数据边界，因而适合作为本书的第一个综合案例。

本案例的目标不是构造可直接用于真实身份认证的产品，而是建立一条可以观察、
拆解和复现实验的技术链路。系统在昇腾 310B 开发板上运行两个离线模型，将
人脸图像转换为可比较的特征向量，再由 SQLite
保存用户记录和考勤事件。FastAPI 提供类型明确的 HTTP 接口，React
界面负责用户注册、浏览器抓拍、手动打卡和
记录查看。板端摄像头产生的预览帧通过 MJPEG 接口送往浏览器。

自动登记陌生人是本案例保留的教学演示策略：它用于展示``检测到人脸---提取
特征---写入数据库''的完整分支，不代表经过同意的身份注册，也不构成生产级
认证方案。真实部署必须增加身份确认、访问控制、活体检测、审计和数据删除
机制；本章不把演示结果表述为识别准确率或考勤有效性结论。

\section{系统架构}\label{ux7cfbux7edfux67b6ux6784}

系统由四个相互约束的层次构成：

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \textbf{采集层}：板端 \passthrough{\lstinline!VideoCamera!}
  读取摄像头帧并维护最近一帧；React 可以
  使用浏览器摄像头生成上传图像。两种来源都进入同一图像处理接口。
\item
  \textbf{硬件工作层}：一个受控的运行线程顺序调用检测、裁剪和特征提取；注册、
  打卡等推理任务经同一队列执行，避免多个 HTTP 请求同时使用同一 ACL
  context、 Device buffer 或摄像头句柄。SQLite 另以进程内锁保护读写。
\item
  \textbf{服务层}：FastAPI 将注册、抓拍、手动打卡、记录查询和 MJPEG
  预览暴露为 HTTP 资源。API
  只负责校验请求、提交硬件任务和组织响应，不在请求函数中
  复制一套推理流程。
\item
  \textbf{界面层}：React 调用 API
  并呈现状态。界面中的``自动登记''标签必须说明
  其教学属性，不能暗示这是经过人工授权的生产注册。
\end{enumerate}

\subsection{一次图像请求的逻辑顺序}\label{ux4e00ux6b21ux56feux50cfux8bf7ux6c42ux7684ux903bux8f91ux987aux5e8f}

对于注册或手动打卡，一次请求通常经历以下阶段：

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  FastAPI 读取 multipart 文件或 base64 图像，并限制请求大小；
\item
  OpenCV 解码图像，检查图像非空且位于允许的处理范围；
\item
  检测模型定位候选人脸，选择面积最大的候选作为本案例的简化策略；
\item
  根据边界框裁剪人脸并送入特征模型；
\item
  将输出向量与数据库中的向量逐一计算余弦相似度；
\item
  注册请求写入用户和头像，打卡请求在通过阈值时写入事件；
\item
  API 返回结构化结果，界面根据
  \passthrough{\lstinline!success!}、\passthrough{\lstinline!match!}
  或错误状态更新视图。
\end{enumerate}

这是一种便于教学的串行流程。它没有声称对多人脸、遮挡、姿态或大规模用户
库具有最佳性能；这些问题应在后续实验中单独设计协议。

\subsection{输入和前处理}\label{ux8f93ux5165ux548cux524dux5904ux7406}

当前实现编码了两组固定输入形状：检测输入为
\passthrough{\lstinline!1×3×640×640!}，特征输入为
\passthrough{\lstinline!1×3×112×112!}，数据类型为浮点数组。摄像头帧通常以
BGR 排列进入 OpenCV， 再缩放、归一化并转换为
\passthrough{\lstinline!NCHW!}。这些尺寸和归一化常数属于运行时合同，必须
与板端 OM 的描述和模型准备记录一致；改变其中任一项都应重新执行输入输出
检查和数值烟测。

特征模型的输出在当前实现中被解释为 \passthrough{\lstinline!float32!}
向量并写入 SQLite BLOB。向量
维度、字节序和归一化方式是数据库数据的隐含类型信息，迁移或更换模型时不能
只保留文件名而忽略这些字段。

\subsection{从 ONNX 到 OM}\label{ux4ece-onnx-ux5230-om}

ONNX 是准备和检查阶段的交换格式，OM 是昇腾运行时加载的离线模型。模型准备
脚本负责下载或定位源资产、检查 ONNX 输入输出，并在板端调用 ATC 生成 OM。
ATC、PyACL 和 OM 执行依赖 CANN 环境，开发机上的纯 Python
测试不能替代这些
步骤。模型、照片、数据库和板端报告属于运行资产，均不复制到本书源码。

推荐把证据分成四个独立门槛：

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \textbf{文件检查}：路径存在、文件可读、ONNX 能被解析；
\item
  \textbf{合同检查}：输入形状、输出数量、数据类型与后处理实现一致；
\item
  \textbf{转换检查}：ATC 成功生成目标 OM，并保留命令和日志；
\item
  \textbf{运行检查}：在目标开发板上完成 ACL 加载、一次推理和资源释放。
\end{enumerate}

只有完成相应门槛，文档才可以使用``已验证''这一表述。没有报告支撑的 FPS、
延迟、准确率和召回率不应写入案例结论。

\section{PyACL
运行时与资源生命周期}\label{pyacl-ux8fd0ux884cux65f6ux4e0eux8d44ux6e90ux751fux547dux5468ux671f}

\subsection{初始化}\label{ux521dux59cbux5316}

应用启动时由运行时管理器完成以下工作：

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  调用 \passthrough{\lstinline!acl.init!}，设置目标设备并创建 context 与
  stream；
\item
  加载检测和特征 OM，读取模型描述中的输入输出信息；
\item
  为输入、输出数据集和 Device buffer 分配资源；
\item
  初始化 SQLite，并启动摄像头采集线程或延迟到首次使用。
\end{enumerate}

FastAPI 的 lifespan
是组织这些步骤的合适位置。它使服务启动失败能够显式呈现 为
\passthrough{\lstinline!degraded!}
健康状态，而不是让请求在模型不存在时悄悄生成没有语义的向量。

\subsection{一次执行}\label{ux4e00ux6b21ux6267ux884c}

对每个模型，主机把连续的 NumPy 数组拷贝到 Device buffer，调用
\passthrough{\lstinline!acl.mdl.execute!}，再将输出拷回主机并按模型合同解释。检测和特征提取应由
同一个硬件工作队列串行调度；数据库查询和余弦相似度计算在主机侧完成，SQLite
读写由进程内锁与事务边界保护。

\subsection{释放}\label{ux91caux653e}

服务停止时应先停止接收新任务，再停止 MJPEG 生成器和摄像头线程，随后释放
模型数据集、data buffer、Device buffer、模型句柄、stream、context
和设备，最后 调用 \passthrough{\lstinline!acl.finalize!}。显式的
\passthrough{\lstinline!stop()!} 与线程 \passthrough{\lstinline!join()!}
比依赖 Python 析构函数更
容易测试；若线程未在期限内退出，运行时必须报告失败并禁止再次创建硬件
owner。

\subsection{浏览器界面}\label{ux6d4fux89c8ux5668ux754cux9762}

React 页面通过 \passthrough{\lstinline!fetch!}
调用上述资源，使用文件上传或浏览器
\passthrough{\lstinline!getUserMedia!}
产生图像。离开页面、重新抓拍或请求失败时，前端应释放媒体 轨道并清理对象
URL。FastAPI
托管构建后的静态资源；\passthrough{\lstinline!/!}、\passthrough{\lstinline!/users\_page!}
和 \passthrough{\lstinline!/attendance\_page!} 作为兼容入口回退到同一个
SPA，使旧书签仍然可用。

MJPEG 预览只读取硬件线程维护的最近 JPEG，不在每个 HTTP 客户端中重新执行
检测。这样可以把``采集与推理''和``网络传输''分开，避免浏览器数量改变硬件
工作顺序。它仍然是教学级流式方案，不提供 WebRTC、鉴权和带宽自适应。

\subsection{同步与异步的选择}\label{ux540cux6b65ux4e0eux5f02ux6b65ux7684ux9009ux62e9}

FastAPI 采用 ASGI，但 PyACL、OpenCV 和标准库
\passthrough{\lstinline!sqlite3!} 都是阻塞调用。请求
处理函数不能因为使用 FastAPI 就全部改写为
\passthrough{\lstinline!async def!}；硬件操作应进入单一
工作队列或受控线程池，异步层只负责等待结果和发送响应。多 worker
启动会复制 模型和摄像头句柄，本案例固定单 worker。

\section{检测、特征与比对}\label{ux68c0ux6d4bux7279ux5f81ux4e0eux6bd4ux5bf9}

\subsection{检测与裁剪}\label{ux68c0ux6d4bux4e0eux88c1ux526a}

检测输出先经过分数阈值筛选、坐标缩放和 NMS，再得到候选框。当前示例在存在
多张人脸时选择面积最大的框，作为单人考勤演示的确定性策略。空框、越界框或
裁剪后尺寸为零时，应返回可解释的业务错误，不应把整张无脸图像当作有效身份
输入。

\subsection{特征比对}\label{ux7279ux5f81ux6bd4ux5bf9}

设查询向量为 \(q\)，数据库向量为 \(v_i\)，余弦相似度为

\[
s(q,v_i)=\frac{q\cdot v_i}{\lVert q\rVert_2\lVert v_i\rVert_2+\epsilon}.
\]

系统在候选用户中取最大相似度，并与配置阈值比较。示例阈值是工程参数，不是
经过特定数据集校准的生物识别决策边界；改变模型、摄像头、光照或用户群体后，
应以独立的正负样本协议重新估计阈值，并报告误接受与误拒绝情况。

\subsection{两种考勤分支}\label{ux4e24ux79cdux8003ux52e4ux5206ux652f}

\begin{itemize}
\tightlist
\item
  \textbf{板端自动分支}：摄像头线程定期取当前帧，检测最大人脸，完成特征比对；
  已匹配用户可以写入 \passthrough{\lstinline!camera\_auto!}
  事件，陌生人按教学策略自动登记并标注为 演示事件。
\item
  \textbf{浏览器手动分支}：React 上传文件或浏览器抓拍，API
  完成同样的检测、 特征和比对过程；只有匹配通过时才写入
  \passthrough{\lstinline!manual!} 事件，未匹配结果返回
  \passthrough{\lstinline!match=false!}。
\end{itemize}

\passthrough{\lstinline!GET /api/attendance!}
的当前语义是``当天每位用户最近一次记录''，不是完整历史
审计。若研究需要多次事件、跨日期查询或导出，应另行设计带日期、用户、分页和
时区参数的接口，不应仅修改页面标题。

\section{数据存储与隐私边界}\label{ux6570ux636eux5b58ux50a8ux4e0eux9690ux79c1ux8fb9ux754c}

SQLite 表保存用户名称、特征
BLOB、头像资源标识和考勤事件。特征是敏感的生物 特征数据，即使转换为 BLOB
也没有自动获得加密或匿名性。教学部署应至少做到：

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  上传文件由服务端生成不透明资源名，限制大小和图像类型，校验规范化路径
  位于 \passthrough{\lstinline!data/uploads!} 内；
\item
  API 列表不返回 embedding，资源下载经过明确的访问边界，不把上传目录
  直接作为公开静态目录；
\item
  数据库、照片、模型和报告保留在设备本地，测试结束按实验协议删除；
\item
  日志只记录必要的事件标识，不输出完整特征、原始图像或调试堆栈；
\item
  自动登记仅用于教学观察，正式系统必须有知情同意、人工审核、撤销和删除
  流程。
\end{enumerate}

这些措施是最低限度的工程边界，不等同于完整的隐私影响评估或合规认证。

\section{实验步骤与证据记录}\label{ux5b9eux9a8cux6b65ux9aa4ux4e0eux8bc1ux636eux8bb0ux5f55}

\subsection{开发机上的纯 Python
检查}\label{ux5f00ux53d1ux673aux4e0aux7684ux7eaf-python-ux68c0ux67e5}

开发机不具备 CANN、PyACL、OM
和摄像头运行条件。可执行的检查包括目录合同、 Python 语法、FastAPI
请求合同和使用 fake runtime 的生命周期测试：

\begin{lstlisting}[language=bash]
cd samples/case1
python -m unittest discover -s tests -p 'test_layout.py'
python -m py_compile app.py face_attendance/*.py
\end{lstlisting}

模型检查脚本可以解析已提供的 ONNX 文件，但解析成功不等于转换成功或推理
正确。测试输出应标明``静态检查''，不能写成板端性能结论。

\subsection{开发板上的硬件检查}\label{ux5f00ux53d1ux677fux4e0aux7684ux786cux4ef6ux68c0ux67e5}

在已加载 CANN 环境的 Ascend 310B 上依次完成：

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  检查设备状态、摄像头节点和 Python \passthrough{\lstinline!acl!} 导入；
\item
  检查 ONNX 输入输出合同，按目标 SoC 运行 ATC（若 OM 尚未存在）；
\item
  加载两个 OM，执行一次检测和一次特征提取，确认输出形状；
\item
  启动 FastAPI，检查
  \passthrough{\lstinline!/api/health!}、静态首页、用户 API 和 MJPEG
  首帧；
\item
  用合成或经同意的测试图像完成注册、手动打卡和自动分支；
\item
  发送停止信号，检查摄像头、模型、ACL context 和服务进程均已释放。
\end{enumerate}

每项结果都应保留命令、环境、模型文件名、输入协议和原始日志路径。只有在
具有明确测量脚本和报告时，才可增加延迟、帧率、识别率或资源占用数字。

\subsection{API 合同示例}\label{api-ux5408ux540cux793aux4f8b}

以下示例只说明接口形状，不包含真实图像或生产凭据：

curl http://127.0.0.1:5000/api/health
curl http://127.0.0.1:5000/api/users
curl -F 'name=example' -F 'image=@synthetic-face.jpg' \

板端服务若需要局域网访问，应显式传入受控的
\passthrough{\lstinline!--host!}，并在实验结束后恢复本机
监听。默认命令不启用调试模式、自动重载或多 worker。

\section{局限与可扩展方向}\label{ux5c40ux9650ux4e0eux53efux6269ux5c55ux65b9ux5411}

本案例的简化点包括：最大人脸策略、全库线性检索、固定阈值、SQLite
单机写入、 MJPEG
预览和教学性的陌生人自动登记。它们有助于暴露基本数据流，但不能直接
推导出大规模、多摄像头、跨网络或高安全场景的结论。

合理的后续实验包括：

\begin{itemize}
\tightlist
\item
  用独立的同人/异人样本校准阈值，并报告 ROC、误接受率和误拒绝率；
\item
  增加活体检测和人工审核，将``未知人脸''与``新用户注册''分离；
\item
  将向量检索从全库遍历扩展为带版本和重建策略的 ANN 索引；
\item
  以任务队列和限流机制研究多摄像头、多个浏览器客户端的资源竞争；
\item
  比较 MJPEG 与其他传输协议的带宽和延迟，但不得把协议比较结果归因于 NPU
  推理速度。
\end{itemize}

\section{小结}\label{ux5c0fux7ed3}

案例1把一个看似简单的``摄像头打卡''问题拆解为模型合同、硬件运行时、数据
比对、服务接口和隐私边界五个可以单独验证的对象。FastAPI 与 React
负责清晰 地表达服务和交互，单一硬件工作线程负责稳定地使用摄像头与
NPU，SQLite 则
提供可观察的本地事件存储。学习重点不是记住某个未经测量的延迟数字，而是
建立从资产检查到板端证据的完整推理链，并能说明每个结论的适用范围。
