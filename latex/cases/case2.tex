\section{目标跟踪对时序关联的要求}\label{ux76eeux6807ux8ddfux8e2aux5bf9ux65f6ux5e8fux5173ux8054ux7684ux8981ux6c42}

目标检测解决的是单帧图像中的两个问题：

\begin{itemize}
\tightlist
\item
  目标在哪里。
\item
  目标属于什么类别。
\end{itemize}

例如，在一帧图像里，检测器可能输出三个框，其中两个是行人，一个是汽车。但仅靠检测器，我们无法回答下面这些时间维度上的问题：

\begin{itemize}
\tightlist
\item
  当前这一帧左侧的行人，是不是上一帧的 3 号目标。
\item
  被遮挡后重新出现的车辆，是否还是之前那一辆。
\item
  两个目标交叉通过时，系统该如何保持它们的身份不交换。
\end{itemize}

上述问题正是目标跟踪所要解决的核心任务。多目标跟踪系统不仅需要检测目标的存在，还需要为同一目标在连续帧中维持稳定的身份编号，即稳定的
ID。

因此，目标跟踪可以理解为``目标检测在时间维度上的延伸''。检测负责看见目标，跟踪负责维持目标身份。

\section{MobileNet-SSD

\subsection{边缘侧场景的基本要求}\label{ux8fb9ux7f18ux4fa7ux573aux666fux7684ux57faux672cux8981ux6c42}

昇腾 310B
面向边缘智能计算场景。在这类场景中，算法设计通常要同时考虑以下问题：

\begin{itemize}
\tightlist
\item
  实时性是否足够。
\item
  模型规模是否可控。
\item
  推理链路是否简单稳定。
\item
  是否便于部署到 NPU 或 CPU 回退环境。
\end{itemize}

如果直接选择参数量庞大、结构复杂、后处理繁重的检测器，理解成本与工程调试成本都会显著上升，系统主线反而不易把握。因此，本案例采用轻量、经典且工程路径清晰的
MobileNet-SSD 组合作为检测前端。

\subsection{MobileNet
的网络结构}\label{mobilenet-ux7684ux7f51ux7edcux7ed3ux6784}

MobileNet
的核心设计思想，是用深度可分离卷积替代标准卷积，从而显著降低参数量与计算量。

标准卷积把空间卷积和通道融合同时完成，而 MobileNet 将其拆分成两步：

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Depthwise Convolution：对每个输入通道分别做空间卷积。
\item
  Pointwise Convolution：使用 1×1 卷积完成通道之间的信息融合。
\end{enumerate}

如果标准卷积的输入通道数为 \(M\)，输出通道数为 \(N\)，卷积核大小为
\(K \times K\)，特征图大小为
\(D \times D\)，那么标准卷积的计算量大致为：

\[
D^2 \cdot K^2 \cdot M \cdot N
\]

而深度可分离卷积的计算量大致为：

\[
D^2 \cdot K^2 \cdot M + D^2 \cdot M \cdot N
\]

当 \(K=3\)
时，这种拆分能够显著降低计算成本。这一特性对于边缘设备尤为重要。

从结构上看，MobileNet 可以理解为由以下几类模块反复堆叠而成：

\begin{itemize}
\tightlist
\item
  普通卷积层，用于最初级的特征提取。
\item
  深度卷积层，用于逐通道提取空间信息。
\item
  逐点卷积层，用于跨通道融合特征。
\item
  下采样层，用于逐步扩大感受野，获得更强的语义信息。
\end{itemize}

MobileNet 的主要价值体现在以下几个方面：

\begin{itemize}
\tightlist
\item
  它很好地体现了轻量化网络的设计思想。
\item
  它适合作为边缘侧模型部署的入门例子。
\item
  它与 SSD 结合后，能够形成一条结构清晰、速度较快的检测链路。
\end{itemize}

\subsection{MobileNet v1 至 v4
的版本演进}\label{mobilenet-v1-ux81f3-v4-ux7684ux7248ux672cux6f14ux8fdb}

MobileNet 并非单一网络，而是一个持续演进的轻量级网络家族。v1 至 v4
的演进，本质上体现为在移动端与边缘侧约束下，对精度、速度与结构表达能力的持续平衡与优化。

\subsubsection{MobileNet v1}\label{mobilenet-v1}

MobileNet v1
是这个家族的起点。它最核心的贡献，就是把深度可分离卷积系统化地应用到整个网络主干中。

结构特点：

\begin{itemize}
\tightlist
\item
  以 depthwise convolution 加 pointwise convolution 为基本单元
\item
  网络结构规整，堆叠方式简单直接
\item
  参数量和计算量相比标准卷积网络大幅下降
\end{itemize}

优点：

\begin{itemize}
\tightlist
\item
  结构最直观，最容易理解
\item
  轻量化效果明显
\item
  在边缘设备上容易部署
\end{itemize}

局限：

\begin{itemize}
\tightlist
\item
  特征表达能力相对有限
\item
  在相同算力下，精度通常不如后续版本
\end{itemize}

\subsubsection{MobileNet v2}\label{mobilenet-v2}

MobileNet v2 的核心改进是引入了 inverted residual 和 linear bottleneck。

结构特点：

\begin{itemize}
\tightlist
\item
  先通过 1×1 卷积扩张通道
\item
  再做 depthwise convolution
\item
  最后通过线性 bottleneck 压缩回较低维度
\item
  在满足条件时使用残差连接
\end{itemize}

它与传统残差块的设计思路存在明显差异。传统残差块通常采用``宽输入到宽输出''的结构，而
MobileNet v2 更强调``窄输入、宽中间层、窄输出''，因此被称为 inverted
residual。

这一版本的优势在于：

\begin{itemize}
\tightlist
\item
  在轻量化前提下提升了表达能力
\item
  残差连接帮助梯度传播更稳定
\item
  在线性 bottleneck 中减少非线性带来的信息损失
\end{itemize}

\subsubsection{MobileNet v3}\label{mobilenet-v3}

MobileNet v3 在 v2
基础上继续优化，它融合了神经网络结构搜索和轻量注意力机制的思想。

结构特点：

\begin{itemize}
\tightlist
\item
  延续 inverted residual 主体框架
\item
  引入 SE 模块增强通道注意力
\item
  使用 h-swish 等更适合移动端的激活函数
\item
  网络结构由精度与延迟共同驱动优化
\end{itemize}

与 v2 相比，v3
的一个重要特征在于更加关注真实硬件上的执行效率，而不仅仅是理论 FLOPs
的下降。换言之，v3
的优化目标并非单纯减少计算量，而是在移动端与边缘端设备上取得更优的实际速度与精度平衡。

\subsubsection{MobileNet v4}\label{mobilenet-v4}

MobileNet v4
是更后续的轻量骨干版本，它进一步强化了硬件感知设计，更强调不同算子组合在实际设备上的性能收益。

结构特点：

\begin{itemize}
\tightlist
\item
  延续轻量主干的整体方向
\item
  更强调不同卷积模块和块结构的组合效率
\item
  进一步面向硬件友好的延迟优化
\item
  在不同配置下兼顾速度、参数量和表达能力
\end{itemize}

从本仓库的模型组织可以看出，模型目录中既包含
\passthrough{\lstinline!mobilenetv4!}，也包含
\passthrough{\lstinline!mobilenetv4\_conv\_large.onnx!}
这样的变体文件。这表明 v4
系列本身已经具备不同配置路径，用于在更强表达能力与更低计算开销之间进行权衡。

\subsection{MobileNet v1-v4
的结构对比总结}\label{mobilenet-v1-v4-ux7684ux7ed3ux6784ux5bf9ux6bd4ux603bux7ed3}

如果按结构演进主线来总结，四个版本的差异可以概括为：

\begin{itemize}
\tightlist
\item
  v1：用深度可分离卷积解决``怎么把网络做轻''
\item
  v2：用 inverted residual 和 linear bottleneck
  解决``轻量化下如何保留表达能力''
\item
  v3：用 SE、h-swish
  和结构搜索解决``如何进一步优化真实设备上的速度与精度平衡''
\item
  v4：进一步走向硬件感知和模块组合优化，强调在实际部署环境中的综合收益
\end{itemize}

如果按本案例的应用视角看，这些版本的差异意味着：

\begin{itemize}
\tightlist
\item
  v1 更适合讲轻量化网络的最基础结构
\item
  v2 更适合讲轻量网络中的残差和瓶颈设计
\item
  v3 更适合讲轻量网络与注意力机制、激活函数优化的结合
\item
  v4 更适合讲面向部署性能的后续演化方向
\end{itemize}

\subsection{MobileNet 与 ResNet
骨干在本案例中的取向差异}\label{mobilenet-ux4e0e-resnet-ux9aa8ux5e72ux5728ux672cux6848ux4f8bux4e2dux7684ux53d6ux5411ux5deeux5f02}

本案例同时提供 MobileNet 和 ResNet
两条骨干路线，这样可以更直观地对比不同网络家族的使用取向。

MobileNet 系列的特点是：

\begin{itemize}
\tightlist
\item
  参数量更小
\item
  推理速度更快
\item
  更适合实时演示和边缘部署
\end{itemize}

ResNet 系列的特点是：

\begin{itemize}
\tightlist
\item
  特征提取能力更强
\item
  网络层次更深，残差结构更成熟
\item
  在一些场景下更容易得到稳定的检测效果
\end{itemize}

因此，在本案例中：

\begin{itemize}
\tightlist
\item
  如果更关注实时性和轻量部署，可以优先尝试 MobileNet v1-v4
\item
  如果更关注骨干网络深度和表达能力，可以尝试 ResNet18 到 ResNet151
  的多个版本
\end{itemize}

\subsection{SSD 的检测特点}\label{ssd-ux7684ux68c0ux6d4bux7279ux70b9}

SSD 是 Single Shot MultiBox Detector
的缩写，属于典型的一阶段检测器。它的核心特点是：不需要像两阶段检测器那样先生成候选区域，再做分类与回归，而是直接在不同尺度的特征图上预测目标位置和类别。

SSD 的关键思想包括：

\begin{itemize}
\tightlist
\item
  在多个尺度特征图上进行检测，兼顾大目标和小目标。
\item
  在每个位置预先定义一组 default boxes，也叫 prior boxes。
\item
  网络直接回归 default box 的位置偏移量，同时预测各类别分数。
\item
  经过解码和 NMS 后，输出最终的检测框。
\end{itemize}

SSD 的优点主要有：

\begin{itemize}
\tightlist
\item
  推理速度快，适合实时场景。
\item
  结构相对直接，便于理解和部署。
\item
  检测头设计清晰，容易解释``分类''和``回归''两个分支的作用。
\end{itemize}

SSD 的局限也需要明确说明：

\begin{itemize}
\tightlist
\item
  对小目标和密集目标场景通常不如更新的检测器稳定。
\item
  检测效果较依赖先验框设计与输入尺寸。
\item
  在复杂遮挡场景下，单帧检测质量会波动，从而影响后续跟踪。
\end{itemize}

\subsection{MobileNet-SSD
用于目标跟踪的优缺点}\label{mobilenet-ssd-ux7528ux4e8eux76eeux6807ux8ddfux8e2aux7684ux4f18ux7f3aux70b9}

在目标跟踪任务中，检测器不是孤立存在的，它会直接影响轨迹质量。MobileNet-SSD
作为跟踪前端，有以下优点：

\begin{itemize}
\tightlist
\item
  轻量高效，适合边缘侧实时处理。
\item
  输出结构标准，便于接入后续跟踪器。
\item
  检测速度较快，可以为多目标跟踪提供稳定的帧级观测。
\item
  工程复杂度低，便于构建完整案例。
\end{itemize}

但它也存在明显不足：

\begin{itemize}
\tightlist
\item
  对小目标和远距离目标的检测精度有限。
\item
  遇到密集遮挡时，漏检和框抖动会增多。
\item
  当检测框位置不稳定时，跟踪器更容易发生 ID switch。
\item
  仅靠检测框几何信息，难以应对长时间遮挡或重识别问题。
\end{itemize}

因此，MobileNet-SSD
的价值不在于``它是最强的检测前端''，而在于``它能以较低复杂度，把检测到跟踪这条主线讲清楚''。

\section{DeepSORT
作为跟踪后端的选择依据}\label{deepsort-ux4f5cux4e3aux8ddfux8e2aux540eux7aefux7684ux9009ux62e9ux4f9dux636e}

\subsection{从检测到跟踪，还缺少什么}\label{ux4eceux68c0ux6d4bux5230ux8ddfux8e2aux8fd8ux7f3aux5c11ux4ec0ux4e48}

检测器每一帧都输出一组目标框，但这些框之间没有时间关联。要把检测结果变成稳定轨迹，还需要以下机制：

\begin{itemize}
\tightlist
\item
  轨迹状态表示。
\item
  帧间运动预测。
\item
  检测与轨迹之间的匹配。
\item
  轨迹的创建、保留和删除。
\end{itemize}

DeepSORT 恰好提供了这样一套结构完整的解决框架。

\subsection{DeepSORT
为什么适合作为入门算法}\label{deepsort-ux4e3aux4ec0ux4e48ux9002ux5408ux4f5cux4e3aux5165ux95e8ux7b97ux6cd5}

完整的 DeepSORT 在 SORT
基础上增加了外观特征建模，因此在目标遮挡、交叉和重识别问题上通常具有更好的稳定性。尽管本案例并未实现完整的工业级
DeepSORT，但保留了其最核心、最适合入门阶段把握的基本思路：

\begin{itemize}
\tightlist
\item
  用卡尔曼滤波做运动预测。
\item
  用匈牙利算法做全局匹配。
\item
  用 IOU 作为主要几何相似度。
\item
  用轨迹生命周期参数管理目标的出现与消失。
\end{itemize}

这种简化版方案有三个突出优点：

\end{itemize}

因此，将 MobileNet-SSD 与 DeepSORT
组合使用，是一条结构清晰、实现成本适中且便于展开分析的入门路径。

\subsection{decoder.py 如何体现 SSD
的核心思想}\label{decoder.py-ux5982ux4f55ux4f53ux73b0-ssd-ux7684ux6838ux5fc3ux601dux60f3}

ssdlite/decoder.py 直接对应了 SSD
的理论结构，是整条检测链路中的关键部分。

\subsubsection{default boxes}\label{default-boxes}

在 DefaultBoxes 类中，代码根据不同特征图尺度和长宽比生成先验框。这正是
SSD
的基础：网络并不是直接从零开始生成框，而是在预定义框基础上学习偏移量。

\subsubsection{位置回归的反变换}\label{ux4f4dux7f6eux56deux5f52ux7684ux53cdux53d8ux6362}

在 SSDDecoder.scale\_back\_batch
中，网络输出的并不是最终框坐标，而是相对于默认框的偏移量。代码中先利用
scale\_xy 和 scale\_wh
对偏移量进行还原，再把中心点形式转换为左上角和右下角坐标。

更直接地说：

\begin{itemize}
\tightlist
\item
  网络先预测相对于先验框的中心偏移和宽高缩放。
\item
  解码阶段再把这些相对量恢复成图像上的实际边界框。
\end{itemize}

\subsubsection{分类分数与 NMS}\label{ux5206ux7c7bux5206ux6570ux4e0e-nms}

在 decode\_single 中，代码对每个类别分别进行处理：

\begin{lstlisting}[language=Python]
for class_id in range(1, scores_in.shape[1]):
    class_scores = scores_in[:, class_id]
    keep_score = class_scores > 0.05
    keep_nms = _nms(class_boxes, class_scores, criteria)
\end{lstlisting}

这段代码体现了 SSD 后处理的两个关键步骤：

\begin{itemize}
\tightlist
\item
  先按类别分数进行阈值筛选。
\item
  再对同一类别的框做 NMS，去掉大量重叠冗余框。
\end{itemize}

如果没有这一步，检测器往往会输出大量相互重叠的候选框，无法直接作为跟踪器输入。

\subsubsection{NMS
的作用是什么}\label{nms-ux7684ux4f5cux7528ux662fux4ec0ux4e48}

NMS 是 Non-Maximum
Suppression，即非极大值抑制。它的核心作用可以概括为一句话：当多个候选框同时指向同一个目标时，只保留其中最可信的候选框，并删除其余高度重叠的框。

这是因为 SSD
会在每个特征图位置、每种先验框形状上产生候选框。对于一个真实目标，模型往往不会只输出一个框，而是会输出一组位置接近、分数相近的候选框。如果不执行
NMS，画面中就会出现大量相互覆盖的检测框，例如同一行人周围同时叠加 5 个到
10 个候选框。

NMS 的作用主要有四点：

\begin{itemize}
\tightlist
\item
  去除重复检测，让一个目标尽量只保留一个主框。
\item
  降低后续显示和统计的混乱程度。
\item
  为跟踪器提供更稳定、更稀疏的观测输入。
\item
  避免同一目标在跟踪阶段被误认为多个目标。
\end{itemize}

对本案例尤其要强调最后一点。如果检测器把同一目标输出成多个高重叠框，那么
tracking
模块在创建轨迹时，可能会把这些框错误地当成多个独立目标，从而造成重复轨迹、ID
混乱和后续匹配不稳定。

NMS 的处理逻辑可以概括成下面 4 步：

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  按置信度从高到低排序所有候选框。
\item
  取当前分数最高的框作为保留框。
\item
  计算其余框与该保留框的 IOU。
\item
  删除所有 IOU 超过阈值的框，然后继续处理剩余框。
\end{enumerate}

因此，NMS
本质上是在做``去重''。它不是提高分类能力，而是在后处理阶段把重复候选框压缩成更干净的检测结果。

\subsubsection{ssdlite 中 \_nms
的实现解析}\label{ssdlite-ux4e2d-_nms-ux7684ux5b9eux73b0ux89e3ux6790}

ssdlite/decoder.py 中实现的 NMS 函数如下：

\begin{lstlisting}[language=Python]
def _nms(boxes, scores, iou_threshold):
    if len(boxes) == 0:
        return np.empty((0,), dtype=np.int64)

    order = np.argsort(scores)[::-1]
    keep = []
    while order.size > 0:
        index = order[0]
        keep.append(index)
        if order.size == 1:
            break
        iou = calc_iou(boxes[order[1:]], boxes[index].reshape(1, 4)).reshape(-1)
        order = order[np.where(iou <= iou_threshold)[0] + 1]
    return np.array(keep, dtype=np.int64)
\end{lstlisting}

这段实现虽然短，但几乎完整体现了经典 NMS 的核心流程。

第一步，处理空输入：

\begin{lstlisting}[language=Python]
if len(boxes) == 0:
    return np.empty((0,), dtype=np.int64)
\end{lstlisting}

这一步是工程上必不可少的防御式处理。如果当前类别一个候选框都没有，就直接返回空索引，避免后续排序和
IOU 计算报错。

第二步，按照分数降序排列：

\begin{lstlisting}[language=Python]
order = np.argsort(scores)[::-1]
\end{lstlisting}

\passthrough{\lstinline!np.argsort(scores)!}
会返回分数从小到大排列后的索引，\passthrough{\lstinline![::-1]!}
再把顺序翻转成从大到小。这样一来，\passthrough{\lstinline!order[0]!}
就总是当前剩余候选框中分数最高的那个。

第三步，循环保留最高分框：

\begin{lstlisting}[language=Python]
keep = []
while order.size > 0:
    index = order[0]
    keep.append(index)
\end{lstlisting}

这里的含义至关重要：每一轮循环都将当前最高分框作为``代表框''保留下来。NMS
的基本原则是，在一组高度重叠的候选框中，分数最高的框通常最应优先保留。

第四步，只剩一个框时直接结束：

\begin{lstlisting}[language=Python]
if order.size == 1:
    break
\end{lstlisting}

如果当前只剩一个候选框，那么它已经被保留，没有必要再做 IOU 比较。

第五步，计算其余候选框与当前最高分框的 IOU：

\begin{lstlisting}[language=Python]
iou = calc_iou(boxes[order[1:]], boxes[index].reshape(1, 4)).reshape(-1)
\end{lstlisting}

这一步可以这样理解：

\begin{itemize}
\tightlist
\item
  \passthrough{\lstinline!boxes[index]!} 是当前保留框。
\item
  \passthrough{\lstinline!boxes[order[1:]]!} 是除了它以外剩余的候选框。
\item
  \passthrough{\lstinline!calc\_iou(...)!}
  计算这些候选框与当前保留框之间的重叠程度。
\end{itemize}

如果某个候选框与保留框的 IOU
很高，就说明这两个框大概率描述的是同一个目标，此时就没有必要同时保留。

第六步，删除 IOU 过高的重复框：

\begin{lstlisting}[language=Python]
order = order[np.where(iou <= iou_threshold)[0] + 1]
\end{lstlisting}

这一行代码是整个 NMS 实现中最关键的语句之一。

\begin{itemize}
\tightlist
\item
  \passthrough{\lstinline!iou <= iou\_threshold!}
  表示只保留那些与当前主框重叠不太严重的候选框。
\item
  \passthrough{\lstinline!np.where(...)!} 得到满足条件的索引位置。
\item
  之所以要 \passthrough{\lstinline!+ 1!}，是因为前面计算 IOU 时使用的是
  \passthrough{\lstinline!order[1:]!}，也就是跳过了当前最高分框，所以这里需要把索引映射回原来的
  \passthrough{\lstinline!order!} 序列。
\end{itemize}

执行完这一行后，所有与当前主框高度重叠的框都会被移除，剩下的框继续进入下一轮循环。

第七步，返回保留框索引：

\begin{lstlisting}[language=Python]
return np.array(keep, dtype=np.int64)
\end{lstlisting}

最终返回的不是框本身，而是被保留框在原数组中的索引。后续代码再用这些索引去提取真正的框、分数和类别。

\subsubsection{calc\_iou 为什么是 NMS
的基础}\label{calc_iou-ux4e3aux4ec0ux4e48ux662f-nms-ux7684ux57faux7840}

NMS 能否正确工作，取决于 IOU 计算是否准确。本案例在 decoder.py 中通过
calc\_iou 计算两个框集合之间的交并比。其核心思想是：

\[
IOU = \frac{\text{交集面积}}{\text{并集面积}}
\]

在代码里，这一过程分为三步：

\begin{itemize}
\tightlist
\item
  先求两个框相交区域的左上角和右下角。
\item
  再计算交集面积。
\item
  最后用交集面积除以并集面积。
\end{itemize}

如果 IOU 接近 1，说明两个框几乎重合；如果 IOU 接近
0，说明两个框几乎没有重叠。NMS
正是利用这一数值来判断``两个候选框是不是在描述同一个目标''。

\subsubsection{NMS
阈值对结果的影响}\label{nms-ux9608ux503cux5bf9ux7ed3ux679cux7684ux5f71ux54cd}

NMS 中最重要的超参数是
\passthrough{\lstinline!iou\_threshold!}。它决定了``多大程度的重叠应被视为重复''。

如果阈值较小，例如 0.3，那么算法会更严格：

\begin{itemize}
\tightlist
\item
  只要两个框稍微重叠得多一点，就可能删除其中一个。
\item
  输出框更少，更干净。
\item
  但也可能误删本来相邻但不是同一目标的框。
\end{itemize}

如果阈值较大，例如 0.6 或 0.7，那么算法会更宽松：

\begin{itemize}
\tightlist
\item
  允许更多重叠框同时保留。
\item
  对密集目标场景可能更友好。
\item
  但重复检测也更容易残留。
\end{itemize}

因此，NMS 阈值本质上是在``去重强度''和``保留相邻目标''之间做权衡。

\subsubsection{NMS
对跟踪效果的直接影响}\label{nms-ux5bf9ux8ddfux8e2aux6548ux679cux7684ux76f4ux63a5ux5f71ux54cd}

NMS
容易被视为检测模块内部的技术细节，但在目标跟踪系统中，它实际上会直接影响跟踪质量。

原因是跟踪器把检测器输出当作观测输入。如果检测结果中存在大量重复框，就会产生以下问题：

\begin{itemize}
\tightlist
\item
  同一目标可能在同一帧中生成多条新轨迹。
\item
  轨迹关联时会出现多对一竞争。
\item
  轨迹数目虚高，画面看起来混乱。
\item
  目标 ID 容易抖动，甚至频繁切换。
\end{itemize}

从这个角度看，NMS
不是孤立的后处理技巧，而是整个``检测到跟踪''流水线稳定运行的重要保障。

\subsubsection{decode\_single 中 NMS
的完整上下文}\label{decode_single-ux4e2d-nms-ux7684ux5b8cux6574ux4e0aux4e0bux6587}

在本案例中，NMS 不是单独执行的，而是被放在 decode\_single
的类别循环中。其完整语义是：

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  针对每一个类别单独处理。
\item
  先按分数过滤掉置信度过低的框。
\item
  再保留该类别中得分最高的一部分候选框。
\item
  最后在这个类别内部做 NMS。
\end{enumerate}

这意味着本案例采用的是``按类别分别做
NMS''的策略。这样设计的优点是：不同类别之间不会互相抑制。例如一个行人框和一个自行车框即使重叠较大，也不应该因为彼此重叠就被删除。

\subsection{CPU 与 NPU
后端如何被统一接入}\label{cpu-ux4e0e-npu-ux540eux7aefux5982ux4f55ux88abux7edfux4e00ux63a5ux5165}

本案例中的 ssdlite/cpu\_backend.py 与 ssdlite/npu\_backend.py 都继承自
DetectionBackend，这意味着它们对外暴露的是同一套接口。这种设计有两层价值：

\begin{itemize}
\tightlist
\item
  从算法角度看，检测逻辑不依赖具体硬件后端。
\item
  从工程角度看，同一套上层代码可以在 CPU 和 Ascend NPU 之间切换。
\end{itemize}

这也体现了一个重要的工程原则：算法主线尽量稳定，硬件适配尽量下沉到后端实现层。

\section{从检测到跟踪：tracking\_app.py
的桥接作用}\label{ux4eceux68c0ux6d4bux5230ux8ddfux8e2atracking_app.py-ux7684ux6865ux63a5ux4f5cux7528}

如果说 detection\_app.py 用于建立检测流程，那么 tracking\_app.py
的作用就在于将``检测结果如何转化为轨迹''这一过程完整串联起来。

在 demo/tracking\_app.py 中，检测模块与跟踪模块之间的桥接代码如下：

\begin{lstlisting}[language=Python]
detections, profile_ms = backend.infer_with_profile(...)
tracker_inputs = detections_to_tracker_inputs(detections)
tracks = tracker.update(tracker_inputs)
annotated = draw_tracks(...)
\end{lstlisting}

这一过程可以分为四个连续步骤：

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  先由检测器输出本帧的目标集合。
\item
  再把字典形式的检测结果转成跟踪器统一使用的数组格式。
\item
  调用跟踪器更新轨迹状态。
\item
  把最新轨迹结果绘制到图像上。
\end{enumerate}

其中，utils/postprocessing.py 中的 detections\_to\_tracker\_inputs
函数具有关键作用，因为它完成了检测模块与跟踪模块之间的数据接口统一。转换后的输入格式为：

\[
[x_1, y_1, x_2, y_2, score, class\_id]
\]

这正是后续轨迹匹配与分类约束所依赖的输入格式。

\section{跟踪部分代码解析}\label{ux8ddfux8e2aux90e8ux5206ux4ee3ux7801ux89e3ux6790}

\subsection{Track
类如何表示一条轨迹}\label{track-ux7c7bux5982ux4f55ux8868ux793aux4e00ux6761ux8f68ux8ff9}

tracking/deepsort.py 中的 Track
类代表单个目标的历史状态。每条轨迹至少维护了以下信息：

\begin{itemize}
\tightlist
\item
  track\_id：目标编号。
\item
  bbox：当前边界框。
\item
  score：当前检测置信度。
\item
  class\_id：目标类别。
\item
  trail：历史中心点序列，用于绘制轨迹拖尾。
\item
  kalman\_filter：用于状态预测与更新。
\item
  time\_since\_update：距离上次匹配成功已经过去多少帧。
\item
  hits：这条轨迹累计被成功匹配了多少次。
\end{itemize}

这表明轨迹并不是静态边界框的简单记录，而是一个具有时间属性的状态对象。因此，``检测框''和``轨迹''必须明确区分。

\subsection{predict 和 update
对应卡尔曼滤波两阶段}\label{predict-ux548c-update-ux5bf9ux5e94ux5361ux5c14ux66fcux6ee4ux6ce2ux4e24ux9636ux6bb5}

Track 类中最核心的两个方法是 predict 和 update。

predict
的作用是：即使当前帧还没有拿到新的检测结果，也先根据上一时刻状态预测目标现在大概会出现在哪里。

update
的作用是：一旦当前帧有新的检测框匹配到这条轨迹，就用新的观测值修正状态估计。

这正对应卡尔曼滤波的两步：

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Predict：根据上一时刻状态外推当前状态。
\item
  Update：用当前观测修正预测误差。
\end{enumerate}

本案例里，状态量采用了一个比较直观的简化形式：

\[
x = [x, y, v_x, v_y]^T
\]

其中 \(x, y\) 表示目标中心位置，\(v_x, v_y\)
表示速度。这样做的好处是：数学含义直观，代码实现也容易读懂。

\subsection{kalman\_filter.py
如何实现线性状态估计}\label{kalman_filter.py-ux5982ux4f55ux5b9eux73b0ux7ebfux6027ux72b6ux6001ux4f30ux8ba1}

tracking/kalman\_filter.py
中定义了最基础的卡尔曼滤波器。其状态转移矩阵为：

\[
F =
\begin{bmatrix}
1 & 0 & 1 & 0 \\
0 & 1 & 0 & 1 \\
0 & 0 & 1 & 0 \\
0 & 0 & 0 & 1
\end{bmatrix}
\]

这表示系统假设目标在相邻帧之间近似满足匀速运动。观测矩阵为：

\[
H =
\begin{bmatrix}
1 & 0 & 0 & 0 \\
0 & 1 & 0 & 0
\end{bmatrix}
\]

这表示我们能够直接观测到的是目标中心位置，而不是速度。

这一实现虽然经过简化，但其价值十分明确，因为它将``运动预测''与``观测修正''这两个概念直接落实到了矩阵运算之中。

\subsection{卡尔曼滤波器的发展历史与作者信息}\label{ux5361ux5c14ux66fcux6ee4ux6ce2ux5668ux7684ux53d1ux5c55ux5386ux53f2ux4e0eux4f5cux8005ux4fe1ux606f}

卡尔曼滤波器的提出者是鲁道夫·埃米尔·卡尔曼，英文名 Rudolf Emil
Kalman。他是匈牙利裔美国数学家和控制理论学者，1960 年发表了著名论文 A
New Approach to Linear Filtering and Prediction
Problems，系统建立了线性动态系统状态估计的现代形式。

从历史背景看，卡尔曼滤波器并不是突然出现的。它的形成与 20
世纪中叶的控制理论、随机过程、航空航天导航和军事工程需求密切相关。第二次世界大战后，工程界越来越需要解决这样一类问题：

\begin{itemize}
\tightlist
\item
  系统状态不能被直接完整观测。
\item
  传感器观测存在噪声。
\item
  系统本身还在不断运动和变化。
\end{itemize}

例如，雷达跟踪飞机、导弹制导、航天器轨道估计，本质上都属于这一类问题。

卡尔曼滤波器之所以具有里程碑意义，是因为它把``预测''和``校正''统一进了一个递推框架中：

\begin{itemize}
\tightlist
\item
  先根据上一时刻状态和系统模型预测当前状态。
\item
  再根据当前观测对预测结果进行修正。
\end{itemize}

这一思想后来在 20 世纪 60
年代迅速应用到阿波罗计划的导航系统中，也因此被广泛传播到航空航天、自动控制、机器人、计算机视觉和金融工程等领域。

在发展过程中，卡尔曼滤波形成了多个重要分支：

\begin{itemize}
\tightlist
\item
  标准卡尔曼滤波：用于线性高斯系统。
\item
  扩展卡尔曼滤波 EKF：用于非线性系统的一阶近似。
\item
  无迹卡尔曼滤波 UKF：通过采样点传播非线性分布。
\item
  粒子滤波：进一步放宽线性和高斯假设。
\end{itemize}

本案例采用最基础的标准卡尔曼滤波器。采用这一形式，并非因为它代表当前最复杂的状态估计方案，而是因为它在入门阶段具有最清晰的解释路径：

\begin{itemize}
\tightlist
\item
  数学形式清晰。
\item
  与目标跟踪中的位置预测问题高度匹配。
\item
  代码实现短小，便于直接对应矩阵运算理解。
\end{itemize}

\subsection{卡尔曼滤波器到底在解决什么问题}\label{ux5361ux5c14ux66fcux6ee4ux6ce2ux5668ux5230ux5e95ux5728ux89e3ux51b3ux4ec0ux4e48ux95eeux9898}

在目标跟踪里，卡尔曼滤波器要解决的问题可以表述为：当检测器每一帧给出的目标框存在抖动、漏检和噪声时，如何根据历史状态更平滑地估计目标当前位置，并在短时没有观测的情况下继续维持轨迹。

这意味着卡尔曼滤波并不是在做``目标分类''，也不是在做``目标匹配''，它做的是状态估计。

在本案例里，这个状态估计问题被简化成了二维平面上的匀速运动模型：

\[
x_k = F x_{k-1} + w_k
\]

\[
z_k = H x_k + v_k
\]

其中：

\begin{itemize}
\tightlist
\item
  \(x_k\) 表示第 \(k\)
  帧的隐藏状态，也就是目标真实但不可完全直接观测的状态。
\item
  \(z_k\) 表示第 \(k\) 帧的观测，也就是检测器给出的目标中心位置。
\item
  \(F\) 是状态转移矩阵。
\item
  \(H\) 是观测矩阵。
\item
  \(w_k\) 是过程噪声。
\item
  \(v_k\) 是观测噪声。
\end{itemize}

从工程角度看，这个模型表达的是一个朴素但有效的假设：目标会以相对平滑的方式运动，而检测器给出的观测值只是对真实运动状态的带噪声测量。

\subsection{本案例中的 predict 与 update
如何对应算法公式}\label{ux672cux6848ux4f8bux4e2dux7684-predict-ux4e0e-update-ux5982ux4f55ux5bf9ux5e94ux7b97ux6cd5ux516cux5f0f}

tracking/kalman\_filter.py
中的两个核心函数正好对应卡尔曼滤波的两个阶段。

第一阶段是预测：

\begin{lstlisting}[language=Python]
def predict(self):
    self.x = np.dot(self.F, self.x)
    self.P = np.dot(np.dot(self.F, self.P), self.F.T) + self.Q
    return self.x
\end{lstlisting}

该阶段完成以下两项操作：

\begin{itemize}
\tightlist
\item
  用状态转移矩阵 \passthrough{\lstinline!F!} 预测新的状态向量
  \passthrough{\lstinline!x!}。
\item
  用协方差传播公式预测新的不确定性 \passthrough{\lstinline!P!}。
\end{itemize}

第二阶段是更新：

\begin{lstlisting}[language=Python]
def update(self, z):
    y = z - np.dot(self.H, self.x)
    S = np.dot(self.H, np.dot(self.P, self.H.T)) + self.R
    K = np.dot(np.dot(self.P, self.H.T), np.linalg.inv(S))
    self.x = self.x + np.dot(K, y)
    self.P = self.P - np.dot(np.dot(K, self.H), self.P)
\end{lstlisting}

这段代码中几个量的意义需要讲清楚：

\begin{itemize}
\tightlist
\item
  \passthrough{\lstinline!y!} 是
  innovation，也叫残差，表示``观测值与预测值之间的差''。
\item
  \passthrough{\lstinline!S!} 是残差协方差，表示当前误差的不确定性。
\item
  \passthrough{\lstinline!K!}
  是卡尔曼增益，决定``应该更相信模型预测还是更相信当前观测''。
\end{itemize}

这里最重要的量是卡尔曼增益
\passthrough{\lstinline!K!}。它并非经验性设定的固定权重，而是由当前状态不确定性与观测噪声共同决定的自适应权重。

可以直观地理解为：

\begin{itemize}
\tightlist
\item
  如果观测噪声很大，滤波器会更信任模型预测。
\item
  如果观测噪声较小，滤波器会更信任当前检测结果。
\end{itemize}

这也是卡尔曼滤波器的重要优势之一。它并不是简单的滑动平均，而是在概率意义上进行最优线性估计。

\subsection{卡尔曼滤波在本案例中的适用性}\label{ux5361ux5c14ux66fcux6ee4ux6ce2ux5728ux672cux6848ux4f8bux4e2dux7684ux9002ux7528ux6027}

对本案例而言，卡尔曼滤波器之所以合适，并不在于目标运动一定严格符合线性高斯模型，而在于它在工程上实现了较好的综合平衡：

\begin{itemize}
\tightlist
\item
  算法复杂度低。
\item
  推理和更新速度快。
\item
  能明显改善检测框抖动。
\item
  在短时遮挡和漏检场景下能维持轨迹连续。
\end{itemize}

如果在入门阶段直接引入 EKF、UKF
或粒子滤波，虽然理论上能够处理更复杂的运动模型，但理解成本会显著上升，主线结构反而更不易把握。因此，本案例采用标准卡尔曼滤波具有充分的合理性。

\subsection{DeepSORT.update
如何体现多目标跟踪主线}\label{deepsort.update-ux5982ux4f55ux4f53ux73b0ux591aux76eeux6807ux8ddfux8e2aux4e3bux7ebf}

tracking/deepsort.py 中的 DeepSORT.update
是整条跟踪主线最核心的函数，其执行顺序如下：

\begin{lstlisting}[language=Python]
for track in self.tracks:
    track.predict()

matched, unmatched_detections, _ = self._associate(detections)

for track_idx, detection_idx in matched:
    self.tracks[track_idx].update(detections[detection_idx])

for detection_idx in unmatched_detections:
    self._create_track(detections[detection_idx])

self.tracks = [track for track in self.tracks if track.time_since_update <= self.max_age]
\end{lstlisting}

这一段代码几乎完整体现了多目标跟踪的标准流程：

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  对所有旧轨迹做预测。
\item
  把当前检测结果与旧轨迹做关联。
\item
  用匹配到的检测结果更新旧轨迹。
\item
  对未匹配检测创建新轨迹。
\item
  删除长期未更新的轨迹。
\end{enumerate}

换言之，跟踪并不是对检测框进行简单编号，而是在连续帧之间持续执行预测、匹配、更新与清理。

\subsection{数据关联为什么使用 IOU +
匈牙利算法}\label{ux6570ux636eux5173ux8054ux4e3aux4ec0ux4e48ux4f7fux7528-iou-ux5308ux7259ux5229ux7b97ux6cd5}

在 \_associate 中，本案例先构造轨迹与检测之间的 IOU
矩阵，再调用匈牙利算法获得全局最优分配。对应代码思路如下：

\begin{lstlisting}[language=Python]
iou_matrix = self._calculate_iou_matrix(detections)
matched_indices = self._linear_assignment(iou_matrix)
\end{lstlisting}

之所以这样设计，是因为当场景中有多条轨迹和多个检测框时，不能只做局部贪心匹配。匈牙利算法的作用在于：

\begin{itemize}
\tightlist
\item
  从全局角度寻找一一对应的最优匹配。
\item
  避免一个检测框同时分配给多条轨迹。
\item
  避免一条轨迹同时匹配多个检测框。
\end{itemize}

本案例还加入了类别兼容性判断：

\begin{lstlisting}[language=Python]
if not self._is_class_compatible(track.class_id, int(detection[5])):
    continue
\end{lstlisting}

这说明系统不仅看几何位置，还利用类别信息避免``行人轨迹匹配到车辆框''这类明显错误。

\subsection{匈牙利算法的发展历史与作者信息}\label{ux5308ux7259ux5229ux7b97ux6cd5ux7684ux53d1ux5c55ux5386ux53f2ux4e0eux4f5cux8005ux4fe1ux606f}

匈牙利算法是解决二分图最优匹配和指派问题的经典算法。它最早由美国数学家哈罗德·W·库恩，英文名
Harold W. Kuhn，在 1955
年系统提出。之所以命名为``匈牙利算法''，是因为库恩的工作建立在两位匈牙利数学家的理论成果之上：

\begin{itemize}
\tightlist
\item
  德奈什·克尼格，英文名 Dénes Kőnig。
\item
  耶诺·埃格瓦里，英文名 Jenő Egerváry。
\end{itemize}

他们在图论和指派问题上的研究，为后来算法化求解最优匹配提供了重要理论基础。之后，美国数学家詹姆斯·芒克雷斯，英文名
James Munkres，在 1957
年进一步改进了该算法，使其在计算复杂度和工程实现上更加完善。因此，这一算法也常被称为
Kuhn-Munkres 算法。

从历史背景看，匈牙利算法主要服务于一类经典的组合优化问题：

\begin{itemize}
\tightlist
\item
  一组任务要分配给一组工人。
\item
  每一种分配都有代价或收益。
\item
  目标是在一一对应约束下，使总代价最小或总收益最大。
\end{itemize}

这个问题后来被称为 assignment
problem，即指派问题。它在生产调度、资源分配、路径规划、视觉跟踪等场景中都较为常见。

在多目标跟踪中，匈牙利算法的角色就是把``轨迹''和``当前检测框''看成两侧节点，把相似度或代价矩阵看成边权，然后求出全局最优的一一匹配关系。

\subsection{匈牙利算法到底解决什么问题}\label{ux5308ux7259ux5229ux7b97ux6cd5ux5230ux5e95ux89e3ux51b3ux4ec0ux4e48ux95eeux9898}

在目标跟踪里，如果只有一条轨迹和一个检测框，那么匹配很简单。但一旦场景中存在多条轨迹和多个检测框，问题就会迅速复杂起来。

例如，假设当前有 3 条旧轨迹和 3
个新检测框。此时系统不能只看``哪两个最像就先配对''，因为局部最优未必能得到全局最优。匈牙利算法解决的就是这个问题：

\begin{itemize}
\tightlist
\item
  它在满足一一对应约束的前提下，寻找整体代价最小或整体相似度最大的匹配方案。
\end{itemize}

这正是多目标跟踪里数据关联的核心。

\subsection{本案例中匈牙利算法是如何被调用的}\label{ux672cux6848ux4f8bux4e2dux5308ux7259ux5229ux7b97ux6cd5ux662fux5982ux4f55ux88abux8c03ux7528ux7684}

在 tracking/deepsort.py 中，匈牙利算法的调用被封装在
\passthrough{\lstinline!\_linear\_assignment!} 中：

\begin{lstlisting}[language=Python]
def _linear_assignment(self, cost_matrix):
    if cost_matrix.size == 0:
        return np.empty((0, 2), dtype=np.int64)

    row_ind, col_ind = linear_sum_assignment(-cost_matrix)
    return np.array(list(zip(row_ind, col_ind)), dtype=np.int64)
\end{lstlisting}

这里调用的是
scipy.optimize.linear\_sum\_assignment，它是匈牙利算法在科学计算库中的标准实现。

该函数默认求解最小化问题，而本案例构造的是 IOU 相似度矩阵，IOU
越大表示匹配越优。因此，代码中采用了一个典型的等价变换：

\begin{lstlisting}[language=Python]
linear_sum_assignment(-cost_matrix)
\end{lstlisting}

即将``最大化相似度''转化为``最小化负相似度''。

这里需要强调的一点是，同一个优化算法既可以用于最小代价问题，也可以通过简单变换用于最大收益问题。

\subsection{匈牙利算法在本案例中的完整上下文}\label{ux5308ux7259ux5229ux7b97ux6cd5ux5728ux672cux6848ux4f8bux4e2dux7684ux5b8cux6574ux4e0aux4e0bux6587}

在 \passthrough{\lstinline!\_associate!} 中，数据关联的整体过程是：

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  先计算每一条轨迹与每一个检测框之间的 IOU。
\item
  用这些 IOU 构造一个矩阵。
\item
  调用匈牙利算法得到全局最优分配。
\item
  再结合 IOU 阈值和类别兼容条件过滤不合理匹配。
\end{enumerate}

对应代码主线是：

\begin{lstlisting}[language=Python]
iou_matrix = self._calculate_iou_matrix(detections)
matched_indices = self._linear_assignment(iou_matrix)

for track_idx, detection_idx in matched_indices:
    if iou_matrix[track_idx, detection_idx] < self.iou_threshold:
        continue
    if not self._is_class_compatible(...):
        continue
\end{lstlisting}

这段代码说明一个重要事实：匈牙利算法本身只负责``给出最优一一分配''，但它并不直接理解哪些匹配在语义上是合理的。因此，本案例又叠加了两层约束：

\begin{itemize}
\tightlist
\item
  IOU 必须高于阈值。
\item
  类别必须兼容。
\end{itemize}

由此可见，匈牙利算法提供的是全局分配框架，而不是完整的业务规则集合。

\subsection{匈牙利算法相对于贪心匹配的优势}\label{ux5308ux7259ux5229ux7b97ux6cd5ux76f8ux5bf9ux4e8eux8d2aux5fc3ux5339ux914dux7684ux4f18ux52bf}

一个常见问题在于，为什么不直接选择当前最大 IOU
的一对进行匹配。该贪心策略看似简单，但存在明显局限：

\begin{itemize}
\tightlist
\item
  先做出的局部选择可能破坏后续整体最优。
\item
  当多个轨迹都与同一个检测框接近时，容易造成冲突。
\item
  在目标密集场景下，局部贪心更容易导致 ID 交换。
\end{itemize}

匈牙利算法的价值就在于它能从全局角度处理这类一一匹配问题。虽然本案例的匹配度量比较简单，只用了
IOU，但只要场景中存在多目标竞争，使用全局分配通常都比局部贪心更稳健。

\subsection{匈牙利算法在多目标跟踪中的局限}\label{ux5308ux7259ux5229ux7b97ux6cd5ux5728ux591aux76eeux6807ux8ddfux8e2aux4e2dux7684ux5c40ux9650}

需要说明的是，匈牙利算法并不是万能的。它解决的是``在给定代价矩阵时，如何求最优匹配''，但如果代价矩阵本身构造得不好，算法仍然可能得到错误匹配。

在本案例中，代价矩阵主要由 IOU 构成，因此它会受到以下问题影响：

\begin{itemize}
\tightlist
\item
  快速运动目标与旧轨迹重叠变小，IOU 不足。
\item
  相邻目标位置太近，几何信息不够区分。
\item
  遮挡后重新出现时，仅靠 IOU 难以恢复原身份。
\end{itemize}

这也是为什么完整 DeepSORT
往往还会引入外观特征和更复杂的关联策略。匈牙利算法负责的是``最优分配''，但``什么样的代价矩阵才合理''仍然是跟踪算法设计的关键。

\subsection{轨迹生命周期参数如何影响最终效果}\label{ux8f68ux8ff9ux751fux547dux5468ux671fux53c2ux6570ux5982ux4f55ux5f71ux54cdux6700ux7ec8ux6548ux679c}

本案例中的三组参数具有较强的实验分析价值：

\begin{itemize}
\tightlist
\item
  max\_age：轨迹最长允许失配多少帧。
\item
  min\_hits：轨迹至少命中多少次后才输出。
\item
  iou\_threshold：检测与轨迹关联所需的最小 IOU。
\end{itemize}

这些参数分别控制三类问题：

\begin{itemize}
\tightlist
\item
  轨迹是否容易过早消失。
\item
  新轨迹是否容易过快出现。
\item
  匹配是否保守还是激进。
\end{itemize}

通过调参可以直接观察以下现象：

\begin{itemize}
\tightlist
\item
  max\_age 过小，目标短时遮挡后容易断轨。
\item
  min\_hits 过小，误检容易变成短暂轨迹。
\item
  iou\_threshold 过高，快速移动目标更容易失配。
\item
  iou\_threshold 过低，邻近目标更容易错配。
\end{itemize}

\section{可视化代码如何帮助理解算法结果}\label{ux53efux89c6ux5316ux4ee3ux7801ux5982ux4f55ux5e2eux52a9ux7406ux89e3ux7b97ux6cd5ux7ed3ux679c}

在 utils/postprocessing.py 中，draw\_detections 与 draw\_tracks
分别负责绘制检测结果和跟踪结果。尽管这部分并不直接构成算法主体，但其作用十分重要，因为可视化能够将抽象状态转化为可直接观察的现象。

其中，draw\_tracks 中有两点尤其值得关注：

\begin{itemize}
\tightlist
\item
  每条轨迹使用固定颜色，帮助观察 ID 是否稳定。
\item
  trail 轨迹拖尾可以直观看出运动路径与预测连续性。
\end{itemize}

因此，在调节参数时，不仅能够观察检测框是否正常输出，还能够观察 ID
是否发生跳变，以及轨迹是否保持连续。

\section{如何评价这个案例方案}\label{ux5982ux4f55ux8bc4ux4ef7ux8fd9ux4e2aux6848ux4f8bux65b9ux6848}

\subsection{这个方案的优点}\label{ux8fd9ux4e2aux65b9ux6848ux7684ux4f18ux70b9}

作为昇腾 310B 开发教程中的案例，本方案有很强的适配性：

\begin{itemize}
\tightlist
\item
  模型轻量，适合边缘侧实时实验。
\item
  检测和跟踪两个阶段边界清晰，便于分层讲解。
\item
  代码结构整洁，便于把入口、后端、解码、跟踪拆开讲。
\item
  DeepSORT 采用简化实现，避免课程一开始就陷入 ReID 细节。
\item
  既能跑 CPU，也能跑 NPU，便于体现部署层面的思维。
\end{itemize}

\subsection{这个方案的不足}\label{ux8fd9ux4e2aux65b9ux6848ux7684ux4e0dux8db3}

需要明确的是，本案例并不是为了追求最强跟踪精度：

\begin{itemize}
\tightlist
\item
  检测前端仍是经典 SSD，精度不是当前最先进水平。
\item
  跟踪器没有使用外观特征，因此遮挡恢复能力有限。
\item
  数据关联主要依赖 IOU，对交叉目标和密集目标不够鲁棒。
\item
  卡尔曼状态建模较简化，更偏向实现可解释性而不是工业最优效果。
\end{itemize}

\subsection{作为入门案例的合理性}\label{ux4f5cux4e3aux5165ux95e8ux6848ux4f8bux7684ux5408ux7406ux6027}

正因为它没有引入过多复杂部件，目标跟踪的基本问题反而更容易被清晰呈现：

\begin{itemize}
\tightlist
\item
  检测结果是如何来的。
\item
  检测结果如何进入跟踪器。
\item
  为什么需要预测。
\item
  为什么需要全局匹配。
\item
  为什么轨迹管理会决定最终 ID 稳定性。
\end{itemize}

当这些基础概念建立起来后，再引入完整 DeepSORT、ByteTrack、OC-SORT
或更复杂的 ReID 模块，学习曲线会平缓很多。

\section{章节总结}\label{ux7ae0ux8282ux603bux7ed3}

本案例展示了一条较为典型的目标跟踪实现路线：

\begin{itemize}
\tightlist
\item
  用 MobileNet 作为轻量骨干网络，降低边缘侧计算成本。
\item
  用 SSD 作为一阶段检测器，直接输出类别与边界框。
\item
  用统一检测后端把 CPU 与 Ascend NPU 推理过程封装起来。
\item
  用简化版 DeepSORT 完成轨迹预测、数据关联与轨迹维护。
\end{itemize}

从知识结构上看，本章真正要让读者掌握的，不只是某个脚本的使用方法，而是下面这条主线：

理解这条主线之后，读者就能明白：目标跟踪不是一个独立黑盒，而是一套由检测、预测、匹配和管理共同组成的时序识别系统。

对于昇腾 310B
教程而言，这个案例的价值正在于此。它既保留了真实部署场景中需要考虑的实时性与工程组织问题，又把目标跟踪最核心的算法逻辑清楚地呈现出来，适合作为后续学习更复杂视觉任务的基础章节。
