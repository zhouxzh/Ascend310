\section{两种板卡和无 Torch
边界}\label{ux4e24ux79cdux677fux5361ux548cux65e0-torch-ux8fb9ux754c}

\passthrough{\lstinline!.90!} 是
Ascend310B4/8T；\passthrough{\lstinline!.95!} 是
Ascend310B1/20T。\passthrough{\lstinline!.178!} 和
\passthrough{\lstinline!.210!} 都是历史
采集地址，不应再用于新批次。两块板的
CANN、Python、MindSpore、MindNLP、驱动和
\passthrough{\lstinline!npu-smi!}
版本必须在每个批次重新快照，不能把一块板的环境结论复制给另一块板。
Qwen1.5、TinyLlama 和 DeepSeek 使用板端已有
\passthrough{\lstinline!base!}，因此即使机器门通过也只能标记
\passthrough{\lstinline!experimental\_dirty\_base!}；TinyLlama
的既有失败证据仍保持 \passthrough{\lstinline!blocked!}，DeepSeek 的
质量和准入在双板数据补齐前保持未决。

每次在板端同一个 shell 中准备环境：

\begin{lstlisting}[language=bash]
source /usr/local/miniconda3/etc/profile.d/conda.sh
conda activate base
source /usr/local/Ascend/ascend-toolkit/set_env.sh
# 版本以本批次 environment snapshot 为准；不要从另一块板复制版本结论。
# PYTHONNOUSERSITE=1 只用于负向诊断，不能作为服务启动环境。
unset PYTHONNOUSERSITE
cd ~/case9-mindspore-chat
export PYTHONPATH="$PWD${PYTHONPATH:+:$PYTHONPATH}"
\end{lstlisting}

MindSpore 路线直接调用 MindSpore/MindNLP；现有
\passthrough{\lstinline!torch!}、\passthrough{\lstinline!torch\_npu!}、\passthrough{\lstinline!torchaudio!}
和其他污染包只记录，不删除、不升级，适配代码不得导入它们。ONNX
-\textgreater{} OM 路线使用 独立的
\passthrough{\lstinline!case9-acl-om!} 环境和原生 ACL，板端不安装
Torch、Transformers、ONNX Runtime、 vLLM 或 MindIE。两条路线都不修改系统
CANN、驱动、kernel 或 OPP。控制机 \passthrough{\lstinline!sci-agent!}
只用于静态检查、前端构建和外部参考，不把其运行时复制到板端。

\section{新板环境检查和模型门禁}\label{ux65b0ux677fux73afux5883ux68c0ux67e5ux548cux6a21ux578bux95e8ux7981}

在 \passthrough{\lstinline!.90!} 和 \passthrough{\lstinline!.95!}
分别记录
SoC、CANN、Python、磁盘、内存、HugePages、\passthrough{\lstinline!npu-smi!}
和污染包；\passthrough{\lstinline!.178!}/\passthrough{\lstinline!.210!}
只用于查阅历史报告：

\begin{lstlisting}[language=bash]
python - <<'PY'
import importlib.metadata, sys

MindSpore Profile 没有 OM 转换步骤；其门禁是工件核验、MindSpore Ascend
context、 tokenizer 导入、单 token 生成、JSON/SSE
契约、长输出、稳定性、质量和性能。Qwen2.5 的 ONNX -\textgreater{} ATC
-\textgreater{} OM -\textgreater{} ACL
门禁属于独立正式基线，必须逐板确认 \passthrough{\lstinline!Ascend310B4!}
或 \passthrough{\lstinline!Ascend310B1!} 的 descriptor、输入输出 byte
size、ACL smoke 和 NPU 采样，不能用 MindSpore
结果替代。任何门失败都记录为
\passthrough{\lstinline!failed!}、\passthrough{\lstinline!blocked!} 或
\passthrough{\lstinline!not-run!}，不自动切换
CPU、云端或其他推理框架；没有当前 \passthrough{\lstinline!.95!}
的完整环境和工件快照前，不得把 \passthrough{\lstinline!.210!} 的
历史报告当作 20T 通过证据。

ONNX -\textgreater{} OM 路线的候选端口先使用
\passthrough{\lstinline!127.0.0.1:8084!}；通过完整门禁后才有资格替换正式
\passthrough{\lstinline!127.0.0.1:8080!}。MindSpore 路线使用
\passthrough{\lstinline!127.0.0.1:8090!}，两者不能同时占用同一 NPU
模型实例。

\section{候选 Profile 服务和 OpenAI
API}\label{ux5019ux9009-profile-ux670dux52a1ux548c-openai-api}

\passthrough{\lstinline!case9-modelctl!} 负责停止旧 worker、启动新
worker、轮询健康状态和记录活动状态；失败 时尝试回滚，回滚也失败则
fail-closed：

\begin{lstlisting}[language=bash]
CASE9_ALLOW_EXPERIMENTAL=1 bash scripts/case9-modelctl.sh switch qwen1.5-0.5b-mindspore
# 正式注册表中的 blocked/not-run Profile 会被 CLI 拒绝；测试批次只能使用明确标记
# 的临时注册表，不能用参数绕过工件、环境或质量门禁。
\end{lstlisting}

DeepSeek 的当前目标板是
\passthrough{\lstinline!.95!}；\passthrough{\lstinline!.210!}
只保留为历史地址。服务固定监听
\passthrough{\lstinline!127.0.0.1:8090!}，内部模型名为
\passthrough{\lstinline!case9-active!}，请求限制如下：

\begin{itemize}
\tightlist
\item
  \passthrough{\lstinline!messages!} 只接受
  \passthrough{\lstinline!system!}、\passthrough{\lstinline!user!}、\passthrough{\lstinline!assistant!}，使用
  Profile tokenizer/chat template；
\item
  batch 为 1，单进程单请求串行，实际 token 化后检查 context
  \passthrough{\lstinline!1024!}；
\item
  \passthrough{\lstinline!max\_tokens!} 默认
  \passthrough{\lstinline!32!}、上限
  \passthrough{\lstinline!64!}，只接受
  \passthrough{\lstinline!temperature=0!}、\passthrough{\lstinline!top\_p=1!}；
\item
  请求体上限 \passthrough{\lstinline!256 KiB!}，支持普通 JSON 和 OpenAI
  SSE；
\item
  SSE 只发送前缀差量；实现包含超时 watchdog 和客户端中断清理，但
  watchdog 实际触发、 自动回滚及浏览器会话清空仍未获得本轮正向验收；
\item
  客户端不能指定 Profile、权重路径、后端或任意 Python 表达式。
\end{itemize}

接口为
\passthrough{\lstinline!GET /health!}、\passthrough{\lstinline!GET /v1/models!}
和
\passthrough{\lstinline!POST /v1/chat/completions!}。\passthrough{\lstinline!/health!}
返回 Profile、revision、环境指纹、NPU 型号、worker PID、busy、缓存清理和
admission 状态。

\section{失败处理、回滚和证据保存}\label{ux5931ux8d25ux5904ux7406ux56deux6edaux548cux8bc1ux636eux4fddux5b58}

每次批次使用唯一 UTC
目录，保存命令、PID、服务日志、环境指纹、模型哈希、原始响应和
\passthrough{\lstinline!npu-smi!} before/during/after 快照。失败时：

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  只停止本批次明确记录且命令行匹配的 worker PID；
\item
  保留失败日志、哈希和报告，不删除系统 CANN、conda
  缓存、其他模型或正式服务；
\item
  维持
  \passthrough{\lstinline!blocked!}、\passthrough{\lstinline!not-run!}
  或具体失败状态，不自动切换 CPU、云端、Torch、vLLM、MindIE 或其他模型；
\item
  切换失败先回滚上一个已验证 Profile，回滚失败则保持候选链不可用；
\item
  新板复现时重新做环境、工件、加载、API、稳定性、质量和性能门，不能因相同模型名
  或 IP 别名自动继承正式状态。
\end{enumerate}

若出现 \passthrough{\lstinline!DRV\_LPM\_FAULT!}、设备重置、worker
非正常退出或 NPU 内存持续增长，先保存
\passthrough{\lstinline!dmesg -T!}、\passthrough{\lstinline!npu-smi info!}、\passthrough{\lstinline!modelctl status!}、监听端口和本批次
PID，再停止扩大测试； 不得把一次受控恢复写成模型稳定性通过。

详细原始文件位于
\passthrough{\lstinline!repro/mindspore-chat-20260829/!}、
\passthrough{\lstinline!repro/qwen25-kv1024-dual-board-20260827/!}
以及每次生成的
\passthrough{\lstinline!repro/case9-dual-board-gap-<timestamp>/!}（本地忽略）；板端对应
\passthrough{\lstinline!\~/case9-mindspore-chat/run/!}、\passthrough{\lstinline!reports/!}。TinyLlama
的 \passthrough{\lstinline!U+FFFD!}、\passthrough{\lstinline!.210!}
历史地址的 连接失败记录和任何新的 \passthrough{\lstinline!.95!}
门禁失败都必须保留，不能改写成当前地址的成功结果。
