# 案例 1 审查报告：智能人脸识别考勤系统

## 审查范围与方法

本报告审查 `src/experiment/case1.md`、`samples/case1/README.md` 以及
`samples/case1` 的 Flask、数据库、摄像头和 NPU 推理代码。审查是静态的，
依据源文件行号进行交叉核对；没有把开发机上的依赖缺失或未运行板端推理
误判为运行时结果。下列“已确认问题”表示从当前文件即可复现的文档、实现
或安全边界问题；“待核对项”不作为已取得的实验结论。

## 总体结论

案例 1 已呈现出完整的“采集—检测—特征—比对—存储”教学主线，但当前版本
不宜直接作为可复制的考勤系统教材：未知人脸会被后台自动登记，缺失识别模型
时会生成随机特征，且开发调试服务器对外监听。与此同时，检测模型的算法
命名、前端功能描述、考勤历史语义和性能数字均与可核对证据不完全一致。
应先处理阻断级和安全级问题，再整理算法引用与测量证据。

严重性约定：**P0（阻断）**表示会使身份或实验核心结论失效；**P1（高）**表示
安全边界或教材与实现的关键合同不成立；**P2（中）**表示可复现性、学术表达或
证据不足；本报告没有确认 P3 级问题。下文沿用“阻断/高/中”作为 P0/P1/P2 的
中文标签。

## 已确认问题

### 1. 阻断：未知人脸被自动登记并写入考勤

**证据。** `samples/case1/camera.py:116-129` 在相似度低于阈值时进入
“自动注册”分支，以空字符串作为姓名写入 `users`，随后立即创建头像和
考勤记录。教材却把系统描述为与“预先注册的员工人脸数据库”比对
（`src/experiment/case1.md:5-12`），并将自动打卡作为身份验证后的结果。

**影响。** 任何未登记的人脸都能改变身份库并产生考勤记录；同一陌生人还可能
按时间间隔反复创建用户。这样得到的记录不能解释为身份认证结果，也无法作为
考勤数据的有效证据。

**建议。** 删除后台自动入库路径；未知人脸只产生告警或待审核事件。用户注册
应由显式管理操作完成，并对同一人、阈值、时间窗口和审核状态分别建模。教材
应明确“识别失败”和“注册”是两个不同的状态。

### 2. 阻断：识别模型缺失时返回随机特征向量

**证据。** `samples/case1/ascend_inference.py:285-292` 在
`self.rec_model` 不存在时返回随机的 512 维向量；模型初始化对缺失文件并未
建立强制失败合同（同文件约 `:144-147`）。调用方仍会把该向量注册或与数据库
比较。

**影响。** 模型文件损坏、未转换或路径错误时，系统表面上仍能运行，但所有
匹配结果失去语义，且结果不可复现。随机向量还会掩盖部署错误。

**建议。** 模型缺失、加载失败或输出形状不符时应 fail-closed，返回明确的
“模型未就绪”错误；在启动检查中验证 OM、输入输出合同和版本。教学示例可以
使用显式 mock，但不得把随机向量伪装成识别回退。

### 3. 高：调试服务器绑定所有网卡

**证据。** `samples/case1/app.py:251-257` 使用
`app.run(host='0.0.0.0', port=5000, debug=True, use_reloader=False)`。
教材同时建议通过开发板 IP 访问（`src/experiment/case1.md:34-36`），却没有
说明这是仅限可信实验网的开发配置。

**影响。** Flask 调试器可能暴露交互式调试能力和内部错误信息；在未认证的
局域网服务上还会暴露人脸照片、特征和考勤接口。

**建议。** 默认关闭 debug，使用生产 WSGI 服务器或至少绑定受控地址；教材
需加入认证、访问控制、数据留存和“仅实验网络”的边界说明。若保留开发命令，
应明确其不可用于部署。

### 4. 高：上传路径、静态资源和模板输出缺少安全边界

**证据。** `samples/case1/app.py:96-106` 直接拼接客户端的
`file.filename` 和 `temp_path`，没有文件名规范化、类型/大小限制或路径约束；
`app.py:41-43` 暴露 `/uploads/<path:filename>`。`templates/users.html` 约
`147-152,275-287` 把姓名拼入 `innerHTML` 和内联 `onclick`，
`templates/attendance.html:168-174` 也把数据库字段拼入 HTML。

**影响。** `temp_path` 的客户端输入可能越过上传目录边界；文件服务会扩大
生物照片的可见范围；姓名、路径等未转义字段可造成脚本注入。生物特征和照片
属于高敏感数据，不能按普通静态文件处理。

**建议。** 使用服务端生成的不透明资源 ID 和 `secure_filename`，在规范化后
再次检查真实路径；限制 MIME、大小和图像解码结果；通过鉴权接口返回资源，
禁止把上传目录当作公开静态目录；前端使用 DOM 属性赋值而不是 HTML/内联脚本。

### 5. 高：检测算法名称与实际解码实现不一致

**证据。** 教材在 `src/experiment/case1.md:9,19,42,60-113` 将检测器
称为 RetinaFace，并按该模型展开结构；`samples/case1/README.md:79-95,334`
则把 `det_500m`/`face_detection.om` 说明为 SCRFD，
`samples/case1/ascend_inference.py:191-242` 采用 SCRFD 风格的多尺度距离
解码假设。教材末尾表格的“RetinaFace (SCRFD)”（约 `case1.md:1452`）也没有
定义二者关系。

**影响。** 读者无法判断模型来源、输出张量和解码方程；按 RetinaFace 论文
复现并不能保证得到当前 `det_500m` 的结果，模型转换证据也无法与算法名称
对应。

**建议。** 核实实际 ONNX 的来源和网络类型，统一全文名称并补充原始论文、
版本和输出合同。若模型是 SCRFD，应删除 RetinaFace 的结构性断言；若是定制
变体，应明确变体与解码实现，而不是用斜杠并列两个算法名。

### 6. 高：前端功能说明超出实际页面

**证据。** 教材在 `src/experiment/case1.md:1397-1400` 写明“手动打卡”支持
浏览器上传/摄像头流程；`samples/case1/templates/attendance.html` 只有
`uploadCheckin` 的死代码（约 `:107-129`），没有对应的文件输入、提交按钮或
可见上传工作流。后端 `/api/clockin` 存在并不能证明页面提供了该功能。

**影响。** 学习者按教材操作时找不到入口，端到端复现实验会在 UI 层中断。

**建议。** 要么补齐页面控件、状态和错误处理，要么把教材改为“通过 API
调用手动打卡”，并给出实际请求合同和示例。

### 7. 高：考勤查询只返回当天每人的最近一条记录

**证据。** `samples/case1/database.py:78-96` 的查询用
`MAX(id)` 并按 `DATE(timestamp)=DATE('now','localtime')` 分组，因此只返回
当天每个用户的最后一条记录。教材/README 却使用“查看打卡历史”“所有打卡
记录”等表述（`src/experiment/case1.md:1346-1349,1390-1400`；
`samples/case1/README.md:356`）。

**影响。** 页面无法审计同一用户当天的多次打卡，也无法查询历史日期；这与
考勤系统的核心数据语义不符。

**建议。** 明确接口是“当天每人最近一次”并改写教材，或实现带日期、用户、
分页条件的完整历史查询；同时给出时区和排序约定。

### 8. 中：性能数字没有可追溯测量证据

**证据。** `src/experiment/case1.md:1459-1470` 和
`samples/case1/README.md:280-285` 给出检测 10–20 ms、识别 5–10 ms、端到端
小于 50 ms、30 FPS 等数值，但没有硬件型号、模型版本、预热/迭代次数、统计
方法或报告路径。

**影响。** 读者容易把经验值误认为本案例的实测结果，无法复核，也无法区分
NPU 推理、摄像头采集和数据库开销。

**建议。** 删除数值或明确标为非测量示例；正式结果应关联固定报告，记录 SoC
计算档位、OM 摘要、输入协议、预热和 percentile。不要以单次 UI 观察替代性能
实验。

### 9. 中：XOR 代码被放在安全设计小节

**证据。** `src/experiment/case1.md:1175-1183` 给出特征向量的简单 XOR
“加密”，并在注释中说实际应用应使用 AES。

**影响。** 教材中的可复制代码往往会被直接采用；仅靠注释不足以阻止把 XOR
用于生产生物特征保护，且没有密钥管理、认证标签和轮换策略。

**建议。** 改为 AEAD（如 AES-GCM/ChaCha20-Poly1305）的接口级示例，说明密钥
托管、访问控制、撤销和删除策略；若必须展示 XOR，只能放在“反例”框中并明确
其不可用于任何真实数据。

### 10. 中：快速开始不足以构成可复现环境

**证据。** `samples/case1/README.md:294-304` 的安装示例只执行
`pip install flask`，而代码还导入 OpenCV、NumPy、requests 以及板端提供的
`acl`；`samples/case1` 当前没有与该 README 对应的完整 `requirements.txt`。
模型准备脚本也没有下载摘要/输入输出合同校验，且模型文件属于本地资产。

**影响。** clean clone 按教程无法建立同一运行环境，模型缺失或版本漂移会被
误认为程序故障。

**建议。** 提供分层依赖（开发机/板端）、固定版本与模型资产清单；把 CANN、
ATC、ACL 命令标注为板端步骤；对下载文件做摘要和合同校验，并把生成的 OM 与
运行报告作为外部证据而非隐含的仓库文件。
