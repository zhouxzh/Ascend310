# 案例 4 审查报告：掌纹识别工作台

## 审查范围与方法

本报告审查以下内容：

- 教材章节：<code>src/experiment/case4.md</code>；
- 运行样例：<code>samples/case4/README.md</code>、<code>palmprint_workbench/</code>、<code>models/</code> 和 <code>tests/</code>；
- 工程证据：<code>samples/case4/docs/</code> 及其 <code>evidence/</code> 文件。

本次是基于当前工作树的静态审查，没有在本机执行 CANN、PyACL、OM、摄像头或触摸屏测试，也没有重新连接 Ascend 310B4 开发板。现有板端摘要可以作为随附证据引用，但不能视为本次审查重新验证的结果。

## 总体结论

案例 4 的模型准入边界和合成 ROI API 冒烟记录较清楚，但人工测试 profile 仍保存明文生物特征模板，并将服务示例绑定到所有网卡；触摸屏和摄像头验收尚未闭合。作为正式教材，必须把内测数据边界、网络暴露和验收状态写成不可误读的前置条件。

严重性定义：

- P1：会影响隐私安全、部署准入或读者对结果的根本理解，发布前应处理；
- P2：不会直接证明运行失败，但会造成复现、接口解释或排版上的误导，建议在出版前处理。

## 已核实问题

### 3.1 P1：网络暴露、明文模板与图像留存没有形成安全隔离

**证据**

- 教材在 <code>src/experiment/case4.md:21-27</code> 使用 <code>PALMPRINT_PROFILE=manual_test</code>，并以 <code>--host 0.0.0.0</code> 启动服务；同一节还显式 unset 模板加密相关变量。
- <code>src/experiment/case4.md:51</code> 说明用户主动触发的原图、ROI 和 JSON 会写入 <code>data/captures/</code>，明文 PWST1 embedding 写入 <code>data/templates/</code>；删除模板不会删除图片证据。
- <code>samples/case4/README.md:7</code> 声明没有账号、TLS 或模板多租户隔离；<code>README.md:68,76</code> 再次说明 manual_test 不启用模板/图片加密，并保存本地明文模板和图片。
- <code>samples/case4/README.md:144-152</code> 说明删除模板只删除 embedding，关联原图和 ROI 仍保留。

**影响**

掌纹是不可更换的生物特征。只要服务暴露在受信局域网之外，监听地址、无认证和明文模板便可能使上传图像、ROI、embedding 及识别请求被未授权访问。即使当前文档写有“只适用于受信设备”的提醒，读者仍可能把可运行的命令当作生产部署模板；“删除模板”也不能被理解为完成了数据删除。

**修复建议**

1. 将 manual_test 明确隔离为合成 ROI/匿名图像专用 profile，默认只监听 127.0.0.1；需要局域网演示时显式传参并在启动前打印不可忽略的安全警告。
2. 为正式 profile 设计加密模板存储、密钥生命周期、访问控制、审计日志和图像保留期限；未完成前不要把该 profile 命名为生产可用。
3. 在教程的注册、删除和清理步骤中分别说明“删除 embedding”和“删除原图/ROI”的差异，提供带绝对路径确认和备份检查的清理脚本。
4. 明确禁止真实掌纹、姓名和完整报告进入源码、截图、GitHub 或模型托管平台，并给出合成数据替代流程。

**验证要求**

- 在板端从 localhost 和受控局域网分别检查监听地址、HTTP 路由和拒绝未授权请求的行为；
- 使用合成数据验证模板加密/解密、密钥不可读、删除 embedding 与删除图像的独立审计记录；
- 对摄像头上传、注册和识别路径做数据保留清单审计；
- 在没有完成上述安全门槛前，将章节结论标为“内部教学演示”，不得标为生产生物识别系统。

### 3.2 P1：内测冒烟证据与正式验收状态需要明确分层

**证据**

- <code>src/experiment/case4.md:7</code> 已写明五个 CompNet 为 manual_test_pending，不能写成稳定验收通过；但章节标题和“冻结的人工测试发布”容易被读者理解为已完成发布。
- <code>samples/case4/docs/evidence/manual-test-smoke-20260818.md:1-3</code> 将记录定义为脱敏功能冒烟，不是识别精度、摄像头或触摸屏验收。
- 同一文件 <code>:12-27</code> 只证明健康检查、bootstrap、六个模型的合成 ROI 闭环以及重启后的列表状态。
- 同一文件 <code>:29-36</code> 明确触摸屏排版、摄像头 100 帧预览/拍照/释放和全量评测尚未完成。
- <code>samples/case4/docs/04-release-checklist.md:55-91</code> 仍有启动、六模型人工测试、触摸屏和摄像头等未勾选项。

**影响**

现有证据足以支持“合成数据上的 API/模板生命周期冒烟”，不足以支持真实图像识别精度、摄像头资源释放、触摸屏可用性或稳定模型准入。若教材只引用“冻结发布”而不突出 pending 状态，读者会把功能连通性误读为完整验收。

**修复建议**

1. 在章节开头单独列出“已验证、未验证、明确不声称”的三栏；标题改为“人工测试准备版”或同等不含歧义的名称。
2. 将合成 ROI 冒烟、模板重启持久性、摄像头验收、UI 视口验收和识别精度分成独立证据门槛；只有所有门槛有原始报告时才更新 release status。
3. 把 checklist 中未勾选项的状态同步到教材，禁止使用旧数字或旧截图填充未完成项目。

**验证要求**

- 在 Ascend 310B4 / 8T 上按六个 canonical model ID 重跑合成闭环，并保留 HTTP、模型耗时、模板 namespace 和 PID 日志；
- 分别完成触摸屏四页检查、摄像头 100 帧预览、拍照识别、设备释放和再次打开；
- 若宣称识别精度或性能，必须附数据集、样本数、输入协议、统计方法和原始报告路径；
- 重新生成 release manifest 后再将 pending 状态改为 accepted，不能手工修改字段。

### 3.3 P1：递归删除命令可能误删全部生物数据

**证据**

- <code>src/experiment/case4.md:53-59</code> 直接给出 <code>rm -rf "$PALMPRINT_ROOT/data/captures"</code> 和 <code>rm -rf "$PALMPRINT_ROOT/data/templates"</code>。
- <code>samples/case4/README.md:146-152</code> 及 <code>samples/case4/docs/04-release-checklist.md:75-83</code> 重复了同样的清理方式，并只要求操作者手动执行。

**影响**

命令依赖环境变量和目录结构，执行前没有绝对路径确认、运行实例确认、备份清单或二次确认。误设置 PALMPRINT_ROOT、切换发行目录或在保留证据前执行命令，可能一次性删除所有图片、ROI、模板和复盘材料；删除操作也不可由服务自动恢复。

**修复建议**

提供只读列举、按 run/日期归档、逐项删除和最终确认四步流程。清理脚本应拒绝空变量、拒绝仓库根目录/家目录等宽路径，并先将待删文件清单写入审计日志。教程应明确“模板删除”和“图像证据删除”是两项独立操作。

**验证要求**

在临时合成目录中测试空变量、错误发行目录、符号链接和备份恢复；板端只使用明确的绝对发行目录，确认清理后服务不会引用已删除模板，也不会意外删除 reports/manifest。

### 3.4 P2：模型特征维度合同需在教材中显式区分

**证据**

- <code>samples/case4/models/registry.json:7-50</code> 中 CCNet 的 feature_dim 为 2048，CompNet 条目使用 512 维合同。
- <code>samples/case4/palmprint_workbench/domain/registry.py</code> 的候选适配和准入检查分别处理 CCNet 与 CompNet；代码并非一个统一的 embedding 维度。
- <code>src/experiment/case4.md:34-49</code> 以六模型列表和统一 namespace 介绍人工测试，没有在同一处突出两类输出维度差异。

**影响**

读者可能把六个模型当成可互换的 embedding 生成器，错误地复用模板、相似度阈值或数据库 schema。维度不匹配会在 API 之外才暴露，难以从章节表格判断。

**修复建议**

在模型矩阵中增加输入尺寸、输出维度、模板 namespace 和准入状态四列；明确 CCNet 2048-D 与 CompNet 512-D 不能共享模板或阈值。为跨模型切换给出“必须重新注册”示例。

**验证要求**

对六个模型分别执行输出 shape、模板 namespace、跨模型查询拒绝和重启后恢复测试；将结果写入同一份人工测试报告，不用单一“embedding 通过”字段代替。

### 3.5 P2：浏览器视口与摄像头能力被混写

**证据**

- <code>src/experiment/case4.md:36</code> 同时列出 1280×720、1024×768 和 375×812 的触摸屏测试尺寸。
- 同一文件 <code>:63</code> 又要求优先选择 1280×720 MJPG，并检查实际输出尺寸；<code>samples/case4/README.md:86-89</code> 将摄像头分辨率环境变量与浏览器界面检查并列。
- <code>samples/case4/docs/04-release-checklist.md:85-91</code> 仍把视口排版、/api/cameras 节点和 100 帧预览放在同一检查段落。

**影响**

375×812 更像浏览器内容视口，而 1280×720/1024×768 可能是显示窗口或摄像头模式。若不区分对象，读者会把一次 UI 响应式检查误认为摄像头支持声明，或把摄像头输出尺寸误认为页面尺寸。

**修复建议**

将验收拆为“浏览器视口布局”“显示器/窗口尺寸”“摄像头实际模式”三项；每项记录来源、设备节点、像素格式、帧率和测量方法。通用教材正文只保留可迁移的原则，把具体尺寸放到一次实验记录中。

**验证要求**

板端查询 /api/cameras，保存实际节点、格式、分辨率和帧率；在至少一个桌面和一个窄视口中检查布局，不用同一个数值同时代表 UI 和摄像头能力。

### 3.6 P2：严格资产检查的 clean clone 前置条件未说明

**证据**

- <code>src/experiment/case4.md:26</code> 和 <code>samples/case4/README.md:24-27</code> 要求在源码目录直接执行 verify_assets --strict。
- <code>samples/case4/README.md:18</code> 明确源码仓库不包含 checkpoint、ONNX、OM、数据集、模板和原始报告；OM 需要另行同步并校验。

**影响**

读者在干净源码副本上按顺序执行会得到“缺少资产”的失败，容易误判为代码或环境错误。严格检查本身是正确的准入门槛，但缺失资产与合同校验失败必须区分。

**修复建议**

将流程分成源码检查和板端资产包检查：源码阶段验证 manifest schema、路径和前端；资产包阶段验证字节数、SHA-256、OM 输入输出合同。命令输出应明确提示“源码包预期不含 OM，请先取得已批准资产包”。

**验证要求**

在 clean clone 和完整资产包两种目录分别运行检查，记录预期退出码和错误分类；不把下载或未校验的模型当作通过。

## 现有正面控制

- candidate_manifest.json、registry.json 和 release manifest 对生产模型与 manual_test 候选做了区分；
- API 文档明确 CPU、EDCC 和未准入候选不进入在线接口；
- evidence/manual-test-smoke-20260818.md 使用合成几何 ROI，并明确不声称识别精度；
- 服务健康检查不会主动加载 NPU，文档要求另做真实上传或摄像头 smoke，这一证据边界是合理的。

这些控制不能替代隐私、摄像头、触摸屏和板端持续运行验收。

## 验证要求与板端未验证项

本次未执行以下项目：
