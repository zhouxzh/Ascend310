## 统一审查标准

每份报告都把以下内容分开记录：

- 教材中的事实、方法、解释和结论；
- 样例代码实际实现的接口、模型和状态；
- 转换、数值 smoke、任务精度、性能、UI 和硬件验收等不同证据类型；
- 可在开发机复核的结果与只能在 Ascend 板端复核的结果。

严重性使用以下级别：

- `P0`：安全、隐私、数据完整性或核心结论失效；
- `P1`：主要功能、模型合同、复现性或验收结论存在重大问题；
- `P2`：影响教学准确性、可维护性或出版质量；
- `P3`：一般编辑、措辞、引用或格式问题。

审查采用“证据不足即不宣称”的原则。没有随仓库保存原始数据、模型、运行日志或固定报告的数字，只能标记为外部板端证据、示例值或待验证，不能自动视为可复现结果。现有 OM、CANN、PyACL、NPU、摄像头和板端音频项目不在开发机上执行。

## 跨案例共性问题

1. 一些章节把设计目标、示例输出或历史板端记录写成当前实测结论，但缺少模型版本、数据集、运行协议和原始报告。
2. 部分样例的运行时安全边界与教材中的“可部署”表述不一致，涉及调试服务器、局域网监听、未鉴权控制面、生物特征留存和设备令牌。
3. 模型任务语义、输入输出合同和后处理逻辑在若干案例中没有由 manifest、测试或代码共同约束。
4. 当前生成的 LaTeX 对部分 Mermaid 只保留了源码 listing；Case 7 还存在 emoji 缺字，Case 8/9 存在 overfull 警告。这些属于正式出版物的构建问题，不应由读者自行解释。
5. 本目录中的报告是审查资料，不自动加入 VuePress 侧栏、教材目录或 PDF。需要公开发布时，应先解决报告列出的 P0/P1 问题，再单独更新发布产物。

## 后续处理顺序

建议先处理 P0/P1 的数据安全、模型合同、接口实现和证据边界，再处理 P2 的章节结构、引用和排版，最后处理 P3 的措辞与格式。每次修复后应重新运行对应案例的本地测试和文档检查，并在板端重新获取硬件证据；不得用旧报告中的数字覆盖新的失败结果。
