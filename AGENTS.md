# AGENTS.md - Ascend310 Codex Instructions

## Scope

These instructions apply to the whole repository unless a deeper `AGENTS.md`
exists in a subdirectory.

## Runtime Boundary

- The local workspace is a development environment, not the Ascend 310B device.
- Do not install or run Ascend device-only components locally, including CANN,
  PyACL runtime checks, ATC conversion, OM inference, `npu-smi`, or hardware
  DVPP/NPU tests.
- In this workspace, Python code may be edited and syntax-checked, but hardware
  behavior must be validated on a real Ascend 310B device.
- `prepare_models.py` scripts that export ONNX and run ATC belong on the Ascend
  device unless the user explicitly says otherwise.

## Documentation Sources

- Markdown under `src/book/`, `src/experiment/`, and `src/appendix/` is the
  source of truth for the book, experiment chapters, and appendices.
- Files under `latex/chapters/`, `latex/cases/`, and `latex/appendices/` are
  generated by Pandoc.
  Do not hand-edit these generated LaTeX files for content fixes.
- Markdown-to-LaTeX conversion is handled by the repository script
  `./convert-vuepress.sh`. Use this script instead of calling Pandoc manually
  unless the user explicitly asks for a lower-level conversion command.
- When a documentation correction is needed, edit the matching Markdown source
  first, then regenerate LaTeX/PDF with `./convert-vuepress.sh` only when the
  user asks for generated outputs or when the task explicitly includes a build.
- If generated LaTeX differs from Markdown, treat the Markdown as authoritative.

## Documentation Layout

This repository is organized around a book + experiment workflow. When editing
or reviewing documentation, use the following structure as the map:

- `README.md`: repository overview and entry point.
- `src/book/`: theory/tutorial manuscript source.
  - `src/book/README.md`: book front matter and overall chapter roadmap.
  - `src/book/chapter1.md` ... `src/book/chapter9.md`: main theory chapters.
  - `src/book/ssd_optimize.md`: supplementary chapter content.
  - `src/book/img2/` ... `src/book/img6/`: figures and DOT sources used by the book.
- `src/experiment/`: practical case manuscript source.
  - `src/experiment/README.md`: experiment overview and case index.
  - `src/experiment/case1.md` ... `src/experiment/case9.md`: experiment cases.
  - `src/experiment/img1/` ... `src/experiment/img3/`: case figures and assets.
- `src/appendix/`: appendix manuscript source.
  - `src/appendix/README.md`: appendix overview and index.
  - `src/appendix/appendix1.md`, `appendix2.md`, and later sequential files:
    numbered appendices.
  - `src/appendix/img1/`: figures and assets used by Appendix 1.
- `samples/`: code and helper scripts paired with chapters and cases.
  - `samples/chapter2/` ... `samples/chapter5/`: chapter demo code.
  - `samples/case1/` ... `samples/case9/`: case implementations, configs, and setup scripts.
  - Each sample directory usually contains its own `README.md`, runnable code,
    and model-preparation helpers such as `prepare_models.py`.
- `src/.vuepress/`: VuePress site configuration, theme, and public assets.
- `latex/`: generated LaTeX/PDF pipeline artifacts and conversion helpers.
  - `latex/chapters/`, `latex/cases/`, and `latex/appendices/` are generated
    outputs.
  - `latex/book.tex` is the main PDF entry file.
  - `latex/book.pdf` is the compiled book output.
- `notebook/`: Jupyter notebooks and export helpers for auxiliary learning materials.

Relationship rules:

- Chapter, case, and appendix content always comes from the Markdown under
  `src/book/`, `src/experiment/`, and `src/appendix/`.
- Example code lives under `samples/` and should be kept in sync with the
  corresponding chapter or case documentation.
- Generated LaTeX, PDF, and image artifacts are outputs, not the primary source.

## Build Notes

- `./convert-vuepress.sh` converts `src/book/*.md`, `src/experiment/*.md`, and
  `src/appendix/appendix*.md` into `latex/chapters/*.tex`,
  `latex/cases/*.tex`, `latex/appendices/*.tex`, and `latex/book.pdf`.
- The conversion script checks that `src/book/chapter*.md` uses `##` as the
  top-level heading because chapters are included under explicit `\chapter{}`
  entries in `latex/book.tex`.
- After running `./convert-vuepress.sh`, inspect `latex/book.log` for actual
  errors and important warnings. `Missing character` warnings must be fixed;
  they usually come from unsupported Unicode characters in the Markdown source.
- Fix `Missing character` issues in the Markdown source, not in generated
  LaTeX. Prefer LaTeX/PDF-safe text replacements for symbols that the current
  fonts do not contain, such as replacing emoji with plain Chinese/English text
  and replacing decorative symbols with ASCII where appropriate.
- Avoid touching generated media, PDF, or LaTeX artifacts unless the requested
  work is specifically about regenerating or fixing the build output.

## Change Discipline

- Prefer narrow edits that directly answer the request.
- Do not revert user changes. If unrelated files are already modified, leave
  them alone.
- For Ascend hardware claims, avoid over-specific architecture statements unless
  they are backed by device logs or official documentation.
- Be explicit when a result cannot be validated locally because it requires the
  Ascend 310B device.
